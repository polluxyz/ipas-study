# 每日題本：實作計畫

規格：`docs/specs/daily-booklet.md`（v1，已核可）。協調與驗收：Claude。前端設計與實作：Codex（`gpt-6.1-sol` + `high`）。

## 元件與相依

| 元件 | 相依 | 分支 |
|---|---|---|
| 規格、計畫、任務清單、既有規格修改 | 使用者核可 | `docs/daily-booklet` |
| 版面 mockup（不合併） | 文件 PR | `polluxyz/daily-booklet-mockup` |
| 整合分支 | 使用者看過 mockup | `feature/daily-booklet` |
| 題本資料層、遷移、抽題排除、純邏輯 | 整合分支 | 各 worker 自己的分支，併入整合分支 |
| 每日頁、文字、瀏覽器測試 | 資料層 | 同上 |

使用者要求細分 worker，每個 worker 只做一件事。但新舊資料層不能分開上線，否則會出現半套流程。

作法：每個 worker 開自己的工作樹，基底是整合分支。協調者驗收後併入整合分支。全部完成才從整合分支開 1 個 PR 到 `main`。

## 順序

1. 使用者核可規格與 plan。**此處停下等回覆。**
2. 修改既有規格，文件 PR 合併。
3. R0：非作者 Codex 審查規格的資料設計。高中度問題先修規格；會改變決定的才回報使用者。
4. M1：Codex 做 mockup 並截圖。協調者看過後交給使用者。
5. U1：使用者看 mockup。**此處停下等回覆。**
6. 平行：I1 資料層、I3 抽題排除。
7. I1 併入後：I2 遷移、I4 題本純邏輯。
8. I2、I3、I4 併入後：I5 每日頁。
9. I5 併入後：平行做 I6 文字、I7 更新既有瀏覽器測試、I8 新瀏覽器測試。
10. R1：非作者 Codex 審查整包差異。
11. V1：協調者跑全部檢查與瀏覽器測試，看差異與截圖。
12. P1：PR、CI 全綠、squash 合併、重建 4321、更新 `docs/handoff.md`。

## 風險與對策

| 風險 | 對策 |
|---|---|
| 遷移弄丟使用者作答 | 舊鍵不刪；寫入後讀回才算完成；遷移表每列有測試；舊 `Attempt` 逐筆比對 |
| 上線時舊分頁還開著 | 遷移時把第 1 版草稿 `seq` 加 1，讓舊分頁進唯讀；這只做資料層測試，未對舊建置做端對端 |
| 使用者在實作期間做題，資料狀態改變 | 遷移不綁特定狀態；已有草稿的題本可照常作答 |
| 第 1 版在實作期間仍會覆蓋舊清單 | 上線前請使用者不要開沒有草稿、清單是舊日期的科目 |
| 舊版測試大量綁定第 1 版鍵 | I7 專責更新，並逐條對照原斷言，不刪除測試案例 |
| 完整歷史每 15 秒重寫 | I1 實測 21 本的資料量與寫入時間；超出才改成分開存放，並回報 |
| 科目 3 其他題型先用完 | 本規格只提示，不補題；等查到已做題數再決定 |
| 考前時間緊，上線弄壞每日練習 | 全部完成才合併 `main`；合併後才重建 4321 |

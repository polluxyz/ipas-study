# 每日題組交卷模式：實作計畫

規格：`docs/specs/daily-exam-mode.md`（v3）。協調與驗收：Claude。前端設計與實作：Codex（`gpt-6.1-sol` + `high`）。

## 元件與相依

| 元件 | 相依 | 分支 |
|---|---|---|
| 規格、計畫、任務清單 | 無 | `docs/daily-exam-mode` |
| 版面 mockup（不合併） | 文件 PR | `feature/daily-exam-mockup` |
| 草稿資料層與提交（`attempts.ts`、純邏輯） | 文件 PR | `feature/daily-exam-mode` |
| 題卡延後解析、共用顯示函式 | 資料層 | 同上 |
| 每日頁流程、快速選單、版面 | 資料層、題卡、使用者看過 mockup | 同上 |
| 瀏覽器測試 `demo/scripts/daily-exam-smoke.mjs` | 每日頁流程 | 同上 |

這些改動共用同一批檔案，也要一起上線才不會出現半套流程，所以放在同一個 PR。

## 順序

1. 文件 PR 合併。
2. Codex 做 mockup 並截圖。協調者看過後，把截圖交給使用者。
3. 使用者看過 mockup。**此處停下等回覆**，意見改回 mockup。
4. Codex 依核可的版面實作，測試一併寫。
5. 非作者 Codex 審查差異。
6. 協調者自己跑全部檢查與瀏覽器測試，看差異與截圖。
7. PR、CI 全綠、squash 合併、重建 4321、用真資料走一遍。

## 風險與對策

| 風險 | 對策 |
|---|---|
| 測試全綠但 Enter 仍立即顯示解析 | 瀏覽器測試直接按 Enter 並檢查畫面 |
| 交卷中斷造成重複紀錄 | 先固定 ID 再整批寫入；故障測試逐步失敗再重試 |
| 共用題卡改動影響官方題 | `reveal` 預設 `instant`；官方題、一般測驗、單題頁做回歸 |
| 使用者當天進度遺失 | 第 4.3 節掃描舊作答；用既有資料形狀寫測試，上線前不動使用者的 localStorage |
| 舊分頁寫回已清除的資料 | 寫入前比對 `id`、`seq`；瀏覽器測試涵蓋 |
| 考前時間緊，功能壞掉影響每日練習 | 每個階段可單獨驗收；合併後才重建 4321 |

## 驗證點

- mockup：協調者親讀截圖，使用者核可。
- 實作：規格第 10 節 12 條逐條有證據。
- 上線：4321 重建後，以真實 localStorage 開頁，確認今日舊作答被鎖定、解析收起。

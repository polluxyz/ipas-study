## 3. 資料格式變更

外部題沿用 `source: mock`，加選填的 `origin` 物件。不新增第 4 種 `source`。理由：外部題在網站上的行為與模擬題相同（顯示「參考答案」），新增 `source` 會影響 `content.config.ts:44`、`QuestionCard.astro:12` 與所有依 `source` 分支的程式。

```yaml
origin:                       # 選填。外部來源題才有
  author: zero2005x
  repo: https://github.com/zero2005x/ipasAI
  commit: 253811bf7e4891537ed6738786847c532a11a573
  path: book/L23/v0.3/ch03.md
  original_id: SIM-L23101-001
  license: CC-BY-NC-SA-4.0
  license_url: https://creativecommons.org/licenses/by-nc-sa/4.0/deed.zh-hant
  original_answer: B          # 原題答案字母
  option_map: {A: C, B: A, C: D, D: B}   # 原選項 → 本站選項
  modified: 選項重排；刪除正解選項內的理由；解析改寫
```

- 外部題的 `answer` 等於 `option_map[original_answer]`。檢查器驗證這條關係。
- 選項重排時，`explanation.wrong` 的各選項說明一起重新對應。
- `author` 欄記錄解析改寫者。
- 檢查器新增規則：有 `origin` 的題目必須有全部子欄位；`license` 只能是允許清單內的值；`commit` 必須是 40 字元 SHA。每條規則附會失敗與會通過的 fixture。
- 外部題放在 `content/questions/mock/external/zero2005x/`，目錄內附 `LICENSE.md`（授權全文連結、原作者、修改說明）。題目 ID 用 `Z-<主要代碼>-<三位序號>`，例如 `Z-L23101-001`，檔名同 ID。本站新模擬題接續 `M-<主要代碼>-<三位序號>`。

## 4. 品質門檻與審查流程

### 4.1 自動門檻（每批）

1. 檢查器 0 錯誤。照抄檢查 0 筆（不得與指引、考卷連續 25 字相同）。
2. 正解分布：A–D 每個字母占 15%–35%。
3. 正解是最長選項的比例 ≤ 65%（官方考古題基準 61%）。唯一最長與並列最長分開統計。
4. 計算題與程式題：答案用 `tools/python/` 實際執行或驗算，留下執行紀錄。

### 4.2 人工審查（逐題）

1. Codex 寫作者寫題。每批約 20 題。
2. 非作者 Codex 盲解：只拿題幹與選項，不看答案。
3. 非作者 Codex 全審：答案、事實、干擾項是否合理、選項有沒有作答線索。
4. Claude 主審：盲解不一致、全審提出問題的題目全部審；其餘每批抽審。L21203 法規事實一律上網查證。
5. 高、中度問題清零才標 `verified` 並合併。審不過的標 `disputed` 或退回重寫。

審查紀錄寫明「同供應商非作者審查＋Claude 主審／抽審」，不稱跨供應商全審。

### 4.3 外部題的作答線索

- 先依假設 5 重排選項並刪除正解內的理由。
- 重排後仍有明顯線索的題目，逐題加長干擾項或補上合理但錯誤的條件。正解原意不變，改動寫進 `origin.modified`。

## 6. 每日 50 題模式

### 6.1 抽題規則

- 頁面 `/daily/`，選科目後出 50 題。
- 只抽 `source: mock` 的 `verified` 題（外部題與本站模擬題），排除 `disputed`。考古題與指引練習題不進每日題組。
- 50 題全部是未做題。「未做」以任何模式的既有作答判斷；題目改版（`rev` 變動）不算新題。
- 代碼權重：抽題範圍不含官方題，但權重仍以考古題計算。80% 依官方考古題該科的代碼比例，20% 平均分給該科全部代碼。以 `codes[0]` 計，用最大餘數法取整數。
- 科3 每份含 10–13 題程式或圖表題（題庫足夠時）。
- 未做題不足 50 題時，顯示缺額，不暗中補入做過的題目。

### 6.2 作答方式

- 全部答完才能交卷，交卷後才看解析。可顯示累計用時，不強制時限。細節見 `docs/specs/daily-exam-mode.md`。
- 90 分鐘強制時限不在本次範圍。
- 錯題複習用另一個入口，不占這 50 題。

### 6.3 當日題組固定

- 同一天重新整理頁面不換題。日期以台北時間（Asia/Taipei）計。
- 當天題組存進一個獨立的 localStorage 鍵，內容是日期、科目、題目 ID 與 rev、順序。讀寫只經過 `attempts.ts`。這份快取不進匯出檔；清除資料時一併清除。
- 當天有題目被移除或不再是 `verified` 時，顯示說明並略過，不自動補題。例外：同日快取全部失效且沒有非空草稿時，視同沒有快取，重新抽題（`docs/specs/daily-exam-mode.md` 第 3.6 節）。
- 作答紀錄沿用既有 `Attempt` 格式。`mode` 記為 `daily:2026-11-05:S1`，日期是題組建立日期。
- 前一份題組未交卷時，隔天保留舊題組，不建立新題組（`docs/specs/daily-exam-mode.md` 第 3.4 節）。
- v4 上線前已存的當日題組可能含官方題。開啟頁面時，把其中的官方題換成未做的非官方題並寫回快取。其他題目與順序不變。被換掉的官方題作答紀錄保留，但不計入當日進度。這也是「不自動補題」的例外。

### 6.4 官方題完整練習

- 頁面 `/official/` 列出 6 份題組：114-2 科1、114-2 科3、115-1 科1、115-1 科3，以及指引練習題科1、科3。每份題組有獨立頁面，官方題依原題號排序。
- 題組包含該份全部題目，含 `disputed` 題。爭議題照常顯示爭議說明，依官方答案計分。
- 進度只看該份題組的 `mode`，例如 `official:115-1:S3`、`official:guide:S1`。在其他模式做過的題目，這裡仍算未做。
- 作答後即時看解析，顯示累計用時。考古題另外顯示答對題數與換算分數（每題 2 分）。交卷後才看解析的模擬考不在本次範圍。
- 作答紀錄沿用既有 `Attempt` 格式與 `attempts.ts`，不新增 localStorage 鍵。

## 9. 寫題規則（新模擬題與外部題共用）

寫作者只改自己被指派的題目檔。

### 格式

- 依 `docs/specs/site-v1.md` 4.1：`id`、`rev: 1`、`source: mock`、`subject`、`type`、`codes`、`concepts`、`stem`、`options`、`answer`、`explanation`（`summary`、`correct`、`wrong` 只寫 3 個錯誤選項）、`guide_refs`、`author: codex`、`review`。
- `concepts` 只用 `content/concepts/` 已有的 ID。不新增概念。
- `guide_refs` 寫法是 `guide-<科目>:<印刷頁碼>`，要實際查過 `text/guide_科目*.txt`。
- 寫作者交件時 `review.status: draft`。審查通過後才改 `verified`，之後才合併。

### 內容

- 風格模仿 115-1：情境題為主，帶具體數字，問「最適合」「主要原因」「最正確」。
- 全部用繁體中文，用自己的話寫。不照抄學習指引或考卷（連續 25 字相同會被 `check-copy` 擋下）。
- 不重複既有題目：同一概念可以再考，但情境、數字、問法都要不同。換字題不算新題。
- 干擾項要合理，每個都對應一種真實的誤解。解析的 `wrong` 要說明該誤解錯在哪。
- 計算題與程式題必須實際驗算或執行：`uv run --project tools/python python <檔案>`。執行紀錄交給審查者。
- 不寫法規條號、日期、金額等無法查證的事實。寫到法規時要上網查證並把來源列進交件報告。

### 批次門檻

每批要符合第 4.1 節：A–D 各占 15%–35%；正解是唯一最長選項的比例 ≤ 65%（並列最長另外統計）。

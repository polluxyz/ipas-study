## 0. 假設清單（待使用者確認）

1. 網站是一本完整教材：學習指引的每個主題都要教到，指引沒寫但重要的內容也要補。速查是另外的產品，不取代教材。
2. 教材、檢核小題、考古題分開。學習路線只用教材與自編檢核小題，不出現考古題。
3. 公式用 LaTeX 撰寫，建置時轉成數學排版（KaTeX）。
4. 視覺輔助需要才放：有視覺推理需求的學習目標（曲線判讀、切分流程、空間關係）一定要有合適的圖；純文字概念可以沒有圖。不放裝飾圖。
5. 用詞以學習指引與考卷的實際用字為主詞，其他譯名當別名；有歧義的別名在正文說明。
6. 先寫 3 個代表頁，使用者看過再寫完 L23303，最後套用到全站。

## 1. 成功條件（L23303 範例單元）

1. **涵蓋**：指引 5.3 的 19 個主題拆成學習目標。每個目標都有對應的概念頁段落（已對應率 100%，檢查器算），並經非作者審查確認教到要求的深度（審查完整率 100%）。兩個數字分開報告。
2. **相容**：既有 30 個概念 ID、題目連結、爭議題狀態、作答與閱讀紀錄都仍可用。新增概念要另外核可。
3. **公式**：每組公式有來源、符號說明、適用條件與一個完整算例。指引公式對照過 PDF 頁面圖；補充公式附外部可靠來源。KaTeX 渲染 0 錯誤。
4. **視覺**：有視覺推理需求的學習目標都有合適的圖，逐頁列出「有圖／無圖與理由」。數據圖可從固定資料重建；分類指標用獨立的已知答案核算，含同分、只有單一類別、分母為零等邊界。
5. **分流**：教材正文沒有考題 ID、題號引用（檢查器只查正文範圍，相關考題連結區除外）。學習路線的階段小測驗只抽自編檢核小題。
6. **檢核小題**：每頁 2–3 題，每題對應一個學習目標，先作答再看回饋，不計入錯題本。
7. **速查**：L23303 有 1 頁速查（公式、指標選擇、診斷），每條連回教材。
8. **閱讀**：320px、375px 與桌面寬度、深淺主題下沒有整頁橫向溢出；公式與圖可讀；收合區與檢核可用鍵盤操作。代表頁要看截圖，不只看自動斷言。
9. **品質**：照抄檢查 0 片段；交叉審查的高嚴重度錯誤為 0，其餘有處置紀錄。
10. **使用者試讀**：使用者不做考古題也能走完「讀教材 → 看例子 → 做檢核 → 看回饋 → 查速查」。

## 3. 教材單位與頁面骨架

1. **一個概念一頁**，概念 ID 不變。學習路線的每個階段加一段「階段導讀」，說明本階段要解決什麼問題、概念之間怎麼接。
2. 每頁開頭有「讀完你會」（1–3 個學習目標）與「建議先讀」（前置概念）。
3. 骨架順序如下。依 `kind` 可省略不適用的節，但順序不變：

| # | 節 | 內容 |
|---|---|---|
| 1 | 一句話 | 這個概念是什麼（≤ 40 字） |
| 2 | 為什麼需要 | 它解決什麼問題 |
| 3 | 直覺 | 視覺輔助 + 說明；最多 1 個生活比喻 |
| 4 | 定義與公式 | 公式、符號說明、適用條件 |
| 5 | 算一次／走一次流程 | 用單元共用的例子逐步算；流程類概念改成走一次流程 |
| 6 | 程式 | 最小可執行例子與輸出（不適用就省略） |
| 7 | 怎麼用、怎麼判讀 | 什麼情境用、結果怎麼看、和相近概念怎麼選 |
| 8 | 常見誤解 | 概念層級的誤解，不引用考題 |
| 9 | 進階（選讀，預設收合） | 推導、變體、教材勘誤 |
| 10 | 小結 | 3–5 條重點 |
| 11 | 檢核小題 | 每個學習目標至少 1 題，共 2–5 題，選擇題占多數 |

4. 影響主要結論的邊界條件（分母為零、正類定義、時間或群組限制）寫在第 4 或第 7 節，不收進進階。
5. 互相比較的頁面共用一批資料，讓數字能互相核對。例：L23303 分類指標共用同一批樣本的標籤與分數，混淆矩陣是指定閾值下算出來的結果。迴歸、切分等各用適合的小例子。
6. 例子要分散到不同應用領域（使用者 2026-10-31 要求）：
   - 每頁在 `## 怎麼用、怎麼判讀` 加 `### 換個場景`：用 2–3 個不同領域（例如醫療篩檢、製造瑕疵、推薦、客服、金融、交通）說明同一個概念怎麼用、判讀重點有什麼不同。用表格或短段落，不必附新算例；有數字就要可驗算。
   - 先寫指引替這個概念列出的「適用場景」，再補其他領域。指引的寫法有兩種，都要涵蓋：領域例子（如 Recall 的癌症偵測、詐騙偵測）與資料條件（如 K-fold 的中大型資料集、分層 K-fold 的正負樣本懸殊）。已在主例子或其他段落講過的可以不重複。
   - 標示：指引列出的場景不標補充；新增的場景在表格的場景欄加「（補充）」。整節都是新增時，只在小節標題加「（補充）」。
   - writer 動筆前先用 `scripts/tools/compare-sources.cjs` 或 `text/guide_科目3.txt` 找出該概念的「適用場景」，在 worker_done 列出指引場景與頁面對應位置。
   - 一個概念群內，主例子至少涵蓋 2 個不同領域；同一群互相比較的頁面仍共用同一份資料。新資料由協調者放進 `content/examples/`。

## 4. 可讀性規則

以下數值是試行值，超過時檢查器列**警告**，由審查者處置並記錄理由。不得靠拆成假段落消除警告。

1. 一段最多 4 句、約 90 字。一節約 150–300 字。不設最低字數。
2. 一頁提示框最多 3 個，種類固定：重點、注意、例子。程式段落的「讀碼重點」不計入。
3. 表格最多 4 欄 × 6 列。
4. 程式以 15 行為目標；放不下時用「完整例子 + 重點片段」，不得省略關鍵步驟。
   - 每段 ```python 後面緊接 ```text 輸出區塊，輸出必須是在 `tools/python/` 環境實際執行的結果（見 4.1）。
   - 程式後面可以放 `:::tip[讀碼重點]`：列出要看哪幾行、哪個參數最常出錯。不另寫「考試會考程式」之類的說明句。
5. 英文術語第一次出現寫成「中文（English）」。用詞照 `content/glossary.csv`。
6. 圖緊接在說明它的段落後面。圖說一句，講看圖要注意什麼；座標與單位直接標在圖上。

### 4.0 上網參考（使用者 2026-11-01 要求）

- writer 每頁動筆前上網查：官方文件（scikit-learn、PyTorch、Keras、MLflow 等）確認定義與 API；再看 1–2 篇別人的教學文章或課程，找更完整的內容與更好懂的講法、例子、圖。
- 參考只取思路，不照抄：不得出現與外部文章連續 25 字以上相同的句子，用自己的話重寫。
- 實際打開過的網址才能寫進 `formula_groups.source` 或頁尾參考來源；worker_done 列出查過的網址與各自用在哪裡。
- 審查分兩部分（使用者 2026-11-01 核可）：主審由非作者 provider 的強模型（Claude Opus 5.5 或 Gemini 4 Argon）負責事實、涵蓋深度、可讀性，並回原始來源核對公式出處與場景說法、抽查有無照抄外部文章；公式獨立核算與程式實測由非作者 Codex reviewer（`--search`）負責。角色見 `docs/orca-multi-agent.md` 第 1 節。

### 4.1 程式實測環境

- 環境：`tools/python/`（uv 專案，Python 3.12，套件版本鎖在 `uv.lock`）。只有協調者改 `pyproject.toml` 與 `uv.lock`。
- 執行：`uv run --project tools/python python <檔案>`。環境變數 `PYTHONIOENCODING=utf-8`、`MLFLOW_DISABLE_AGENT_HINT=1`。
- 程式要可重現：固定 `random_state`／種子；寫檔只寫到暫存資料夾。
- 輸出含隨機或依版本而變的數字時，正文說明哪些數字會變，不寫「本機沒有執行」。

### 4.2 概念連結

1. 連結文字一律顯示概念標題（`title`），不顯示 ID。
2. 自動連結：網站在每個二級標題（`##`）範圍內，把其他概念的標題或別名第一次出現處轉成連結。寫作者不必手動標 `[[...]]`，手動標的照舊可用。
3. 不自動連結：標題、公式、程式碼、已是連結的文字、本頁自己的概念、提示框標題。
4. 比對規則：長的詞優先（「PR-AUC」不會被拆成「AUC」）；英文別名要整詞相符；2 個字元以下的英文別名（如 TP、F1）不自動連結。
5. 同一個詞對到 2 個以上概念時，建置報錯，由協調者修 `aliases`。

## 5. 公式

1. 行內 `$...$`，區塊獨立成行 `$$...$$`。多字母量用 `\mathrm{TP}`。長式用 `aligned` 分行。
2. 新符號第一次出現就說明。每組公式有一個完整算例，不必每行都附符號表。
3. 公式群有 ID，記錄來源（指引頁碼或外部來源）、核對者與結果。回 PDF 只證明原書怎麼寫，不證明它寫對。
4. 技術：`remark-math` + `rehype-katex` + `katex`，建置時渲染（RS5 已試驗）。

## 6. 視覺輔助

| 類型 | 用途 | 分工 |
|---|---|---|
| 數據圖 | ROC、學習曲線、殘差圖 | Codex 先做受控模板與黃金範例；writer 寫教學意圖與資料宣告；計算由非作者核算 |
| 示意圖 | K-fold 切分、洩漏路徑 | writer 寫需求，Codex 做 SVG；流程圖可用 Mermaid |
| 互動圖 | 只用在閾值移動 | Codex，並一定附靜態版 |

1. Markdown 引用：`![圖說](figure:<圖ID>)`。資料宣告放 `content/figures/`，建置產物不手改。
2. 圖資來源標明「教學模擬資料」或真實來源。指標數值由同一份資料算出，不手填。
3. 每張圖有替代文字與圖說。全站固定顏色語意，不只靠顏色區分。
4. L23303 視覺清單以 RS2 為起點，由 writer 依學習目標判斷哪些需要；不需要圖的頁寫明理由。

## 7. 考題剖析

1. 沿用題目 YAML 既有的 `explanation`（考什麼、正解理由、各選項錯在哪）。
2. 新增 `explanation.rule`：一句可重用的判斷規則，並連到概念頁。不另寫一份重複的剖析。
3. 題目頁順序：作答 → 對錯與官方答案 → 逐選項解析 → 判斷規則 → 回到概念頁。
4. 每代碼的「考點整理」頁先不做，等逐題內容穩定後再評估。

   - 有效審查：該列有 `reviewer`，且 `reviewed_revision` 等於該列 `concept_id` 概念頁目前的 `sha256:` 雜湊。頁面改過就要重審。
   - 已對應：目標至少有一列合法、非 `unmapped`、`concept_id` 與 `section_anchor` 齊全。
   - 審查完整：同時滿足 3 點。(1) 至少一列 `complete` 且審查有效，它的 `evidence_refs` 合起來滿足該目標全部 `required_evidence`。(2) 該目標沒有 `unmapped`／`mentioned` 列。(3) 該目標每一列都有有效審查。
   - `partial` 列表示支援頁只教一部分，照實保留，不為了分數刪除或硬補成 `complete`。`review_note` 寫明它負責哪部分、完整證據在哪一列。
   - 報告另列「映射列審查」：有效審查列數／總列數，以及各狀態列數。
   - 已知限制：跨頁引用的證據（例如 precision 列引用 recall 頁）只核對主頁雜湊。被引用頁改動時，要人工安排重審。要自動化時另提格式變更。

### 9.1 欄位契約（協調者定，所有 worker 照用）

概念頁 frontmatter 新增：

```yaml
summary: ROC 曲線把每個閾值下的真陽率與假陽率畫成一條線   # 一句話，≤ 40 字
goals:                       # 讀完你會，1–3 條
  - id: g1

formula_groups:              # 有公式才寫
  - id: tpr-fpr

    checked_by: null         # 核對者（reviewer 任務 ID）
self_check:                  # 每個 goal 至少 1 題，共 2–5 題
  - id: c1
    goal: g1
    type: choice             # choice | short
    prompt: 題幹
    options: { A: ..., B: ..., C: ..., D: ... }   # 只有 choice，固定 4 個選項
    answer: B                                # 只有 choice
    explain: { A: ..., B: ..., C: ..., D: ... }   # choice：每個選項一句理由
    key_points: [ ... ]                      # 只有 short：可接受的關鍵點
```

- 檢核小題：選擇題至少占 2/3。排列順序固定為所有 choice 在前、short 在後；題目 `id` 不因排序而改。正解位置要分散：同一頁的正解不得全部相同；同一單元每個字母不超過 40%。選項不用「以上皆是／皆非」，解析不用字母指代其他選項。
- 前置概念沿用既有的 `requires`，不另加欄位。
- 正文固定的二級標題（依骨架順序，不適用的省略）：`## 為什麼需要`、`## 直覺`、`## 定義與公式`、`## 算一次`（或 `## 走一次流程`）、`## 程式`、`## 怎麼用、怎麼判讀`、`## 常見誤解`、`## 進階`、`## 小結`。「一句話」用 `summary`，「讀完你會」用 `goals`，「檢核小題」用 `self_check`，都由網站顯示，不寫在正文。
- `## 進階` 由網站預設收合。補充內容在小節標題後加「（補充）」。
- 提示框用 Starlight 語法：`:::tip[重點]`、`:::caution[注意]`、`:::note[例子]`；程式段落另可用 `:::tip[讀碼重點]`。
- 圖：`![圖說](figure:<圖ID>)`。

代碼頁 `stages` 每階段新增 `intro`（2–4 句階段導讀）。題目 YAML 的 `explanation` 新增 `rule`（一句判斷規則）。

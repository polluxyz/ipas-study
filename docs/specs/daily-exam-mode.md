## 3. 使用者可見的行為

### 3.1 交卷前

- 點選項就暫存答案。已答題可回去改答，但不能改回未答。
- 目前題目沒選答案時，「下一題」停用，也不能跳到後面的題。
- 畫面不顯示對錯、答案、解析、答對題數、分數。
- 每題有「不確定」切換鈕。選好答案後才能使用。
- 快速選單只列已答題與第 1 個未答題，點題號跳題。全部答完才會列滿 N 題。
- 「下一題」前往下一個位置。下一個位置既未答、也不是第 1 個未答題時，前往第 1 個未答題（只會發生在第 4.3 節的舊作答）。
- 上方顯示：已答 A／N・不確定 U・累計用時。不強制時限。
- 全部 N 題答完，「交卷」才能使用。按下一律跳確認視窗，因為交卷不可撤銷。
- 確認視窗顯示不確定題數。預設焦點在「返回作答」。取消後焦點回到「交卷」按鈕。
- 題卡不再有「確認作答」按鈕與「每題確認作答後，立即顯示解析」的文字。
- 鍵盤按 Enter 不會提交，也不會顯示解析。

### 3.2 交卷後

- 一次寫入 `Attempt`，顯示答對 C／N 題、C×2 分／2N 分。N 不是 50 時，標明不是正式考試換算。
- 選項與不確定標記鎖定，重新整理後不變。
- 所有題可回看答案與解析。
- 焦點只移動 1 次，移到成績摘要。
- N=0 時不提供交卷。
- 計時在交卷時停止。

### 3.3 快速選單的狀態

題號不加勾勾、叉叉、問號等記號，只用顏色（使用者 2026-11-06 指定）。朗讀文字保留，螢幕報讀軟體仍可分辨。綠色與橙色要有足夠的明暗差。目前所在題號的外框與不確定外框要能分開辨識。

交卷前：

| 狀態 | 顏色 | 朗讀文字範例 |
|---|---|---|
| 第 1 個未答題 | 灰色 | 第 12 題，未答 |
| 已答 | 綠色 | 第 12 題，已答 |
| 已答且不確定 | 橙色 | 第 12 題，已答，標記不確定 |
| 其他未答題 | 不顯示 | 無 |

選答案的當下，該題號立刻從灰色變綠色。按「下一題」後，新的題號以灰色加入選單。

交卷後列滿 N 題：

| 狀態 | 顏色 | 朗讀文字範例 |
|---|---|---|
| 答對 | 綠色 | 第 12 題，答對 |
| 答錯 | 紅色 | 第 12 題，答錯 |
| 曾標不確定 | 上述顏色加橙色外框 | 第 12 題，答錯，曾標記不確定 |
| 解析不可用 | 灰色 | 第 12 題，已移除或改版 |

綠色在交卷前後意思不同，所以圖例文字要跟著換。

### 3.4 開啟頁面時選哪一份題組

本節由 `docs/specs/daily-booklet.md` 第 4.1 節取代。以下保留作為第 1 版的紀錄。

依序判斷目前科目：

1. 草稿狀態是 `open` 或 `submitting`：還原這份草稿，不看日期。日期不是今天時，明示「正在續作 2026-11-05 題組」。狀態是 `submitting` 時先自動重試提交。
2. 草稿狀態是 `submitted`：顯示檢討畫面。日期不是今天時，提供「開啟今日題組」按鈕。日期是今天時，說明明天才有新題組。
3. 沒有草稿，但有今日題組：這是舊流程建立的題組。依第 4.3 節掃描舊作答，建立草稿。
4. 其他情況：抽今日題組並建立草稿。舊日期的題組沒有草稿，代表舊流程已結束，不再續作。

開啟頁面時要先讀草稿，不可先用今日題組蓋掉舊題組。午夜不停用作答，也不自動交卷。

### 3.5 位置

網址 `position` 指向選單內的題號時優先，否則讀草稿的位置，再否則第 1 個未答題。不可用網址跳到選單沒有的題。

### 3.6 例外情況

| 情況 | 行為 |
|---|---|
| 草稿保存失敗 | 持續提示，提供重試，保留畫面上的答案。不可當成已保存 |
| 草稿損壞或版本未知 | 保留原資料，停止覆寫，提示問題。不建立新題組 |
| 另一頁更新過草稿 | 本頁改唯讀，提示重新載入 |
| 另一頁清除資料 | 本頁改唯讀，不可把舊資料寫回 |
| 題目改版或移除（交卷前） | 略過並提示，不補題，N 扣除該題 |
| 建立題組時候選題為 0 | 不建立草稿，顯示目前沒有可做的題目。題庫恢復後重新開頁就抽新題組 |
| 同日快取的題目全部已移除或改版，且沒有非空草稿 | 視同沒有快取，重新抽題並取代快取。快取不含使用者作答，不需要使用者確認。候選題為 0 時依上一列處理 |
| 既有草稿沒有可作答的題（題目清單為空，或全部已移除、改版） | 不能交卷，也不新增 `Attempt`。題目清單為空時視同沒有草稿，依本節之前的規則處理。清單不為空時保留草稿，明示「這份題組已沒有可作答的題目」，提供「開啟今日題組」入口；使用者按下才以今日題組取代 |
| 題目改版或移除（交卷後） | 分數維持交卷當時的值。該題顯示「已移除或改版，解析目前不可用」 |
| 匯入舊備份 | 不改變草稿，也不會讓題組變成已交卷 |
| 匯出、清除、再匯入 | 正式作答可恢復；草稿、標記、題組順序不恢復。備份與清除的說明文字要寫明 |

## 4. 資料格式

本節由 `docs/specs/daily-booklet.md` 第 6 節取代。第 1 版資料的遷移規則見該規格第 6.3 節。交卷寫入順序與重試（第 4.2 節）仍沿用。以下保留作為第 1 版的紀錄。

### 4.1 新鍵 `ipas-daily-draft-v1`

這是核可過的新格式。`Attempt`、`ipas-attempts-v1`、`ipas-daily-v1` 的格式都不變。

```ts
interface DailyDraftQuestion {
  id: string;
  rev: number;
  choice: Choice | null;
  unsure: boolean;
  ms: number;                 // 這題累積的可見停留時間
  legacyAttemptId?: string;   // 第 4.3 節沿用的舊紀錄
  correct?: boolean | null;   // 交卷時固定
}
interface DailySubmission {
  ts: string;                 // 實際交卷時間
  attempts: Attempt[];        // 本次新增的紀錄，ID 在此固定
  total: number;              // N
  correct: number;            // C，含沿用的舊紀錄
}
interface DailyDraft {
  id: string;                 // 隨機 ID；清除後重建會不同
  seq: number;                // 每次寫入加 1
  subject: 1 | 3;
  date: string;               // 題組建立日期，不是今天的日期
  status: 'open' | 'submitting' | 'submitted';
  position: number;           // 0 起算
  questions: DailyDraftQuestion[];  // 順序就是題組順序
  submission?: DailySubmission;     // submitting、submitted 才有
}
// 儲存內容：{ version: 1, drafts: DailyDraft[] }，每科最多 1 份
```

- 寫入時只替換目前科目那一份，另一科以最新讀到的內容為準。
- 寫入前比對 `id` 與 `seq`。不符或草稿已不存在，就拒絕寫入並回報衝突。
- 只監聽 `storage` 事件不夠。它可以提早發現衝突，但不能取代寫入前比對。

### 4.2 交卷的寫入順序

1. 結算計時，組出 `submission`，把草稿改成 `submitting` 並保存。之後答案與 ID 不再變動。
2. `attempts.ts` 驗證整批，依 ID 去重後合併，用 1 次 `setItem` 寫入作答鍵。
3. 把草稿改成 `submitted` 並保存。
4. 第 3 步完成才宣告成功並顯示解析。

任何一步失敗都可以重試。重試沿用第 1 步固定的 ID，所以新增筆數不變。不可在頁面上迴圈呼叫 `saveAttempt`。

`Attempt` 的欄位：`ts` 是實際交卷時間；`mode` 是 `daily:<題組建立日期>:S<科目>`；`ms` 是該題累積時間。

### 4.3 上線當天的舊作答

- 只在「題組已存在、草稿不存在」時掃描 1 次。之後不再掃描，所以匯入備份或在其他入口作答都不會鎖住題目。
- 條件：`mode` 等於該題組的 mode，且 `qid`、`rev` 都相符。同題多筆時取最新一筆。
- 符合的題目記下 `legacyAttemptId` 與 `choice`，鎖定不可改答。
- 交卷時這些題新增 0 筆 `Attempt`，舊紀錄的 `ts` 與 `mode` 不動，`correct` 計入分數。
- 題組含這類題目時，畫面註明「部分解析曾顯示」。
- 不確定鈕在這些題仍可使用。
- 舊作答可能不連續，例如第 1、2、5 題。選單列出這些已答題與第 1 個未答題（第 3 題）。

### 4.4 還原規則

- 交卷前與檢討畫面都只讀草稿，不從 `Attempt` 推導。
- 既有 `Attempt` 不能單獨讓題組變成已交卷。
- 本機自學頁不防查原始碼。需求是畫面與可存取內容不呈現結果，不要求 HTML 移除答案。

## 5. 計時

- 每題累積頁面可見時的停留時間，放進草稿的 `ms`。
- 跳題、切到背景、離開頁面、交卷時結算並保存。頁面可見時每 15 秒另存 1 次。
- 異常關閉頁面時，最多遺失 15 秒。
- 關閉頁面的時間不計入。重新整理後累計用時不倒退。
- 舊流程的鎖定題不再累積時間。
- 題卡與題組的計時合成單一來源。

## 6. 版面

版面方案要使用者看過 mockup 才大量實作。設計由 Codex 判斷。

### 6.1 使用者指出的問題（2026-11-05 截圖）

| 問題 | 量測或原因 |
|---|---|
| 「上一題」與「下一題」上緣不同高 | `#daily-next` 多了 16px 上邊距。兩鈕 top 為 1164 與 1172，差 8px。`/official/` 相同 |
| 「提交後顯示答案與完整解析」與「確認作答」未對齊 | 題卡 `.answer-actions` 的按鈕同樣多了 16px 上邊距。`/official/` 相同 |
| 「每題確認作答後，立即顯示解析」緊貼按鈕，字級 16px 大於周圍 | 按鈕是 12.96px，上方小字是 12.16px。這段文字也與題卡小字重複 |
| 「確認作答」在右，「上一題／下一題」在左下 | 動作按鈕分 2 列，原作者與修改摘要夾在中間 |

上邊距問題在共用樣式修正，`/official/` 一併受惠。修正後要回歸檢查。

### 6.2 其他已觀察到的問題

- 頁首 6 段資訊（官方題連結、科目選單、日期、狀態、剩餘題數、錯題連結）字級與間距不一。
- 進度條、題號、題型標籤分散成 3 列。
- 題幹與選項字級差距大。
- 主欄 1056px 寬，一行過長。
- 科目選單旁的「開啟今日題組」在續作舊題組時語意不對。

### 6.3 限制

- 桌面右側放快速選單，手機改成可展開的面板，並提供展開狀態與明確名稱。
- 不可只靠縮小主欄容納選單。長選項、程式碼、原題附圖要維持可讀。
- 驗證 320、375、1440 寬度與暗色模式。全站目前由 `LightTheme.astro` 固定亮色，沒有切換入口。本功能不新增入口，暗色樣式以測試設定 `data-theme="dark"` 驗證，一般文字對比至少 4.5:1。
- 頁首的流程說明只出現 1 次：標題說明「完成後一起檢討」，導讀與狀態列不再重述。
- 科目卡的已答數與狀態跟著作答、交卷立即更新，不需重新載入。另一分頁更新另一科時，收到草稿變動事件或回到分頁就刷新 2 張科目卡，不換目前題組。
- 科目卡文字依序判斷：沒有草稿「尚未開啟」；題目清單為空「沒有可作答題」；已交卷「已交卷・已答 X／N」；未交卷且全部已移除或改版「題目已失效・需換題」；其他「作答中・已答 X／N」。
- 上面的例外：建立題組時目前科目候選題為 0，且沒有既有非空草稿時（第 3.6 節），本頁用暫時的空草稿，科目卡顯示「沒有可作答題」，這個草稿不保存。另一科的頁面讀不到草稿，仍依規則顯示「尚未開啟」。
- 手機面板點題號跳題後自動收合。題號被拒絕（例如目前題未答時點後面的題）時不收合、不跳題。桌面的選單維持展開。
- 視窗寬度改變時，焦點不可掉回頁面本體：選單收合時，選單內的焦點移到展開按鈕；放寬後展開按鈕被隱藏時，焦點移到目前題號；目前題號停用時移到「重試保存」，再不行移到題目標題。縮窄後展開按鈕要在可視範圍內，且不被固定列遮住；按鈕原本就可見時不捲動。固定列之間放不下按鈕的極低高度不適用這條可視要求（實測 320×240：可用 40px，按鈕 48px），焦點仍留在按鈕上。
- 交卷按鈕寬度在未答完與全部答完時相同，答完不縮窄。
- 只有程式碼區可橫向捲動，整頁不可水平溢出。
- 出處、授權、概念連結仍可讀。
- 共用字級若調整，要回看 `/official/`、`/quiz/`、單題頁。

### 6.4 無障礙

- 跳題後，焦點移到題號或題幹標題。
- 不確定鈕提供 `aria-pressed`，`type="button"`。
- 每秒更新的計時不觸發朗讀。
- 底部按鈕的 Tab 順序與視覺順序一致：上一題、不確定、下一題。

### 6.5 已核可的按鈕位置

所有寬度都適用，包含手機。

| 元素 | 交卷前 | 交卷後 |
|---|---|---|
| 題目卡頂端進度列右側 | 「交卷」。未答完時停用並顯示「交卷（31／50）」 | 「已交卷・僅供檢討」 |
| 底部操作列左側 | 上一題 | 上一題 |

- 底部操作列只放這 3 個按鈕，所有寬度都排成 1 列，文字不截斷。
- 進度列與底部操作列固定在畫面上，長題目捲動時仍看得到交卷與下一題。固定列不可遮住跳題後的題目標題。
- 320×700 時，2 條固定列之間至少留 500px 讀題。這項在底部操作列貼住視窗下緣時量測。捲到題目卡尾端時，操作列停在原位、下方露出頁尾，內容沒有被遮住，不列入門檻。
- 量測門檻：交卷或已交卷文字右緣與題目卡內容區右緣差 ≤2px，上緣在題幹之上；上一題左緣、下一題右緣與操作列內容區的差 ≤2px；不確定與下一題間距 0–16px；底部按鈕上緣差 ≤1px；按鈕 `scrollWidth <= clientWidth`。

## 9. 界線

- Always：`Attempt` 格式不變；交卷前不顯示任何結果；保存失敗要明示。
- Ask first：把交卷模式擴大到其他頁面；新增「放棄題組」；把草稿加進備份檔；新增相依；改 CI。
- Never：把未答題寫成 `Attempt`；重寫舊 `Attempt`；頁面直接讀寫 localStorage；暗中丟棄草稿；午夜自動交卷。

不做：90 分鐘強制時限、模式切換、重新抽題、跨裝置同步。

## 10. 成功條件

1. 交卷前，整個已呈現頁面與可存取內容都沒有答案、解析、對錯、答對題數。Enter 鍵不改變這件事。
2. 重新整理、關閉分頁後，答案、不確定標記、位置、累計用時都還在。正常保存時用時誤差不超過 15 秒。
3. 本次交卷模式在交卷前不新增 `Attempt`；既有紀錄保留。
4. 本份題組本次交卷，每個有效已答題最多新增 1 筆；沿用舊紀錄新增 0 筆；失敗重試不增加筆數。
5. 快速選單符合第 3.3 節兩張表。交卷前的題號數等於已答數加 1（全部答完時等於 N），交卷後等於 N。題號沒有顏色以外的記號。
6. 跨日未交卷時，舊題組與答案完整保留；切換科目不會覆蓋。交卷後才開得了今日題組。
7. 交卷前，錯題本、未做題判斷、匯出檔內容都不因草稿改變。
8. 第 6.1 節 4 個問題都解決：同列按鈕上緣差不超過 1px；不再有重複說明。
9. `/official/`、`/quiz/`、單題頁仍即時解析。
10. `pnpm --dir demo test`、`node demo/scripts/check-textbook/cli.mjs --summary`、`pnpm --dir demo run build --force`、`node demo/scripts/daily-exam-smoke.mjs` 全過。
11. 目前題目沒選答案時，「下一題」、不確定鈕、網址參數都無法前進或標記；未答完不能交卷。
12. `/daily/` 的按鈕位置符合第 6.5 節全部門檻：2 科、寬度 320／375／390／1440、未答完／答完／交卷後都要量。

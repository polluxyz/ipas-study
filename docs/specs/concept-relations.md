- v1：Claude 起草。

本規格定義學習網站裡「概念與概念之間」可以畫哪幾種連線、怎麼判斷、怎麼檢查。題目、評鑑代碼、指引頁碼與概念的對應不在本規格內，另寫規格。

## 0. 假設清單（待使用者確認）

1. 關係是「學習用」的關係，不是完整的知識本體。目的只有 3 個：排出閱讀順序、找出易混淆的概念、從問題找到對策。
2. 科目 1 與科目 3 共用同一張圖。例如 CNN 只有一頁，同時標 L23203 與 L21102。
3. 概念總數估計 120–180 個。
4. 每條關係只在一個方向寫一次，反方向由程式在建置時算出來。
5. 關係由 Claude 撰寫，Codex 獨立複核。雙方不一致時保留兩方依據，由使用者決定。
6. 正文裡的 `[[連結]]` 不帶類型，只表示「這裡提到了」。有類型的關係只寫在 frontmatter（檔案開頭的設定區）。
7. 讀者程度：懂基本程式與高中數學，正在準備本考試，還沒學過這個概念。`requires` 依這個程度判斷。

## 1. 目標與成功條件

目標：寫內容的人看到兩個概念，能在 30 秒內決定「用哪一種關係」或「不用任何關係」，而且不同人判斷的結果一致。

可驗證的成功條件：

- **一致性**：Claude 與 Codex 各自只看本規格，獨立標註一組沒標過的新概念對（16 對）。兩方結果一致的比例 ≥ 85%。不重用舊的 16 對，避免規格只是針對舊題目調整。
- **檢查器**：第 5 節每條檢查規則，都有一個會失敗的範例和一個會通過的範例。
- **試做**：L23303 的 3–5 個概念頁照本規格寫完，檢查器 0 個錯誤。
- **學習價值**：試做頁面先產生「建議先讀」清單、對策表、比較表。使用者看過，確認有幫助，再做關係圖。

v1 一致性測試結果：16 對中 14 對一致（87.5%）。2 對不一致，原因與修正見第 9 節。

## 2. 節點：概念

### 2.1 概念 ID

- 用英文小寫加連字號，例如 `cnn`、`data-leakage`、`roc-auc`。
- ID 一旦發布就不能改。改名只改 `title`，ID 不動。理由：題目、作答紀錄、其他概念頁都用 ID 指向它。
- 中文名稱、簡體寫法、常見別名放在 `aliases`，給搜尋用。例如 `資料洩漏`、`資料泄漏`、`data leakage`。
- 縮寫有多種意思時，ID 寫全名。例如 LDA 分成 `linear-discriminant-analysis` 與 `latent-dirichlet-allocation`，兩頁的 `aliases` 都可以有 `LDA`。

### 2.2 概念種類 `kind`

每個概念只能有一個種類。種類主要用來檢查 `mitigates` 的目標，以及提醒可能寫錯的關係（見 4.2）。

| kind | 意思 | 例子 |
|---|---|---|
| `model` | 完整的模型、演算法、模型族 | CNN、Random Forest、集成模型 |
| `component` | 模型或系統裡的一個元件 | 池化層、自注意力、輸出層、檢索器 |
| `technique` | 方法、技巧、處理步驟、策略 | Dropout、SMOTE、交叉驗證、LoRA、Bagging |
| `metric` | 評估指標 | F1、ROC-AUC、Statistical Parity |
| `problem` | 會出錯的現象或風險 | 過擬合、資料洩漏、梯度爆炸、演算法偏見 |
| `theory` | 數學或原理 | 貝氏定理、先驗機率、偏差-變異權衡 |
| `regulation` | 法規、標準、治理框架 | GDPR、個資法、NIST AI RMF |
| `tool` | 程式框架、函式庫、API、產品 | PyTorch、scikit-learn Pipeline、向量資料庫 |

**同名的方法與模型**：Bagging、Boosting 這類名稱同時指「策略」和「用這個策略的模型」。方法頁的 kind 是 `technique`。具體模型用 `requires` 指向方法頁；要分類時，`is_a` 指向模型族頁。例如：Random Forest `is_a` 集成模型、Random Forest `requires` Bagging。

## 3. 關係類型（5 種）

所有關係都是「從本頁概念 A 指向概念 B」。

| 類型 | 讀法 | 例子 |
|---|---|---|
| `is_a` | A 是一種 B | LoRA `is_a` 參數高效微調 |
| `part_of` | A 是 B 一定有的組成元件 | 池化層 `part_of` CNN |
| `requires` | 不懂 B，就讀不懂 A | CNN `requires` 卷積 |
| `mitigates` | A 用來減輕或防止問題 B | Dropout `mitigates` 過擬合 |
| `contrasts` | 考題或指引會要求分辨 A 與 B | ROC-AUC `contrasts` PR-AUC |

### 3.1 各類型的判斷細則

**`is_a`（分類）**

- 用句子測試：「A 是一種 B」要成立。B 的共同特性，A 都要有。
- 只連到最近的上層。LoRA 連到「參數高效微調」，不要再直接連到「微調」。

**`part_of`（組成）**

- 用句子測試：B 的標準定義裡一定有 A。
- 常見的實作選項不算。RAG 一定有檢索器，所以檢索器 `part_of` RAG。RAG 不一定用向量資料庫（也可以用關鍵字檢索），所以向量資料庫和 RAG 之間不寫 `part_of`。
- 訓練方法不是組成元件。反向傳播和 CNN 之間用 `requires`，不用 `part_of`。

**`requires`（前置知識）**

- 這是學習上的前置，不是技術上的相依。依第 0 節第 7 條的讀者程度判斷。
- 用句子測試：解釋 A 的定義或原理時，一定要用到 B。
- 「常在同一個流程裡一起出現」不算。超參數調校可以只用一份驗證集完成，不一定要交叉驗證，所以兩者之間不寫 `requires`，改在正文用 `[[交叉驗證]]` 連結。
- 只寫直接前置。A `requires` B、B `requires` C 時，A 不再寫 C。
- 每個概念的 `requires` 建議不超過 4 個。超過時，通常表示這個概念要拆頁，或有些前置其實是間接的。

**`mitigates`（對策）**

- B 一定是 `kind: problem`。
- 只寫教材或考題明確當成對策的關係，必須附 `source`（見 4.1）。Dropout 對過擬合要寫。Batch Normalization 對過擬合不寫，它的主要用途不是這個。
- 對策沒效、或有副作用的情境，寫在 `note`。例如「資料增強 `mitigates` 過擬合；note：增強方式改變標籤語意時會產生錯誤樣本」。

**`contrasts`（易混淆）**

- 必須附 `note` 與 `source`。`note` 用一句話寫出兩者的關鍵差異，這句話就是考點。
- 考題比較過、或指引比較過的組合都收。只收考過的組合，網站會變成只背歷屆題。
- 法規之間只在 `source` 指出具體比較點時才寫。例如 GDPR 與個資法在「被遺忘權」上的差異有來源，才寫。
- 只寫「確實會被拿來比較」的組合，不寫「兩個東西屬於同一類」。同類關係由 `is_a` 處理。
- 只在其中一頁寫：寫在 ID 字母順序較前的那一頁。

### 3.2 判斷方式

1. 對 5 種類型逐一檢查，不是找到第一個符合的就停。
2. 每種類型都要測 2 個方向：A→B 和 B→A。
3. `contrasts` 可以和其他任何類型同時存在。
4. `is_a` 與 `part_of` 不能同時存在於同一對概念。
5. 5 種都不成立時，不寫有類型的關係，只在正文用 `[[B]]` 連結。這是正常結果，不是每兩個相關的概念都需要有類型的關係。

### 3.3 刻意不收的類型

| 不收的類型 | 理由 | 改用 |
|---|---|---|
| `related`（相關） | 什麼都能放，最後會變成垃圾桶 | 正文 `[[連結]]` |
| `used_in`（被用於） | 和 `part_of`、`requires` 難以區分 | 依 3.2 判斷 |
| `evaluates`（評估） | 指標評估模型的關係太普遍，每個分類模型都會連到 F1 | 指標用 `is_a` 歸類 |
| `causes`（導致） | 數量少，可以在 problem 頁的正文寫成因 | 正文說明 |
| 配對關係（任務↔損失函數、任務↔輸出層） | 是「條件 → 選擇」的對照，不是兩個概念之間的關係。例：115-1 科3 第10題 | 概念頁內的對照表 |

## 4. 寫法

### 4.1 frontmatter 格式

```yaml
id: cnn
title: CNN 卷積神經網路
aliases: [卷積神經網路, Convolutional Neural Network]
kind: model
codes: [L23203, L21102]
is_a: [deep-learning-model]
requires: [convolution, backpropagation, activation-function]
contrasts:
  - target: rnn
    note: CNN 擷取局部空間特徵；RNN 依序處理時間序列，保留前後文狀態
    source: [guide-3:4-xx, 115-1-S3-Q00]
```

```yaml
id: dropout
kind: technique
mitigates:
  - target: overfitting
    note: 只在訓練時隨機關閉神經元；推論時不關閉
    source: [guide-3:4-xx]
```

- 沒有的關係可以省略該欄位。
- `is_a`、`part_of`、`requires` 只用 ID 清單，`source` 可省略。
- `mitigates` 用物件格式，`target` 與 `source` 必填，`note` 可省略。
- `contrasts` 用物件格式，`target`、`note`、`source` 都必填。
- `source` 格式：指引寫 `guide-<科目>:<印刷頁碼>`；考題寫題目 ID（規則另定，暫用 `<場次>-S<科目>-Q<題號>`）。

上面範例中的 `4-xx`、`Q00` 是佔位符，不是真實頁碼。

### 4.2 種類檢查

只有 1 條是硬限制，其他是提醒。

| 規則 | 層級 |
|---|---|
| `mitigates` 的 B 必須是 `problem` | 錯誤 |
| `is_a` 的 A、B kind 不同 | 警告：先確認是否應改成「指向模型族頁」或 `requires` |
| `part_of` 的 B 是 `problem` 或 `metric` | 警告 |

## 5. 建置時的檢查規則

| 編號 | 規則 | 違反時 |
|---|---|---|
| C1 | 概念 ID 唯一；所有目標 ID 都存在 | 錯誤 |
| C2 | 欄位名稱、格式符合 4.1（例如 `contrasts` 缺 `note`、`mitigates` 缺 `source`） | 錯誤 |
| C3 | 不能指向自己 | 錯誤 |
| C4 | `is_a`、`part_of`、`requires` 各自不能形成循環 | 錯誤，列出循環路徑 |
| C5 | 同一頁同一類型重複寫同一個目標 | 錯誤 |
| C6 | 同一對概念同時有 `is_a` 與 `part_of` | 錯誤 |
| C7 | `contrasts` 同一對寫在兩頁，或沒寫在字母順序較前的那一頁 | 錯誤 |
| C8 | 4.2 的種類檢查 | 依 4.2 |
| C9 | `source` 指向不存在的考題 ID，或頁碼格式錯誤 | 錯誤 |
| C10 | `requires` 有多餘的間接前置（任意長度的路徑都算） | 警告 |
| C11 | `requires` 超過 4 個 | 警告 |
| C12 | 孤立概念：沒有任何進出的有類型關係、沒有被正文連結、沒有被題目引用 | 警告 |
| C13 | `aliases` 在不同概念間重複 | 警告；兩頁都要顯示「你是不是要找…」 |

## 6. 網站上的呈現

先做清單與表格，確認有學習價值後再做關係圖（見第 1 節「學習價值」）。

| 關係 | 在 A 頁顯示 | 在 B 頁顯示（反向，自動產生） |
|---|---|---|
| `is_a` | 頁首分類路徑：深度學習模型 › CNN | 「種類」清單 |
| `part_of` | 「屬於」 | 「組成元件」清單 |
| `requires` | 「建議先讀」，沿著前置往回排出閱讀順序 | 「讀完可以接著讀」 |
| `mitigates` | 「用來處理」 | problem 頁的「對策」表，含 note 與來源 |
| `contrasts` | 比較表，含 note 與來源 | 同一張比較表 |

表格的「來源」欄只顯示指引來源。`source` 裡的考題 ID 放進預設收合的考古題區，不在表格裡顯示（2026-11-01 使用者核可，見 `docs/specs/textbook.md` 第 8 節第 9 條）。

關係圖（第二步）：每頁顯示距離 1–2 步的局部圖。全域圖可以依科目、評鑑代碼、關係類型篩選。

### 6.1 關係圖 v1（2026-10-31 使用者決定）

- 做全域圖與局部圖兩種。先做全域圖的小型原型給使用者看，方向確認後再做局部圖。
- 連線分兩層：5 種有類型的關係用不同顏色或線型，並標出方向；正文的 `[[連結]]` 畫成淡色細線，可以用開關隱藏。同一對概念已有類型關係時，不再畫正文連結。
- 正文連結只是畫面上的輔助，不是第 6 種關係類型，不匯出到 `relations.csv`。
- 畫圖套件只加在 `demo/`，由 Codex 選一個並回報名稱、版本、大小與理由（使用者已核可新增一個套件）。
- 離線可用，不連外網。原本的清單與表格保留，地圖不取代它們。

## 7. 界線

- **Always**：新增概念前先搜尋 `aliases`，確認沒有重複的概念。
- **Always**：`mitigates` 與 `contrasts` 附 `source`。
- **Ask first**：新增第 6 種關係類型，或新增 `kind`。
- **Ask first**：修改已發布的概念 ID。
- **Never**：用 `contrasts` 或 `requires` 代替「相關」。
- **Never**：從學習指引照抄 note 原文。
- **Never**：用一致性投票決定概念的意義。雙方意見不同時，回到定義與來源判斷。

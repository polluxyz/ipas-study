## 4. 使用者可見的行為

### 4.1 開啟 `/daily/`

網址不變，桌面捷徑不用改。開頁與重新整理都不抽題。

| 該科狀態 | 畫面 |
|---|---|
| 有未交卷題本 | 直接接續，答案、不確定標記、位置、用時都保留 |
| 全部已交卷 | 顯示最後一本的檢討，並提供「開下一本」 |
| 沒有任何題本 | 顯示「開第 1 本」按鈕 |
| 未做題用完 | 顯示「未做題已用完」，不提供開本按鈕 |
| 目前題本已沒有可作答的題（全部移除或改版） | 明示「這本已沒有可作答的題目」，提供「結束這本」。不自動抽題 |

### 4.2 開下一本

1. 按鈕只在該科沒有未交卷題本時出現。
2. 按下後才抽題，寫入題本，畫面進入第 1 題。
3. 寫入失敗時不進入作答，保留原題本，顯示錯誤。

隔天開頁仍是同一本，也不會出現新題本。

### 4.3 題本清單

每科列出全部題本，內容如下：

- 「第 N 本」、建立日期、狀態（作答中／已交卷／已結束）、題數。
- 作答中的題本顯示已答題數。已交卷的題本顯示答對題數。
- 已交卷的題本可點開回看檢討。回看是唯讀，不計時。
- 清單旁寫明「題本只存在這個瀏覽器的這個網址」。

回看網址是 `/daily/?subject=<科目>&book=<題本 ID>`。

### 4.4 進度數字

| 數字 | 算法 |
|---|---|
| 這本已答 | 目前題本已選答案的題數 A，顯示 A／N |
| 今日交卷 | 該科今天（台北時間）交卷的題本題數合計。跨日交卷算在交卷日 |
| 可再開 | 第 5.2 節的 `F`，顯示可開完整本數與最後一本題數 |

「每天 50 題」只是建議文字，不限制開本。不顯示「今日實答」與「落後量」，因為現有資料沒有逐題作答日期。

### 4.5 舊紀錄

只彙整 `daily:` 與 `booklet:` 開頭的作答。一般測驗、官方題、單題頁的作答不列入。

同一 `mode`、同一 `qid` 只看最新 1 筆作答。這筆作答的 `id` 被某本引用，就算題本已呈現，不列舊紀錄。「引用」只有 2 種：該本目前 `questions` 內某題的 `legacyAttemptId` 等於這個 `id`；該本 `submission.attempts` 含這個 `id`。`retired` 題本不算引用。

只有相同的 `mode` 或 `qid` 不算引用。`assignedQids` 只供抽題排除，不決定歸屬。遷移時沒留下的題、失效後被略過的題，以及草稿題未交卷時匯入的舊作答，都列入舊紀錄。這些作答不會同時從題本與舊紀錄消失。

其餘作答依 `mode` 分組，每組列 1 行：

| 欄位 | 算法 |
|---|---|
| 日期 | `daily:` 取 `mode` 內的日期。`booklet:` 取該組最新 `ts` 的台北日期 |
| 科目 | `mode` 結尾的 `S<科目>` |
| 已答、答對 | 同 `qid` 只算最新 1 筆 |

清單已被覆蓋時，畫面寫明：未答題清單無法列出；這些題仍在題庫，之後可能抽到。

舊紀錄不算題本，不佔「第 N 本」，也不計入「今日交卷」。「今日交卷」只累加已交卷題本的 `submission.total`，每本 1 次。

### 4.6 名稱

側欄與頁面標題由「每日 50 題」改成「每日題本」。其他頁面提到每日題組的文字同步修改。

## 5. 不重複規則

### 5.1 抽題排除

抽新題本時，下列題目都不抽：

1. 任何模式有作答紀錄的題。比對 `qid`，所以題目改版後不算新題。
2. 已在任何題本 `assignedQids` 內的題，包含未交卷題本與已結束題本。
3. 第 5.3 節同題群組內，已有成員符合第 1、2 項的題。
4. 這次抽題已選中成員的同題群組其他題。

其他條件沿用現有規則：`source: mock`、`review.status: verified`、有主代碼、科目相符。代碼權重與程式題目標也沿用（`demo/src/lib/daily.ts:45`）。代碼權重用完整題庫計算，不用排除後的題目計算。

### 5.2 題量算法

```text
F = 符合第 5.1 節第 1–3 項的題目分成的群組數（未列入群組的題自成 1 組）
可開完整本數 = floor(F / 50)
最後一本題數 = F % 50
```

實際抽到的題數必須等於 `min(50, F)`。`F` 是該科當下的值。科目 1 開本後，科目 3 的 `F` 要重算，因為同題群組跨科。兩科的 `F` 不可相加。

`F` 為 0 時顯示「未做題已用完」。下一本不足 50 題時，按鈕寫實際題數，例如「開下一本（41 題）」。不足 50 題的題本不換算成正式模擬卷分數，沿用現有少量題組說明。

全新紀錄的題量（2026-11-07，從 `content/questions/` 複算）：

| 項目 | 科目 1 | 科目 3 |
|---|---:|---:|
| 可抽題數 | 560 | 491 |
| 完整本數 | 11 | 9 |
| 同題群組最多再減 | 4 | 4 |
| 減完後的完整本數 | 11 | 9 |

使用者實際已做題數未知。2026-11-07 查 `127.0.0.1:4321` 的使用者瀏覽器：作答 0 筆、只有科目 1 的 2026-11-06 題組（`open`）。其他瀏覽器或網址的紀錄未查。實際本數由第 5.2 節在使用者瀏覽器算出。

做到 2026-11-13 需要每科 350 題，做到 2026-11-14 需要每科 400 題。上述需求要從已做題數與同題群組扣除後比較。

### 5.3 同題群組

新增內容檔 `content/question-duplicates.yaml`，列出編號不同但內容相同的題。群組只影響抽題排除，不改題目 ID，不刪題目。

比對條件：

1. 範圍：可抽題的題幹。
2. 正規化：去掉空白、標點與符號（Unicode 類別 Z、P、S），英文轉小寫。
3. 切組：每 2 個相鄰字一組，同一題內重複的組只算 1 次。
4. 相似度：共同組數除以聯集組數（Jaccard），不四捨五入，達 0.75 算候選配對。

分數只用來找候選配對。是否算同一題由人判斷。題幹相同且問同一判斷時，選項不同仍算同一題。

| 群組 | 比對結果 |
|---|---|
| `Z-L21203-006`、`Z-L23402-001` | 題幹相同，0 個選項相同 |
| `Z-L21301-002`、`Z-L23301-003` | 題幹相同，3 個選項相同 |
| `Z-L21302-005`、`Z-L23401-003` | 題幹相同，2 個選項相同 |
| `Z-L21301-004`、`Z-L23302-001` | 題幹相似度 0.90625，2 個選項相同 |

同一科內部：0 組題幹相同，0 對相似度達 0.75。

限制：比對只看題幹文字。情境不同但考同一概念的題不算重複（`question-bank-expansion.md` 第 237 行）。

內容檔另有 `distinct` 清單，列出分數達標、但人工判斷考點不同的配對，並寫明理由。例如運算符號、否定詞或數值不同，會改變答案。

單元測試用同一條件掃描題庫。出現未列入群組也未列入 `distinct` 的配對時，測試失敗。不可為了通過測試直接把配對併入群組。

### 5.4 題型比例

科目 3 全新紀錄下，程式題 192 題、其他題型 299 題。沿用現有抽題器連續抽題時，第 8 本起程式題比例會升高：

| 第幾本 | 程式題 |
|---|---:|
| 1–7 | 各 12 |
| 8 | 17 |
| 9 | 50 |

本規格不補題。題本的程式題超過 13 題時，題本頂端註明題數與原因。

## 6. 資料格式

### 6.1 `Attempt`

欄位與鍵 `ipas-attempts-v1` 不變。舊作答不重寫。

新題本的 `mode` 是 `booklet:<題本 ID>:S<科目>`。遷移來的題本保留原本的 `daily:<日期>:S<科目>`。

同一天同一科可能有 2 本，所以新題本不能用日期當身份。

### 6.2 新鍵 `ipas-daily-draft-v2`

```ts
interface BookletStore {
  version: 2;
  migratedAt: string | null;           // 從第 1 版遷移的時間；沒有舊資料時是 null
  current: { '1': string | null; '3': string | null }; // 各科目前題本 ID
  booklets: Booklet[];                 // 全部題本
}

interface Booklet {
  id: string;                          // 題本身份。新題本隨機；遷移題本依來源固定
  seq: number;                         // 寫入次數，用來偵測另一頁已更新
  subject: 1 | 3;
  number: number;                      // 「第 N 本」，只用於顯示與排序
  createdDate: string;                 // 建立日期（台北時間），不決定換題
  attemptMode: string;                 // 建立時固定，之後不變
  origin: 'new' | 'v1-draft' | 'v1-set';
  status: 'open' | 'submitting' | 'submitted' | 'retired';
  position: number;
  assignedQids: string[];              // 建立時分配的全部題目 ID，之後不變
  questions: DailyDraftQuestion[];     // 目前有效題，沿用現有欄位；失效題會被略過
  submission?: DailySubmission;        // 沿用現有欄位
}
```

規則：

- 讀寫只經過 `demo/src/lib/attempts.ts`。
- 驗證器依題本的 `attemptMode` 核對提交內容。`attemptMode` 只接受 `booklet:<本題本 ID>:S<本題本科目>`，或 `daily:<日期>:S<本題本科目>`。驗證器也檢查題本 ID 不重複、同科 `number` 不重複、`current` 指向存在且同科的題本、`questions` 的 ID 都在 `assignedQids` 內。
- 每次寫入先比對該題本的 `id`、`seq` 與該科 `current`。不符時改唯讀，提示重新載入。規則沿用 `daily-exam-mode.md` 第 2 節第 6 項。
- 每次寫入都重新讀 store，只替換目標題本與該科 `current`，其他科與其他題本保留最新內容。不可把呼叫端手上的整包資料寫回。
- 開本時也重新讀 store 與作答，確認該科沒有未交卷題本，再用最新資料算第 5.1 節的排除。讀、抽、寫在同一段同步程式內完成。
- 交卷寫入順序與重試沿用 `daily-exam-mode.md` 第 4.2 節，作答 ID 先固定再寫入。
- 開啟 `/daily/` 時，兩科的 `submitting` 題本都用原提交內容完成，再顯示畫面。
- 損壞或未知版本時顯示錯誤，不覆寫，不抽題。
- 回看只讀指定題本，不寫入，不要求它等於 `current`。
- 完整歷史每 15 秒重寫一次，寫入成本要實測（第 10 節）。

題本失效規則：

- 題目失效時，從 `questions` 略過，`assignedQids` 不變，所以恢復後也不會再抽到。該題已有的作答依第 4.5 節列入舊紀錄。
- `questions` 為空或全部失效時，不能交卷。使用者按「結束這本」後，狀態改成 `retired`，該科 `current` 改成 `null`，保留原資料，不寫 `Attempt`。
- `retired` 題本留在清單，標「已結束」，不計入進度。按鈕只在這個情況出現，不是「放棄題本」。

### 6.3 從第 1 版遷移

開啟 `/daily/` 時，如果新鍵不存在，就一次處理兩科，並且排在任何抽題之前。遷移不抽題，也不補題。

第 1 版每科最多 1 份草稿與 1 份清單。清單要讀全部日期，不可只查今天（`getDailySet` 需要指定日期，不能用於遷移）。

「相同」的定義：日期相同、科目相同、`qid` 集合相同。順序與 `rev` 以草稿為準。

每科依草稿與清單的組合處理：

| 草稿 | 清單 | 處理 | 目前題本 |
|---|---|---|---|
| `open` | 無或相同 | 建立 1 本，原順序、答案、標記、位置、用時全部保留；只略過下方去重規則指定的未答題 | 這本 |
| `open` | 不同 | 草稿 1 本；清單依下方保留條件建 1 本排在後面 | 草稿那本 |
| `submitting` | 無或相同 | 建立 1 本，提交內容與作答 ID 不變，開頁後完成原提交 | 這本 |
| `submitting` | 不同 | 同上，清單依下方保留條件建 1 本排在後面 | 草稿那本 |
| `submitted` | 無或相同 | 建立 1 本已交卷題本，可回看 | `null` |
| `submitted` | 不同 | 已交卷題本 1 本；清單依下方保留條件建 1 本 | 清單那本；清單沒有留下題目時是 `null` |
| 無 | 有 | 清單依下方保留條件建 1 本。用原 `mode`、`qid`、`rev` 找最新作答，鎖定並計分，`legacyAttemptId` 指向該筆 | 這本 |
| 無 | 無（含清單被覆蓋） | 不建立題本。作答保留，依第 4.5 節顯示舊紀錄 | `null` |

草稿的去重規則。先處理全部草稿，順序是科目 1、科目 3，同一份依題目順序。只有 `open` 草稿的未答題（`choice` 是 `null`）會被略過。已選答案的題、`submitting` 與 `submitted` 草稿的題一律保留。失效題不參與比較，依下方規則原樣搬入。

1. 未答題本身或同題群組的成員已有作答：略過這題。
2. 同題群組在草稿內有已選答案或已提交的題：略過未答題。
3. 同題群組在草稿內都是未答題：只保留處理順序的第 1 題。
4. 同題群組在草稿內都已選答案或已提交：都保留，不刪答案。

被略過的題不放進 `questions`，仍留在 `assignedQids`。`position` 指向原本那題。那題被略過時，改指向下一個留下的題；後面沒有題時，指向最後 1 題。

清單的保留條件。全部草稿處理完後，依科目 1、科目 3 處理清單。清單的每一題，符合下列任一項就留下：

1. 有同一 `mode`、`qid`、`rev` 的作答（要鎖定計分）。
2. 同時符合 3 件事：不是官方題；不與已分配的題重複（比對 `qid` 與同題群組）；本題與同題群組的成員都沒有任何作答（包含同 `mode` 不同 `rev`）。

官方題與失效題：

- 清單裡的官方題若沒有符合第 1 項，不留下，也不補題。作答保留。
- 草稿裡的官方題或失效題，遷移時原樣搬入。開頁時依第 6.2 節題本失效規則略過，答案不套到其他題。
- 清單留下 0 題時不建立題本。0 題的舊清單與去重後 0 題的 `open` 草稿都不建立題本。
- `assignedQids` 是來源的全部 `qid`，包含沒有留下的題，只供抽題排除。舊紀錄的歸屬依第 4.5 節。

補充：

- 第 1 版只有草稿能帶未交卷答案，每科最多 1 份。所以不會出現同科 2 份有答案的衝突。
- 同一科有多本未交卷時，交卷後先接續下一本未交卷題本，不抽新題。
- 舊清單若全部已答，遷移後狀態仍是 `open`。使用者按交卷後看到檢討，不會新增重複作答。
- 遷移題本的 ID 依來源固定：`v1-S<科目>-<日期>-draft` 或 `v1-S<科目>-<日期>-set`。固定 ID 只用來辨識來源。防止 2 頁互相覆寫靠下方的跨分頁鎖。
- 題號依建立日期排序，同日時已交卷排前面。

跨分頁鎖：開頁先讀新鍵。新鍵存在就不取鎖，直接走第 1 步。新鍵不存在時，用 `navigator.locks` 取得獨占鎖 `ipas-daily-migration`（Web Locks，瀏覽器內建，同一時間只有 1 頁能持有），再從第 1 步開始。第 1–6 步在鎖內的同一段同步程式完成，中途不能交出執行權。

寫入步驟：

1. 新鍵存在且合法：直接使用，結束。新鍵存在但不合法：顯示錯誤，不覆寫，結束。
2. 驗證第 1 版資料。損壞時停止，保留舊鍵，顯示錯誤。
3. 把第 1 版全部草稿的 `seq` 加 1，讀回比對。失敗時停止抽題，顯示錯誤。已載入舊草稿的舊分頁，下次寫入會進唯讀。
4. 第 3 步之後重新讀第 1 版資料與作答，依上表組出第 2 版資料。
5. 寫入新鍵，讀回比對。相符才算完成。
6. 讀回不符時：讀回內容是合法的第 2 版，代表另一頁已讀到新鍵並開始寫入，改用它。不合法才移除新鍵，保留舊鍵，停止抽題。

順序的理由：先停用舊分頁再讀資料，讀到的就是最後狀態。舊分頁正在交卷時，第 3 步之後它的最後一次寫入會失敗。遷移看到 `submitting`，用同一批作答 ID 完成，不會重複。任何一步之前關頁，瀏覽器會自動放鎖；下次開頁從第 1 步重來，`seq` 多加一次沒有副作用。

鎖的例外：

- 沒有 `navigator.locks`（網址不是 HTTPS、`localhost` 或 `127.0.0.1`）：不遷移，不抽題，舊鍵不變。顯示錯誤，請使用者改用 `http://127.0.0.1:4321/`。
- 等鎖超過 10 秒：不遷移，不抽題，舊鍵不變。顯示錯誤，請使用者重新載入。

保護範圍與限制：

- 鎖只排除新版頁面之間的交錯。舊分頁不取鎖，只靠第 3 步的 `seq` 防護。
- 只保護「已載入舊草稿的舊分頁」。舊分頁若重新讀到新的 `seq` 仍能寫入第 1 版鍵，例如沒有草稿的舊分頁切科後開新題組。
- 新舊鍵都在時，以新鍵為主。舊鍵只當復原來源，不再寫入新內容。舊分頁後續寫入不合併回題本。
- 所以上線時要請使用者先關掉舊分頁。

### 6.4 備份與清除

- 備份檔維持第 1 版。`booklet:` 作答照常匯出與匯入。
- 匯入只補作答與已讀，不修改現存題本，不會把未交卷題本變成已交卷。
- 清除後再匯入：作答恢復，題本清單不恢復，題號從 1 開始。做過的題仍不再抽。
- 頁面的備份說明寫明這件事。
- 清除資料時移除新鍵與舊鍵（`ipas-daily-draft-v2`、`ipas-daily-draft-v1`、`ipas-daily-v1`），也移除作答與已讀。

## 10. 測試策略

單元測試（Vitest，不連外網）：

- 第 6.3 節遷移表每一列，含兩科狀態不同（例如科目 1 `open`、科目 3 `submitting`，新鍵寫入後關頁再開）。
- 遷移來源：清單與草稿部分重疊、同題不同 `rev`、跨科同題群組、清單含官方題、0 題清單、0 題草稿。
- 遷移去重：清單未答題的同題群組已有一般測驗作答（不留下）；同模式已有作答的題（留下並鎖定）；同題群組的 2 題都未答、只有 1 題已答、都已答，各測跨科與同一份草稿；草稿未答題本身已有作答；`position` 指向被略過的題；去重後 0 題。
- 遷移交錯：讀完後舊頁改答；舊頁交卷的 3 個階段各中斷 1 次；第 3、5 步前後關頁。舊分頁一律用第 1 版寫入邏輯的測試替身模擬。
- 遷移的鎖（鎖用注入的測試替身）：A 持鎖時 B 不寫任何鍵；B 完成遷移並交卷後，較晚取得鎖的 A 不寫新鍵，題本仍是 `submitted`，同題作答只有 1 筆；沒有 `navigator.locks` 與等鎖逾時都不遷移、不抽題，舊鍵逐字不變。
- 多分頁合併：A 存科目 1 後，B 存科目 3，兩科答案、題本歷史、`current` 都保留。
- 遷移失敗 4 種：舊資料損壞、第 1 版 `seq` 寫入失敗、新鍵寫入失敗、讀回不符。舊鍵除草稿 `seq` 外都不變。
- 第 5.1 節排除規則 4 項各有會失敗與會通過的案例。
- 同題群組：同科同群組、跨代碼同群組、`F` 為 50 與 51 的邊界。實際題數等於 `min(50, F)`。
- 未交卷題改版、變爭議後恢復、移除後恢復，都不再抽到。
- 全部失效題本：不能交卷；按「結束這本」後不新增 `Attempt`；恢復後不自動抽題。
- 舊紀錄：舊 `daily:`、新 `booklet:`、清除後匯入、題目失效、同題多筆作答、`retired` 題本的鎖定作答。遷移案例：清單 q1 第 2 版、q2 第 1 版，同模式只有 q1 第 1 版的答對作答；題本只留 q2，舊紀錄是已答 1、答對 1。匯入案例：`open` 草稿的 q1 第 2 版已選 B、沒有 `legacyAttemptId`，再匯入同模式 q1 第 1 版的答對作答；交卷前舊紀錄是已答 1、答對 1，交卷後新作答成為最新 1 筆且被引用，舊紀錄不再列這組。預期數字由測試資料直接寫明，不呼叫同一函式算。
- 題庫不足、剛好 50、為 0。
- 驗證器拒絕跨科或他本的 `attemptMode`。
- 同題群組掃描測試。
- 21 本完整題本的資料量與單次保存時間（序列化加 `setItem`），結果寫進 plan 的實作紀錄。在 Chromium 連續保存 50 次。門檻：資料量不超過 1 MB 字元，保存時間第 95 百分位不超過 50 ms。超過才改成分開存放，並回報。

瀏覽器測試（Playwright，隔離環境，不碰使用者資料）：

- 全新環境：開頁不抽題，按鈕後才有第 1 本。
- 跨日：答 20 題，把日期改到隔天，同 50 題、答案保留。
- 舊流程：沒有草稿、舊清單是昨天，遷移後同 50 題，20 題鎖定。
- 開科目 1 不改變科目 3 的舊清單遷移結果。
- 連開 3 本：題目兩兩不重疊，第 1、2 本可回看。
- 交卷中斷後重試：作答不重複。
- 2 個分頁：一頁開下一本，另一頁改唯讀。
- 遷移的鎖：測試程式在第 1 頁持有真實的 `ipas-daily-migration` 鎖；第 2 頁開 `/daily/` 不寫新鍵；放鎖後第 2 頁完成遷移。再開第 3 頁，題本內容與 `seq` 不變。
- 清除資料後舊鍵不復活；備份往返實跑。
- 既有 `demo/scripts/daily-exam-smoke.mjs` 案例更新後全過；官方題、一般測驗、單題頁回歸。

## 11. 界線

- Always：先遷移再抽題；舊作答不重寫；讀寫只經過 `attempts.ts`；實測都用隔離瀏覽器。
- Ask first：備份改第 2 版；開放多本並行；補科目 3 題目；重新分配已合併的題目 ID。
- Never：讀取或修改使用者瀏覽器的資料；在使用者瀏覽器交卷；把做過的題補進新題本；把官方題放進題本；靜默清除無法解析的資料。

## 12. 可驗證的成功條件

1. 重新整理與跨日開頁，題本的題目、順序、答案都不變。
2. 開頁、重新整理、切科、遷移都不抽題；只有按「開第 1 本」或「開下一本」才抽題。
3. 交卷後當天可開下一本，已交卷題本仍可回看。
4. 連開到題庫用完，同一科任 2 本題目不重疊，也不含做過的題。遷移產生的未答題也不與其他題本重複，也不含已作答群組的題。唯一例外：舊草稿已選答案的題不刪，所以兩份草稿的同群組題都已選答案時會同時保留。
5. 同題群組的 4 對題目，做過其中 1 題後，另 1 題不再被抽到。
6. 第 6.3 節每一列都有測試，舊 `Attempt` 內容逐筆不變。
7. 遷移失敗時，舊鍵除草稿 `seq` 外內容不變，且不抽新題。讀完後舊頁改答或交卷、2 頁同時遷移（含一頁已交卷後另一頁才取得鎖）、中途關頁都不遺失作答，也不新增重複作答。沒有跨分頁鎖或等鎖逾時時不遷移。
8. 題本清單顯示第 N 本、狀態、題數、已答或答對題數。
9. 進度顯示這本已答、今日交卷、可再開本數，數字與資料算出的結果相同。
10. 官方題頁、一般測驗、單題頁行為不變。
11. CI 全綠；瀏覽器測試全過；截圖涵蓋 3 種寬度與亮暗色。
12. 4321 重建後，協調者用隔離瀏覽器走完開本、跨日、交卷、開下一本。使用者本人資料由使用者開頁確認。

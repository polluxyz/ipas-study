## 為什麼需要

要預測設備故障，先找運轉與維修資料；要預測顧客行為，先找互動與交易紀錄。來源選錯，即使下載很多資料，也可能沒有回答問題所需的線索。

資料來源與取得（Data Sources）不只問「去哪裡抓」，還要問欄位代表什麼、何時更新、誰允許使用。

## 直覺

先畫出「需求→欄位→來源」的對照。每個欄位都要能說清楚從哪個系統來，而不是先把所有表格合併，再猜它們有什麼用。

:::supplement[來源：W3C Data on the Web Best Practices，Metadata、Provenance與Data Access]
來源清單像每欄的履歷：保存業務鍵、單位、時間語意、負責單位與版本。這能幫助辨認兩欄看似同名，實際上卻來自不同定義的情況。
:::

## 定義與公式

### 內部資料

| 來源 | 常見內容 | 對應用途 |
|---|---|---|
| ERP企業資源規劃 | 銷售、庫存、採購、財務 | 庫存與生產需求 |
| CRM顧客關係管理 | 互動、服務、回饋 | 分群、行為預測 |
| 機台與設備系統 | 感測、操作、故障、維護 | 生產排程、良率、異常、保養 |
| POS、Web／App、IoT行為 | 交易、點擊、登入、停留 | 黏著度、功能改善 |
| 內部報表與流程 | 稽核、作業、法遵紀錄 | 風險與合規審查 |

### 外部資料

| 來源 | 取得方式 | 用途 | 必須核對 |
|---|---|---|---|
| 開放資料、開放API | 政府資料平台、氣象機構等提供下載或查詢 | 政策、市場、風險分析 | 欄位、更新與授權 |
| 網頁爬蟲（Web Scraping） | 解析價格、評論、新聞 | 競爭分析、輿情、文本探勘 | 網站條款與使用範圍 |
| 商業資料供應商 | 向Experian或Statista等平台購買、訂閱 | 金融投資、徵信、產業趨勢 | 交付品質與授權用途 |

:::supplement[來源：W3C Data on the Web Best Practices，Data Access與Data Licenses]
API是取得方式，不能單憑「有API」推斷資料免費、公開或允許所有用途。
:::

內部資料也須有適當存取與使用權限。

## 走一次流程

### 1. 將需求拆成欄位

以下是共用合成資料的來源安排；表內列的是本例會用到的欄位，而不是要求每個來源都一定提供相同格式。

| 領域 | 輸入來源與欄位 | 標籤來源與欄位 |
|---|---|---|
| 製造60筆 | 機台：設備、時間、溫度、振動；ERP：班別 | 維修流程：12小時內故障標籤 |
| 零售80筆 | POS：金額、時間；CRM：會員、互動次數、通路 | 行為紀錄：12小時內互動中斷標籤 |

### 2. 確認能正確取得與連接（補充）

先確認設備或會員鍵、事件時間、欄位單位與資料範圍，再取得必要欄位。關鍵欄位不齊，應回來源補查，不能只按表格列序拼接。

每列另保留來源、特徵可用時間及標籤確認時間。共用例子00:00的輸入不能拿12:00才知道的故障結果當特徵；時間限制從資料取得時就應記錄。

### 3. 檢查外部來源是否合用

假設模型每小時更新，供應商卻每24小時才提供新資料，契約還只允許報表展示。這份資料同時有時效與用途疑問，應另找來源或協商，不能因已付款就直接訓練。

:::supplement[來源：政府資料開放授權條款第1版；W3C Data on the Web Best Practices，Data Licenses]
開放資料也要逐份確認採用的授權與顯名要求。政府資料開放授權條款要求標示原提供機關的相關聲明；其他資料集的條件應查看其自身授權，不能套用同一結論。
:::

## 怎麼用、怎麼判讀

挑來源時，把業務相關性、欄位品質、更新頻率與授權一起比較。「拿得到」只是第一步，「能合法且及時地回答需求」才是採用理由。

### 換個場景

| 場景／資料條件 | 來源起點 | 檢核重點 |
|---|---|---|
| 智慧製造、預測保養 | 機台與維護紀錄 | 時間、操作條件、故障定義 |
| SaaS黏著度與產品改善 | 登入、點擊與使用路徑 | 行為事件的定義是否一致 |
| 市場、輿情、金融風險 | 開放API、爬蟲、商業資料 | 更新、網站條款與授權 |
| 醫療與金融流程稽核 | 內部報表、法遵紀錄 | 存取與使用範圍 |
| 交通尖峰預測（補充） | 車流與天氣資料 | 更新延遲與區域尺度 |
| 農業病害預警（補充） | 田間感測與觀測紀錄 | 測站與農地是否相符 |

## 常見誤解

- **內部資料就能任意使用。** 仍需確認權限、目的與適用規範。
- **能爬到就代表可以訓練。** 取得能力不等於使用授權。
- **下載頻繁就代表資料即時。** 應看來源更新時間，而非只看下載時間。

## 小結

- 用業務需求反推欄位，再挑內外部來源。
- 內部來源包含ERP、CRM、機台、行為與流程紀錄。
- 比較開放API、爬蟲與付費資料時，都要核對更新與授權。
- 記錄來源與時間語意，才能追查後續品質問題。（補充）

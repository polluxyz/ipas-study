## 為什麼需要

同一物件可能被不同角度、位置與光照拍到。只見過單一外觀的模型容易過度依賴訓練照片中的固定樣式，影像增強（Image Augmentation）讓它多看一些合理變化。

指引列出翻轉、旋轉、裁切、縮放、模糊與色彩變換，並提醒不當變換會改變語意或標註。方法名稱相同，放在不同任務裡可能得到相反的效果。

## 直覺

同一張影像可以產生不同版本。目的在增加訓練樣本的變化，降低過擬合，不要求每一個版本都比原圖漂亮。

### 同一原圖，不同變化

本組M01是方向無關的刮痕任務。下圖每張都由同一原圖產生，不是重新採集的獨立產品。

![比較M01的翻轉、旋轉、裁切、模糊與變暗，注意細小瑕疵可能被削弱。](figure:l23301-image-augmentation-variants)

## 定義與公式

### 增強與畫質修復

指引的「像素增強」列有直方圖均衡化、Gamma校正，用來改善單張低光源或品質不佳影像的對比與亮度。這類畫質處理著重讓原有內容更清楚。

指引另稱「資料擴增」的方法，則製造訓練變體以增加多樣性、降低過擬合。中文都可能叫「增強」，讀題時要先看目的：修好同一張圖，還是讓模型見到更多合理變化。

### 五種方法改變了什麼

| 方法 | 改變項目 | 先查的任務限制（補充） |
|---|---|---|
| 翻轉 | 左右或上下方向 | 字形、左右側與方向標籤 |
| 旋轉 | 拍攝角度 | 角度是否會改變類別 |
| 裁切與縮放 | 視野及物件占比 | 物件是否被切斷或消失 |
| 模糊 | 邊緣與細節 | 小刮痕或文字是否還可辨認 |
| 色彩擾動 | 亮度、對比或色彩 | 顏色是否本身就是標籤 |

### 幾何變換必須同步標註

指引提醒不當變換會改變語意或標註。除了看外觀有沒有變化，還要確認訓練時的答案仍對得上影像。

:::supplement[來源：Torchvision偵測參考實作；Torchvision transforms v2教學]

寬度為$W$的水平翻轉，對右下邊界不含的框使用：

$$
[x_1,y_1,x_2,y_2]\longmapsto[W-x_2,y_1,W-x_1,y_2]
$$

$x_1,y_1$是左上邊界，$x_2,y_2$是右下邊界。這是邊界座標；單一像素索引的翻轉則是$W-1-x$，兩者不可混用。

遮罩跟影像使用同一次幾何變換。分類標籤是否不變仍要由任務判斷：刮痕有無可以不變，箭頭方向必須改，鏡像F則未必有合法的原字類別。
:::

![框與遮罩一起翻轉仍不代表分類標籤必然正確，F鏡像與箭頭方向都要另判斷。](figure:l23301-image-augmentation-labels)

## 算一次

### 一張M01要過三道檢查（補充）

1. **算幾何：** M01寬8，框`[1,2,3,6]`翻轉成`[8−3,2,8−1,6]`，也就是`[5,2,7,6]`；遮罩8格跟著移到右側。
2. **看語意：** 本任務只判斷有無刮痕，方向無關，所以刮痕類別可保留。若任務改成刮痕方向分類，就必須重新檢查標籤。
3. **查部署：** 若相機會出現亮度小幅變化，可試亮度乘0.8；紅色255變204，背景32四捨五入變26。過暗到看不見刮痕就不再是有效樣本。

再換成R01的F字。左右翻轉會產生鏡像字，不能照填F；R09右箭頭翻轉後是左箭頭，只有任務容許左箭頭且同步改標籤時才可能收錄。

若對M01只保留橫向4到8的右半邊，瑕疵遮罩剩0格。此時不能沿用「有瑕疵」標籤；可以拒絕這次裁切，或依事先定好的任務規則重新標註。

## 程式

### 一次決定是否翻轉，影像與遮罩共用結果（補充）

以下用NumPy展示與隨機水平翻轉相同的判斷邏輯。種子固定為23301；正式資料每次抽到的同一個決定，也必須套用到框與遮罩。

```python
import numpy as np
rng = np.random.default_rng(23301)
mask = np.zeros((8, 8), dtype=np.uint8)
mask[2:6, 1:3] = 1
pixels = np.full((8, 8, 3), 32, dtype=np.uint8)
pixels[mask == 1] = [255, 0, 0]
pixels[:2, :2] = np.array([0, 85, 170, 255])[:, None].repeat(3, 1).reshape(2, 2, 3)
do_flip = rng.random() < 0.5
image2 = np.flip(pixels, axis=1) if do_flip else pixels.copy()
mask2 = np.flip(mask, axis=1) if do_flip else mask.copy()
ys, xs = np.where(mask2 == 1)
print(bool(do_flip), [int(xs.min()), int(ys.min()), int(xs.max()+1), int(ys.max()+1)])
print(int(mask2.sum()), bool(np.all(image2[mask2 == 1] == [255, 0, 0])))
```
```text
True [5, 2, 7, 6]
8 True
```

:::tip[讀碼重點]
不要分別為影像與遮罩抽兩次亂數。`axis=1`是寬度方向；若誤翻通道軸，得到的是顏色改變，不是幾何翻轉。
:::

## 怎麼用、怎麼判讀

指引列出人臉辨識與醫學影像分析作為影像增強場景。也指出資料量不足時可藉此增加多樣性，但須依應用選擇方法，且更多變體會增加處理成本。

:::supplement[來源：Torchvision transforms v2教學、ColorJitter；TensorFlow資料增強教學]
`RandomHorizontalFlip(p=0.5)`每次有一半機率翻轉，仍要保住標籤。`ColorJitter`擾動亮度、對比、飽和度與色相；範圍由任務限制決定，不能只看預設值。

訓練採用允許的隨機增強，再做固定輸入轉換；驗證與測試使用對應部署的固定尺寸與像素轉換，不隨機增強。以相同驗證集比較是否改善，不能把「變體更多」當成成效保證。
:::

### 換個場景

| 場景 | 指引用途或條件 | 具體限制（補充） |
|---|---|---|
| 人臉辨識 | 影像辨識模型訓練 | 不可裁掉身分辨識所需的臉部 |
| 醫學影像分析 | 影像辨識模型訓練 | 左右側、病灶大小與顏色可能有意義 |
| 樣本少、環境多變 | 增加訓練多樣性 | 變體不能代表尚未收集的新病灶 |
| 製造瑕疵（補充） | 模擬拍攝外觀變化 | 模糊不能抹掉細刮痕 |
| 零售OCR（補充） | 模擬輕微角度與光照 | 鏡像字不能沿用原字標籤 |

## 常見誤解

- **變換後一律保留標籤。** 指引已提醒語意與標註可能改變；要依任務判定。
- **產生變體等於收集新資料。** 同一來源不能補上未曾觀察的新族群或新缺陷。（補充）
- **偵測框同步就萬無一失。** 裁切若移除物件，還需刪除、重標或拒絕樣本。（補充）
- **驗證一起隨機增強才公平。** 主驗證應固定；其他擾動可另外做壓力測試。（補充）

## 進階

### 強度也要驗證（補充）

可先比較停用增強、只用一種低強度增強、再加其他操作的結果。固定來源切分，記錄種子與參數，才能判斷差異來自何處；本組小影像只驗算變換，不證明模型準確率會提高。

## 小結

- 增強增加合理外觀變化，目的包含提升泛化與減少過擬合。
- 幾何改變時框與遮罩要同步，語意還要另過一關。（補充）
- OCR、方向與色別任務尤其需要查標籤是否改變。（補充）
- 訓練隨機、主評估固定，效果用相同驗證條件確認。（補充）

## 為什麼需要

同時使用影像、文字與感測器，不表示所有輸出都能用一個正確率驗收。辨識病灶、生成摘要與回覆語音，需要的證據不同。

指引依醫療、零售、虛實互動分列應用與指標。設計時先寫交付什麼，再問錯在哪裡、如何量，才能避免只選容易得到好分數的指標。

## 直覺

把需求拆成「來源 → 任務 → 錯誤代價 → 指標 → 驗收條件」。同一組來源可以支援多個任務，每個任務都要有自己的真值或參考。

![先固定任務與錯誤，再選相應的指標，最後連同隱私、同步與期限一起驗收。](figure:l21104-multimodal-application-evaluation-map)

圖中的驗收卡是補充的流程整理；醫療、零售與互動的任務／指標配對來自指引，不應被單一總分取代。

## 定義與公式

本頁不重推既有公式：準確率看全體分類，精確率看預測正類的命中，F1 分數綜合精確率與召回率。假陽性率則看實際負類中被誤報的比例，定義見 ROC 曲線與 AUC。

IoU 比較兩個區域的重疊，ROUGE 摘要評估比較文字片段；語音品質、WER 與延遲則分開解釋轉寫及等待時間。先確認比較物件，不因資料同屬多模態就混用。

### 醫療：診斷與生成是不同任務

| 任務例 | 來源與輸出 | 指引相關指標 |
|---|---|---|
| 病灶與報告 | CT／MRI、病歷 → 病灶判別及診斷摘要 | 診斷看準確率（Accuracy），摘要看 ROUGE |
| 慢性病管理 | 血糖等生理訊號、病歷 → 風險分類 | 準確率、假陽性率（FPR） |
| ICU 監控 | 連續心率等生命徵象、醫師筆記 → 異常警示 | 假陽性率與分類品質 |

資料隱私、不同檢查時間的同步、判斷的解釋性，也要列入設計。指引提到 HIPAA 等規範；實際適用要求需依機構與資料使用情境確認，本頁不作法律判定。

:::supplement[來源：scikit-learn 模型評估文件；多模態學習綜述 §IV-C]
ROUGE 高只表示參考文字重疊較多，不能證明病灶、數字與建議均正確。報告要另外查事實一致性；ICU 警示還須看漏報與警報負擔，不能只追求低假陽性率。
:::

### 零售：讓每個輸出有對應物件

| 任務例 | 多源資料與輸出 | 指引相關指標 |
|---|---|---|
| 動線與停留區域 | 影像、銷售 → 熱區與店面配置分析 | IoU 對照區域重疊 |
| 情境推薦 | 交易、評論 → 推薦商品 | 精確率（Precision）看推薦命中 |
| 情感分析 | 評論、社群 → 正負情感分類 | F1 分數 |
| 營運儀表板 | 影像、POS、評論 → 業務整合畫面 | 對各分析任務分別驗收 |

顧客隱私、多來源噪聲與即時處理是指引列出的挑戰。儀表板顯示很多圖，不等於已證明底層推薦與分類正確。

:::supplement[來源：scikit-learn 模型評估文件；CMU 多模態教學 Quantification]
IoU 須先把動線需求定成可比較的區域或分割；完整路徑追蹤不能只靠重疊值評完。

推薦也要定義相關商品及清單長度，情感評估則先約定類別與平均方式。
:::

### 互動：姿態、轉寫、速度分開量

| 場景例 | 交付內容 | 指引相關指標 |
|---|---|---|
| 虛擬人偶、展覽導覽 | 依語音與手勢調整展示 | 姿態準確率、WER、回應延遲（Latency） |
| 智慧螢幕助理 | 語音加手勢控制介面 | 姿態準確率、回應延遲 |
| 智慧教室 | 辨識手勢與語音互動 | 姿態準確率、WER、延遲 |
| 遠距協作與會議 | 即時手勢、語音轉文字 | 姿態準確率、WER、延遲 |

除了各模態分數，還要檢查語音與手勢是否指向同一操作、是否有足夠運算資源。畫面與聲音各自正確，若不同步仍可能讓人感到反應錯誤。

## 走一次流程

### 用工廠與交通資料練習設計（補充）

共用資料是 `L21104-B-events.json`，每領域 24 事件：前 12 訓練、中 4 驗證、後 8 測試。各模態沿用同一事件 ID、真值、切分與種子 42，避免比較時偷換樣本。

1. 定義正類為「需複核」：工廠看設備異常，交通看路口壅塞。分支分數都是人工設定的教學值，非訓練成績。
2. 固定 0.5 閾值與缺失回退規則。只有核可的四種遮罩可自動處理，可用分支分數取等權平均；000 交人工。
3. 每領域 8 筆測試有 7 筆自動處理。兩領域各為 TP=4、FP=1、TN=2、FN=0，自動部分準確率為 6/7≈85.71%。
4. 自動覆蓋為 7/8=87.5%；不是 8 筆都自動正確。自動部分的假陽性率為 1/3≈33.33%，精確率為 4/5=80%。
5. 檢查分模態有效筆數，另在完整來源的 F17、F18 或 T17、T18 作相同樣本比較；兩筆只能示範分母，不能推論模型優劣。

### 先看分母，再談融合（補充）

下表按各來源實際可用資料計分；它們的分母不同，只能用來盤點，不是公平的優劣排行。

| 路徑 | 工廠：正確／有效 | 交通：正確／有效 |
|---|---|---|
| 影像 | 4/6 | 4/6 |
| 文字 | 4/5 | 4/5 |
| 感測 | 5/5 | 4/5 |
| 融合自動路徑 | 6/7 | 6/7 |

完整來源子集只有各 2 筆。工廠的影像、文字、感測、融合依序為 1/2、2/2、2/2、2/2；交通則為 2/2、2/2、1/2、2/2，與上表的分母不能混用。

### 語音與期限另驗（補充）

每領域的 8 段測試各有 5 個參考詞、共 2 次替換，沒有刪除或插入；因此每領域彙總 WER 為 2/40=5%，兩領域合併則為 4/80=5%。

這裡的文字分支是巡檢註記，ASR 轉寫則是另外的查詢語音參考，兩者不可混認。

本例語音結束至首段可播放回覆為 350～420 ms。F17 是 26350−26000=350 ms，與前置語音品質頁的「送出 TTS 請求至首段」起點不同，不能直接比較。

若另有姿態分類，就要另存姿態真值與預測；不能拿這份「需複核」標籤當成姿態準確率。報告生成也需另外的參考摘要與事實標註，不以本表分類分數代替。

## 程式（補充）

逐模態只評可用事件；融合只評核可組合，同時保留全部測試數作服務覆蓋的分母。

執行前將環境變數 `IPAS_REPO_ROOT` 設為教材專案的絕對路徑，讓程式能找到共用資料。

```python
import json, os
from pathlib import Path
root = Path(os.environ["IPAS_REPO_ROOT"])
d = json.loads((root / "content/examples/L21104-B-events.json").read_text(encoding="utf-8"))
for domain in d["domains"]:
    rows = [r for r in domain["events"] if r["split"] == "test"]
    for mode in ["image", "text", "sensor", "fusion"]:
        pairs = []
        for r in rows:
            valid = r["present_mask"] in d["approved_auto_masks"] if mode == "fusion" else r["branch_scores"][mode] is not None
            if not valid: continue
            s = [v for v in r["branch_scores"].values() if v is not None] if mode == "fusion" else [r["branch_scores"][mode]]
            pairs.append(((sum(s)/len(s)) >= d["threshold"]) == r["truth"])
        print(domain["id"], mode, f"正確={sum(pairs)}/{len(pairs)}", f"涵蓋={len(pairs)}/{len(rows)}")
```
```text
factory image 正確=4/6 涵蓋=6/8
factory text 正確=4/5 涵蓋=5/8
factory sensor 正確=5/5 涵蓋=5/8
factory fusion 正確=6/7 涵蓋=7/8
traffic image 正確=4/6 涵蓋=6/8
traffic text 正確=4/5 涵蓋=5/8
traffic sensor 正確=4/5 涵蓋=5/8
traffic fusion 正確=6/7 涵蓋=7/8
```

:::tip[讀碼重點]
所有分支都先固定同一測試集合，再依可用性記錄分母。這段只列各自有效的筆數；正式比較仍須增加同樣本的共同子集評分。
:::

## 怎麼用、怎麼判讀

醫療要看隱私、同步與解釋；零售要看顧客隱私、噪聲與即時性；互動還要看延遲、跨模態一致性和資源。品質指標通過，不能自動免除這些條件。

:::supplement[來源：scikit-learn 模型評估文件；Hugging Face ASR 評估課程]
驗收卡先約定正類、資料切分、指標平均方式與期限起訖；依缺失、噪聲及環境分組檢查。零分母要回報未定義，沒有預測正類時不能把精確率當成滿分。

延遲另報高分位與超時率，不能只看平均。本例 16 筆測試只有示範規模，不適合拿來承諾部署服務品質。
:::

### 換個場景

| 場景 | 指引交付 | 指標不能取代的檢查 |
|---|---|---|
| 醫療 | 報告、慢性病與 ICU 監控 | 病患配對、資料隱私、解釋 |
| 零售 | 動線、推薦、情感與 BI | 噪聲、顧客隱私、處理時效 |
| 虛實互動 | Avatar、教室、展覽與會議 | 語音／手勢一致與資源 |
| 工廠巡檢（補充） | 異常複核及查詢 | 設備編號、缺失回退、錯報成本 |
| 城市交通（補充） | 壅塞複核及語音查詢 | 路口時點、來源故障與期限 |

## 常見誤解

- 融合後只要一個準確率：生成、區域與互動各有不同交付。
- ROUGE 高就代表報告事實正確：文字重疊不是事實查核。（補充）
- 用不同樣本的分模態分數排行：先固定比較樣本與分母。（補充）
- 把百分比與毫秒平均就是總品質：須先有可解釋且事前約定的效用定義。（補充）

## 小結

- 先指定交付、真值與錯誤代價，再選指標。
- 醫療、零售與互動的任務各有對應評估。
- 分模態評分要並列有效樣本與服務覆蓋。（補充）
- 缺失、同步、隱私與期限都須進驗收條件。

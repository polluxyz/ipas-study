## 為什麼需要

一張異常影像若配到正常設備的紀錄，模型收到的教學訊號就矛盾。多模態資料對齊要處理時間與語意一致性，標註與資料管理則讓關係可追查。

指引還指出，影像加文字等多重標註耗費專業人力。資料量增加後，儲存、維護與品質管理都會成為成本。

## 直覺

時間對齊問「何時發生」，語意對齊問「是不是在描述同一內容」。資料版本則回答「當時用哪一批輸入、哪一版標籤」。

:::supplement[來源：nuScenes devkit 教學；DVC 資料版本文件]

| 錯配 | 教學例 | 要保留的線索 |
|---|---|---|
| 時間 | F01 感測時鐘快 50 ms | 原始時間、偏移與校正版本 |
| 語意 | F01 照片配到 F02 的文字 | 事件 ID、來源 ID、配對依據 |
| 標註版本 | 同一 F01 被改標正常卻無歷程 | 資料版、標註版與修改理由 |

三者可能同時發生。只把時間戳改成一樣，不會修正錯設備或被覆蓋的標籤。
:::

## 定義與公式

指引列出動態時間校正（Dynamic Time Warping，DTW）、跨模態語意對齊、弱監督與資料版本控制。這些手段處理不同層次，不能互相替代。

### 依問題選管理手段

| 問題 | 指引提出的方向 |
|---|---|
| 時序進度不一致 | DTW |
| 圖文語意不相符 | CLIP 對比學習 |
| 標註人力不足 | 弱監督、自動標註 |
| 標註原型需求 | 生成模型產生標註原型 |
| 資料量與版本複雜 | 分散式儲存、版本控制 |

:::supplement[來源：Snorkel 官方標註教學；DVC 資料管理入門]
查核時分別看序列對應、圖文正配對、標註錯誤與版本快照。弱監督規則會有噪聲，應抽查錯標及未覆蓋的類別；生成原型也不能直接成為真實樣本的標準答案。

例如用維修關鍵詞或感測門檻先提議標籤，未命中可保留未標註。不同規則也可能互相衝突，要抽查其覆蓋與錯誤，再決定如何整合。
:::

### DTW 的局部與累積成本（補充）

DTW 允許兩段序列以不同速度前進，但仍保留先後次序。本頁採絕對差作局部成本；這是 FMP 課程一般局部成本框架的一個選擇。

$$
c(i,j)=|x_i-y_j|,\qquad
D(i,j)=c(i,j)+\min\{D(i-1,j),D(i,j-1),D(i-1,j-1)\}
$$

$X=(x_1,\ldots,x_n)$、$Y=(y_1,\ldots,y_m)$ 是同單位的特徵序列；$i,j$ 是從 1 起算的索引。$c$ 是單次配對差，$D$ 是走到該格的最小累積成本。

邊界設 $D(0,0)=0$，其餘第零列及第零欄為無限大。由 $(1,1)$ 走到 $(n,m)$，每次只能增加一個或兩個索引各 1，不能回頭或跨格。

本頁距離取 $D(n,m)$，不開根號、不除路徑長。tslearn 預設的平方差總和再開根號是另一種成本定義，不能把不同版本數字直接相比。

## 算一次

### 距離表與路徑（補充）

共用例子的 F-S1 與 T-S1 都是 $X=[1,2,3]$、$Y=[1,1,2,3]$。數字代表已轉成相同單位的進度特徵，不是直接拿振動和車流相減。

先列局部成本。表的列是 Y、欄是 X，每格填兩值的絕對差：

| Y 值 | X₁=1 | X₂=2 | X₃=3 |
|---|---|---|---|
| Y₁=1 | 0 | 1 | 2 |
| Y₂=1 | 0 | 1 | 2 |
| Y₃=2 | 1 | 0 | 1 |
| Y₄=3 | 2 | 1 | 0 |

累積表每格都加上合法前一格的最小值：

| Y 索引 | D(1,j) | D(2,j) | D(3,j) |
|---|---|---|---|
| 1 | 0 | 1 | 3 |
| 2 | 0 | 1 | 3 |
| 3 | 1 | 0 | 1 |
| 4 | 3 | 1 | 0 |

例如 $D(2,3)=|2-2|+\min\{1,1,0\}=0$。終點 $D(3,4)=0$，路徑 $(1,1)\to(1,2)\to(2,3)\to(3,4)$ 的四對值皆相等。

![沿標記格保持前進；X 的第一個值對應 Y 的前兩值，表示局部速度不同。](figure:l21104-multimodal-data-alignment-dtw)

成本為 0 只表示這組特徵可完全對應，不代表兩個原始事件必然是同一個。先確認事件身分，才允許演算法調整相對進度。

### 保留標註與版本（補充）

同一份資料管理流程可以接在對齊之後：

1. 建立 F01 的事件清單，固定影像、文字、感測來源 ID；原始時間不覆寫，另外保存偏移及校正版本。
2. 弱監督先提議標籤；從訓練／驗證資料抽查正常、異常與規則衝突者，分開記錄覆蓋率和錯標。
3. 生成影像只作標註原型或流程草稿；專家另對真實資料核定標籤，測試集保留人工真值。
4. 凍結資料 data-v1、標註 label-v1、校正 cal-v1 及切分清單。修標後另立版本，保留原因與來源對應。

| 快照 | 資料／標註 | 校正／切分 | 可回溯內容 |
|---|---|---|---|
| 本例原版 | data-v1／label-v1 | cal-v1／固定 ID | 原始配對及偏移 |
| 修訂示意（未生成） | data-v1／label-v2 | cal-v1／相同 ID | 被改樣本及理由 |

分散式儲存解決容量與存取，版本紀錄解決重現。只把檔案分到多台機器，不會自動保留標籤歷史。

## 程式（補充）

先從共用 JSON 讀 F-S1，算成本並保存前一格。本頁兩段程式依序執行，同分時優先對角、再上、再左，讓路徑可重現。

執行前將環境變數 `IPAS_REPO_ROOT` 設為教材專案的絕對路徑，讓程式能找到共用資料。

```python
import json, os
from pathlib import Path
root = Path(os.environ["IPAS_REPO_ROOT"])
data = json.loads((root / "content/examples/L21104-B-events.json").read_text(encoding="utf-8"))
pair = data["domains"][0]["sequence_pairs"][0]
x, y = pair["x"], pair["y"]
d = [[float("inf")] * (len(y)+1) for _ in range(len(x)+1)]
d[0][0], prev = 0, {}
for i, a in enumerate(x, 1):
    for j, b in enumerate(y, 1):
        q = min([(i-1,j-1), (i-1,j), (i,j-1)], key=lambda p: d[p[0]][p[1]])
        d[i][j], prev[i,j] = abs(a-b) + d[q[0]][q[1]], q
print("DTW 成本:", d[-1][-1])
print("累積表（列為 Y）:", [[d[i][j] for i in range(1,len(x)+1)] for j in range(1,len(y)+1)])
```
```text
DTW 成本: 0
累積表（列為 Y）: [[0, 1, 3], [0, 1, 3], [1, 0, 1], [3, 1, 0]]
```

```python
p, path = (len(x), len(y)), []
while p != (0, 0):
    path.append(p)
    p = prev[p]
print("1 起算路徑:", path[::-1])
```
```text
1 起算路徑: [(1, 1), (1, 2), (2, 3), (3, 4)]
```

:::tip[讀碼重點]
第一段計算所有格子的成本；第二段從終點往回追。回溯後反轉清單，才是依時間前進的配對。
:::

## 怎麼用、怎麼判讀

DTW 處理序列進度，對比學習處理語意關聯，版本控制保存資料與標註歷史。先辨認問題，再決定工具，避免用時間拉伸掩蓋錯設備的配對。

### 換個場景

| 場景 | 指引的資料條件 | 方法與查核 |
|---|---|---|
| 監控影像、語音指令 | 時點或語意不一致 | 分別查時間與指涉內容 |
| 圖片物件及描述標註 | 需專業人力、優質標註稀缺 | 輔助標註、版本及抽查 |
| 工廠動作（補充） | 同流程執行速度不同 | 對可比較特徵做 DTW |
| 交通事件（補充） | 不同路口或車輛身分混雜 | 先核對 ID，再調整進度 |

:::supplement[來源：FMP DTW 課程；Snorkel 官方標註教學]
DTW 不適合任意拉伸沒有對應關係的序列，必要時限制允許路徑的時間範圍。弱監督的抽查與規則調整只用開發資料，最後測試集不拿來反覆修規則。
:::

## 常見誤解

- 同時間就是同語意：仍可能是不同設備或錯誤描述。
- DTW 會理解影像與文字：本頁算法只比較指定特徵的序列距離。（補充）
- 生成原型可直接作真值：真實資料仍需核定與抽查。（補充）
- 檔名加日期就足以重現：還須保留模態配對、標註、校正與切分版本。（補充）

## 小結

- 時間、語意與標註版本，是三種不同的對應問題。
- DTW、語意對齊、輔助標註與版本控制各有分工。
- DTW 路徑可局部重複配對，但不能倒退或跳格。（補充）
- 自動提議的標註仍需抽查，修訂後保存版本。（補充）

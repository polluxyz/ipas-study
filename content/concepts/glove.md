## 為什麼需要

Word2Vec 從局部上下文建立預測任務。GloVe（Global Vectors for Word Representation）則先累積全語料的共現統計，再學習靜態詞向量。

例如，兩個詞未必經常直接相鄰，但若各自常出現在相似詞的附近，統計仍可提供它們用法相關的線索。

## 直覺

把詞排成橫列與直欄，每格記一種中心詞與周邊詞的共現量。先把全語料的事件加總，得到全域統計，再由模型壓成適合使用的向量。

![先看「訂」與「改」共有的上下文欄，再沿箭頭區分共現統計與學習後的稠密向量；下方只示意流程。](figure:l21101-glove-cooccurrence)

這是 24 句語料的六詞子矩陣。圖上的數字來自固定視窗計數，未執行 GloVe 訓練；輸出的詞向量並不直接等於這六個計數。

## 定義與公式

「全域」指整個語料的統計被累積起來，不表示每對詞都必須跨全文直接配對。本組仍用局部視窗定義一次共現，再把所有文件的事件相加。

指引把 GloVe 歸在矩陣分解路線：從共現統計學出較低維的詞向量。這裡的分解仍要看模型指定的目標，不能只見到矩陣就當作同一種演算法。

:::supplement[來源：Pennington 等人 GloVe 原論文第 3 節]
更精確地說，GloVe 對對數共現資訊做加權矩陣分解，以回歸目標學習詞與上下文的向量及偏差。這不能直接等同於對原始次數做一般 SVD。

共現表可以很大且稀疏，輸出則通常是較低維的稠密詞向量。輸出各維不再逐欄對應某個周邊詞。
:::

## 算一次

先確定語料與視窗，再累積共現統計；接著才是 GloVe 的學習階段。不要把計數程式輸出當成已訓練好的嵌入。

### 展開本組的共現計數（補充）

1. 沿用完整斷詞，半徑固定為 2，左右都計入且不跨句；每個中心到周邊算一個有向事件。
2. T02 的「訂」附近有「不、要、明天、的」。「訂」與「明天」距離 1，貢獻 1 次；T01 再貢獻 1 次，全語料合計 2 次。
3. T04 的「改」與「明天」距離 1，貢獻 1 次。因此「訂」與「改」在明天、要、的等欄都有訊號，但次數不完全一樣。
4. 累積完整語料後，再顯示「訂、改、要、明天、的、票」六詞的行列；不能先刪掉其他詞再取視窗。

這套左右等權規則使矩陣對稱；原始位置距離仍依完整句子計算。正式 GloVe 的視窗與距離權重可另有設定，不能把此表當成所有實作唯一的計數結果。

### 和 Word2Vec 對照

| 方法 | 送入學習的訊號 | 使用時的結果 |
|---|---|---|
| Word2Vec | 每個局部上下文構成的預測樣本 | 每詞固定向量 |
| GloVe | 跨全語料累積的共現統計 | 每詞固定向量 |

兩者都能接觸大量語料，也都與局部共現有關。核心差別在統計如何組織成學習訊號，不是「一個看過全語料、另一個完全沒看過」。

## 程式（補充）

只重建共現子矩陣，不訓練 GloVe。從 repo 根目錄執行；實測器以 `IPAS_REPO_ROOT` 指向 repo，結果完全確定。

```python
import json, os
from pathlib import Path
root = Path(os.environ.get("IPAS_REPO_ROOT", "."))
data = json.loads((root / "content/examples/L21101-B-vectors.json").read_text(encoding="utf-8"))
vocab = data["cooccurrence"]["vocabulary"]
index = {w: i for i, w in enumerate(vocab)}
X = [[0] * len(vocab) for _ in vocab]
for doc in data["documents"]:
    s = doc["tokens"]
    for i, a in enumerate(s):
        for j in range(max(0, i-2), min(len(s), i+3)):
            if i != j and a in index and s[j] in index:
                X[index[a]][index[s[j]]] += 1
print(vocab)
for row in X: print(row)
```
```text
['訂', '改', '要', '明天', '的', '票']
[0, 0, 2, 2, 1, 0]
[0, 0, 1, 1, 1, 0]
[2, 1, 0, 3, 0, 0]
[2, 1, 3, 0, 2, 2]
[1, 1, 0, 2, 0, 4]
[0, 0, 0, 2, 4, 0]
```

:::tip[讀碼重點]
先在完整 s 上找位置 j，才判斷是否屬於顯示詞表。若先過濾 s，原本超過視窗的詞可能被移近，計數就會改變。
:::

## 怎麼用、怎麼判讀

指引以國王、女王和皇室相關詞的共現，說明相似上下文如何提供詞間關係。它也把 GloVe 放在靜態嵌入路線：同一詞在不同語境仍取固定向量。

### 換個場景

| 場景 | 使用方式 | 判讀重點 |
|---|---|---|
| 大規模語料的詞關係 | 累積共現後學習詞向量 | 指引以皇室相關詞為例 |
| 多義詞、低頻詞 | 檢查固定表示是否足夠 | 全域統計仍不能保證當次詞義 |
| 製造維修搜尋（補充） | 從設備紀錄學零件相關詞 | 常共現的故障與正常狀態不一定同義 |
| 圖書資料整理（補充） | 依作者、主題周邊用詞找相關詞 | 冷門書名的統計可能不足 |

## 常見誤解

- 「全域就是不需要視窗」：可由局部視窗定義事件，再在全語料累積。
- 「共現為零就是兩詞毫無關係」：它只代表此語料、此視窗沒有該事件，其他上下文仍可提供線索。（補充）
- 「GloVe 輸出就是原共現表的一列」：學習後的低維座標不是原始計數。（補充）

## 進階

### 指引表述校正

指引 3-21 的句子先寫依賴局部上下文，後面又用「而是」接全語料統計，語意不連貫；3-20 也容易讓人把輸出向量和共現表的稀疏性混淆。

:::supplement[來源：Pennington 等人 GloVe 原論文摘要、第 3 節]
原論文結合全域矩陣分解與局部視窗的優點。本頁把「事件定義」、「全域累積」、「學成稠密表示」分成三步，避免誤讀為互斥，也避免把輸入表當成輸出表。
:::

## 小結

- GloVe 累積全域共現統計，再學習詞向量。
- Word2Vec 以局部預測樣本組織訊號；兩者都能使用整批語料。
- 共現矩陣與嵌入表是不同物件，輸出通常為稠密低維表示。（補充）
- 視窗、邊界與距離權重必須明訂，計數才可重現。（補充）

## 為什麼需要

模型會把訓練標記當作要學的標準答案。若有人只框可見部分，有人猜完整身體，同樣的影像就會得到互相矛盾的目標。

影像標註（Image Annotation）不只是在工具裡畫圖。先定義類別、座標與疑難案例的處理方式，才能讓不同標註者產出一致、可覆核的資料。

## 直覺

整圖分類像在每張圖旁放一張類別卡；物件偵測則要替每個物件記類別與位置。T01 有兩名行人，分類只記一次「有行人」，偵測要記兩個框。

![先確認左上原點、x 向右、y 向下，再讀兩個框；右下座標是邊界，不是寬高。](figure:l21102-image-annotation-boxes)

## 定義與公式

### 類別要能讓人一致判斷

本頁採單一類別的整圖分類，每張圖只能選一個類別。以是否存在行人為準，至少一名可確認行人就標「有行人」，沒有則標「無行人」。

| 影像 | 觀察 | 整圖類別 |
|---|---|---|
| T01 | 有兩名可確認的行人 | 有行人 |
| T02 | 只有背景與道路 | 無行人 |

:::supplement[來源：CVAT Academy Quality Control in Data Annotation；必要前置：避免把不確定誤標成負類]
模糊到不能判定時，進入「待覆核」工作狀態，不硬塞進「無行人」。工作狀態是品質欄位，不是二分類模型的第三個輸出類別。

製造圖另定義「有刮痕／無刮痕」：M01 有一處白色刮痕示意，M02 沒有。行人類別與刮痕類別屬於兩個任務，不混成同一套互斥標籤。
:::

### 框的座標約定（補充）

本例原點在左上圖邊，x 向右、y 向下，單位為像素。邊界框（Bounding Box）存成 `[x_min,y_min,x_max,y_max]`，右下界不含，且必須有正的寬高。

對寬 W、高 H 的影像，檢查 `0 ≤ x_min < x_max ≤ W`、`0 ≤ y_min < y_max ≤ H`。這是本例固定規則，轉出給別的工具時要再查其格式。

轉成 COCO 使用的左上位置與寬高時：

$$
\begin{aligned}
x&=x_{\min}, & y&=y_{\min} \\
w&=x_{\max}-x_{\min}, & h&=y_{\max}-y_{\min}
\end{aligned}
$$

這裡 x、y 是左上位置，w、h 是框的寬、高；min、max 是兩端邊界。公式適用於已確認端點約定一致的框，不適用於把右下端當成包含在內的像素索引。

代入 T01 第二框 `[5,1,7,4]`：x=5、y=1、w=7−5=2、h=4−1=3，所以輸出 `[5,1,2,3]`。不是把右下座標原封不動複製。

## 走一次流程

### 先訂規範，再標兩框

同一張 T01 的標記存於 `L21102-A-vision.json`。類別與位置綁在同一筆物件記錄裡；個體 ID 在這裡只是方便逐筆核對。

| 個體 | 類別 | 框（xyxy） | 遮擋 |
|---|---|---|---|
| 1 | 行人 | [1,1,3,4] | 右腕不可見 |
| 2 | 行人 | [5,1,7,4] | 無 |

指引要求統一規範、精確邊界與定期品質檢查。下表把要求具體化為本例的工作規則；細節是示範方案，可因資料目的調整。

| 情況 | 本例規則 | 要記的資訊 |
|---|---|---|
| 遮擋（補充） | 框可見外緣，不推測完整身體 | 遮擋狀態；難例送覆核 |
| 邊界 | 貼緊可見物件 | 座標與邊界覆核結果 |
| 模糊（補充） | 類別無法確認時隔離 | 待覆核原因，不視為負類 |
| 多物件 | 每個可確認個體各一筆 | 不因同類而合框 |

:::supplement[來源：CVAT Academy Quality Control in Data Annotation；必要前置：區分框的範圍與點位的可見性]
框可採可見範圍或推估完整範圍，但全批必須一致。本例選可見範圍；關鍵點與姿態標註的遮擋點位則另有可見性規則，不能互相代用。

若物件碰到圖邊，本例將框截在圖邊，另記截斷狀態。這是本例採用的細則，使用別批資料時須重新確認。
:::

### 雙人標註與裁決

兩位標註者獨立標同批影像，再比對類別、漏標與邊界。指引舉每完成 10 張就檢查一次為例；實際頻率要按風險與資料量訂定。

:::supplement[來源：CVAT Manual QA and Review；CVAT Academy Quality Control in Data Annotation；核心延伸：把品質控制做成可追溯流程]
本例先對每個領域的前 10 張做雙人標註。裁決者依規範解決分歧，修訂規範後重看相似案例；後 10 張每批再抽查 2 張，疑難圖全部覆核。

| 記錄 | 分歧 | 裁決與後續 |
|---|---|---|
| T01，個體 1 | 右腕未標，或可推定但不可見 | 點位記為已標但遮擋；框仍只取可見外緣 |
| T03 | 模糊圖標有行人，或待覆核 | 隔離，不當可靠標準答案 |

每筆保留影像 ID、兩人的原始結果、分歧原因、裁決者、最後結果與規範版本。抽查沒發現問題，不等於其餘全部正確。

T01 的狀態編碼見〈[關鍵點與姿態標註](/concepts/keypoint-annotation/)〉。T03 記為 `review_status: quarantined`，即使預留在訓練分割，也須排除；保留的合成類別與遮罩只供核對來源。
:::

## 程式（補充）

以下用同一張 T01 的座標做格式核對，不用隨機數。它檢查越界與零寬框，但不會判斷框裡是不是真的有行人。

```python
width, height = 8, 6
boxes = [(1, 1, 3, 4), (5, 1, 7, 4)]
def valid(box):
    x1, y1, x2, y2 = box
    return 0 <= x1 < x2 <= width and 0 <= y1 < y2 <= height
converted = []
for box in boxes:
    assert valid(box)
    x1, y1, x2, y2 = box
    converted.append([x1, y1, x2 - x1, y2 - y1])
print("xywh:", converted)
print("零寬框有效:", valid((2, 1, 2, 4)))
```
```text
xywh: [[1, 1, 2, 3], [5, 1, 2, 3]]
零寬框有效: False
```

:::tip[讀碼重點]
`x1 < x2` 排除零寬或反向框；轉格式只改最後兩個值。數值合法之後，還要用原圖檢查類別、漏標與邊界。
:::

## 怎麼用、怎麼判讀

分類標籤、框與像素標記對應不同任務，不能只因工具能畫框就全部改成框。工具名稱可作查找索引，真正要先確認的是標記格式與工作規則。

以下整理指引列出的工具，作為查找入口；同一工具也可能支援多種任務。

| 標註方式 | 指引列出的工具 |
|---|---|
| 整圖分類 | LabelImg、Label Studio |
| 物件偵測 | CVAT、Roboflow |
| 語意分割 | LabelMe、SuperAnnotate |
| 實例分割 | VGG Image Annotator |
| 關鍵點 | COCO Annotator |

- **工具表校正**：指引把 LabelImg 列在分類，但其官方操作以矩形框標註為主。選工具仍須查實際輸出能力。（補充）

### 換個場景

| 場景或條件 | 標記需求 | 品質重點 |
|---|---|---|
| 整圖分類 | 每圖單一類別 | 類別定義一致 |
| 物件偵測 | 各物件類別與框 | 邊界精確，定期覆核 |
| 交通遮擋（補充） | 每名可辨行人的可見框 | 不合併成一大框 |
| 製造刮痕（補充） | 整圖有無，或另訂瑕疵框 | 先問只判品質，還是要定位 |
| 醫療影像（補充） | 專業定義病灶類別與位置 | 不確定案例交專業者覆核 |

## 常見誤解

- **沒有標記就是沒有物件。** 也可能還沒完成標註，必須區分工作狀態。（補充）
- **兩人都畫框就一定一致。** 可見範圍、截斷與邊界標準仍可能不同。
- **座標通過程式就是正確。** 格式檢查只能抓數值問題，無法代替看原圖覆核。（補充）

## 小結

- 分類標整圖；偵測逐物件記類別與框。
- 座標軸、單位、端點與輸出格式都要先寫清楚。
- 遮擋、截斷與模糊都需要共用規則。
- 雙人標註、裁決與抽查留下記錄，才能回查錯誤來源。

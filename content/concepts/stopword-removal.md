## 為什麼需要

大量文件裡，「的」「我」等詞可能很常見，卻不利於區分主題。檢索與主題建模可評估刪去這些詞，讓表示聚焦關鍵詞。

但高頻不等於沒有意義。「不」也常出現，刪掉後可能把負評變成正評，或讓對話不完整。

## 直覺

停用詞移除（Stopword Removal）像替特定任務篩選線索。清單不是語言裡永久的「無用詞名冊」，而是這個表示流程決定暫時忽略哪些詞。

資訊檢索只保留關鍵詞可能仍可搜尋；對話生成若刪掉代詞、介詞，則可能損失語境與自然語氣。

## 定義與公式

輸入是詞序列與停用詞清單，輸出是未命中清單的詞序列。刪除後仍應保留原來順序，不必把剩餘詞排序。

:::supplement[來源：scikit-learn User Guide Feature extraction 的 Using stop words]
清單必須與斷詞、大小寫等規則一致，否則可能刪不掉預期的詞。本組安全版只指保留本例否定詞的清單，不代表適用所有任務。
:::

## 走一次流程

用共用評論 R01、R02 比較；安全清單刪「我」，錯誤清單再加「不」。以下仍保留相同的詞邊界。

| 輸入 | 保留否定詞的版本 | 誤刪否定詞的版本 |
|---|---|---|
| 我／喜歡／這／本／書 | 喜歡／這／本／書 | 喜歡／這／本／書 |
| 我／不／喜歡／這／本／書 | 不／喜歡／這／本／書 | 喜歡／這／本／書 |

第二句原來有 6 個詞，安全版剩 5 個，誤刪版剩 4 個。詞數雖下降，兩個相反評論卻變成同一個輸入表示；模型無法從這份表示找回已刪掉的否定。

:::caution[注意]
高頻不足以構成刪詞理由。先確認否定等關鍵區別仍可辨認，再決定清單是否適合任務。
:::

交通 T01 是完整訂位請求。若生成回覆前把「我」「到」「的」都去掉，地點關係與語氣可能受影響，因此原句應另存，不能只保留刪詞後的檢索輸入。

## 程式

### 否定詞反例（補充）

這段只做固定清單過濾，不訓練分類器，也不推論刪詞後的準確率。

```python
positive = ["我", "喜歡", "這", "本", "書"]
negative = ["我", "不", "喜歡", "這", "本", "書"]
safe = {"我", "的", "The", "the", "are"}
unsafe = safe | {"不"}
for name, stops in [("保留否定", safe), ("誤刪否定", unsafe)]:
    p = [w for w in positive if w not in stops]
    n = [w for w in negative if w not in stops]
    print(name, len(n), " ".join(n), p == n)
```
```text
保留否定 5 不 喜歡 這 本 書 False
誤刪否定 4 喜歡 這 本 書 True
```

:::tip[讀碼重點]
unsafe 只比 safe 多了「不」。用完全相同的兩句比較，才能看出碰撞來自刪詞規則；True 表示兩個處理結果已相同。
:::

## 怎麼用、怎麼判讀

| 任務 | 是否移除 | 要檢查什麼 |
|---|---|---|
| 資訊檢索、主題建模 | 可評估 | 是否保留關鍵詞與區別 |
| 對話生成、語法分析 | 通常保留必要詞 | 關係、語氣與句子完整性 |
| 情感分類（補充） | 依任務清單比較 | 否定與程度詞是否消失 |

:::supplement[來源：scikit-learn User Guide Feature extraction]
比較刪詞與不刪詞時，固定共用語料索引與驗證資料。此頁證明的是資訊碰撞，不是所有分類或檢索任務都應禁用停用詞。
:::

### 換個場景

| 場景 | 選擇 | 判讀重點 |
|---|---|---|
| 文件檢索、主題建模 | 評估低貢獻高頻詞 | 主題區分是否改善 |
| 對話生成、語法分析 | 保留必要語法詞 | 語意關係與語句完整 |
| 金融新聞（補充） | 保留「未」「不」等線索 | 避免把未違約當違約 |
| 交通查詢（補充） | 保留原始請求另建檢索表示 | 起訖站關係不能顛倒 |

## 常見誤解

- 「高頻詞一定沒意義」：否定詞可能決定整句意思。
- 「降低維度必定提高準確率」：刪掉資訊也可能降低表現。
- 「一份清單適用所有模型」：任務、語言與切分方式都會影響選擇。（補充）

## 小結

- 停用詞由任務決定，高頻本身不足以構成刪除理由。
- 否定反例可檢查處理是否破壞關鍵區別。
- 檢索表示可以刪詞，完整原句仍應供生成與核對使用。

## 為什麼需要

法律與醫療文件裡，人名、組織或案件名稱散在句子中。只知道整篇屬法律或醫療，還不能建立可搜尋的欄位。

命名實體辨識（英文：Named Entity Recognition，NER）找出實體並標類型。法律文書可整理法院、當事人與案件，醫療文字也可標註人物及組織等資訊。

## 直覺

在「林安於青禾醫院掛號」中，林安是人名，青禾醫院是組織。NER要交出原文的哪一段與什麼類型，不是只回覆「這句談醫院」。

![上列保留原文字元，下列分別標出林安與青禾醫院；於與掛號不屬於兩段實體。](figure:l21101-named-entity-recognition-spans)

圖為教學示意。詞元切分和實體邊界是兩件事；一個組織名稱可能被切成數個詞元，實體仍應對回完整名稱。

## 定義與公式

NER的核心是辨認實體及其類別。不同應用可需要不同類別：法律重視法院與案件，醫療行政重視人物、組織與文件。

### 邊界與型別契約（補充）

本組用字元範圍（Span）記錄實體，從零起算，左含右不含。例如[3,7)包含索引3、4、5、6，共四個字；這是資料契約，不是所有工具的唯一格式。

本例類型有PERSON、ORG、DATE、COURT、CASE及DOCUMENT。這些是教學標籤，套用現成模型時須核對模型自己的類型集合。

## 走一次流程

同一批醫療行政與法律資料，先標實體，再供關係抽取使用。M01是掛號紀錄，L01是法院受理紀錄；兩者都不是醫療診斷或法律效力判斷。

### 醫療行政M01

原文「林安於青禾醫院掛號，日期為11月5日。」保留標點，才能讓位置可重現。下面只列兩段名稱，日期另標DATE。

| 原文字段 | 字元範圍 | 類型 | 核對方式 |
|---|---|---|---|
| 林安 | [0,2) | PERSON | 原文切片應剛好兩字 |
| 青禾醫院 | [3,7) | ORG | 不含於或掛號 |

### 法律L01與重疊歧義

「晴川法院受理星禾公司提出的甲案」分別標晴川法院為COURT、星禾公司為ORG、甲案為CASE。這裡只有類型與位置，還沒交代誰提出案件。

:::supplement[來源：spaCy命名實體文件；本組標註契約]
M06的「青禾醫院行政處」同時含內層組織「青禾醫院」。本組主欄位只允許不重疊實體，採完整名稱[0,7)；內層[0,4)另存候選，review設真。

先固定粒度，再交人工處理歧義。若任務確實需要巢狀實體，應先調整輸出契約與評估方式，不能直接把相交候選塞進不重疊欄位。
:::

## 程式（補充）

程式驗證人工標註是否對齊原文，沒有執行NER模型。先檢查全部28筆文字的切片，再印M01與L01；更動原文卻沒重算位置時，檢查就會失敗。

```python
import json, os
from pathlib import Path
root = Path(os.environ.get("IPAS_REPO_ROOT", "."))
d = json.loads((root / "content/examples/L21101-E-service-documents.json").read_text(encoding="utf-8"))
rows = d["customer"] + d["documents"]
for r in rows:
    for e in r["entities"]:
        assert 0 <= e["start"] < e["end"] <= len(r["text"])
        assert r["text"][e["start"]:e["end"]] == e["text"]
print("對齊筆數:", len(rows))
for r in rows:
    if r["id"] in {"M01", "L01"}:
        print(r["id"], [(e["text"], e["start"], e["end"], e["type"]) for e in r["entities"]])
```
```text
對齊筆數: 28
M01 [('林安', 0, 2, 'PERSON'), ('青禾醫院', 3, 7, 'ORG'), ('11月5日', 13, 18, 'DATE')]
L01 [('晴川法院', 0, 4, 'COURT'), ('星禾公司', 6, 10, 'ORG'), ('甲案', 13, 15, 'CASE')]
```

:::tip[讀碼重點]
`start:end`的右端不包含在內。原文若先去空白或改標點，舊位置就可能失效；切片相等只證明對齊，語意類型仍須人工核對。
:::

## 怎麼用、怎麼判讀

法律場景看法院、案件與當事人，醫療場景看人名、地點與組織。從非結構化文本建立欄位時，還要確認哪些實體類別對後續工作有用。

### 驗收邊界（補充）

分開盤點漏標、類型錯誤與邊界錯誤。把「青禾醫」標成ORG，類型看似正確，卻漏了「院」；若用完整實體匹配驗收，仍是不合格標註。

同名字串不保證同一個人，辨識實體也不代表已連到唯一身分。實體連結是另一項工作，不能只憑姓名合併所有紀錄。

### 換個場景

| 場景或資料條件 | 實體重點 | 判讀重點 |
|---|---|---|
| 法律文書 | 法院、案件、當事人 | 類型與完整名稱 |
| 醫療文本 | 人名、地點、組織 | 保留原文位置 |
| 大量非結構化文件 | 需要的實體欄位 | 依任務定義類型集合 |
| 電商客服（補充） | 訂單編號 | 避免把金額誤當訂單 |
| 校園公文（補充） | 學校與行政單位 | 完整單位與內層名稱重疊 |

## 常見誤解

- 「NER只需列出名詞。」還要辨認具任務意義的實體類別，不是所有名詞都要標。
- 「斷詞正確就一定標對實體。」實體可能跨詞元，類型也要另外判斷。（補充）
- 「實體辨識後就知道人物關係。」誰與誰如何相連，是後續關係抽取的工作。
- 「切片相等就證明語意正確。」它只檢查位置，無法證明PERSON或ORG選得對。（補充）

## 進階

### 座標系統（補充）

本資料只使用基本多文種平面字元，因此Python與一般前端的字元位置在此一致。新增表情符號時，Unicode碼點與UTF-16單位可能不同，資料交換應明確寫出座標規則。

## 小結

- NER交付實體及類型，實作時要能對回原文邊界。
- 法律與醫療的實體需求不同，要依用途辨識人物、法院或組織。
- 先固定粒度與座標，重疊歧義送覆核；關係仍需另外抽取。（補充）

## 為什麼需要

模型訓練時的知識，可能缺少後來公布的資料或特定領域背景。檢索增強生成（RAG，Retrieval-Augmented Generation）先查外部資料，再根據查得內容回答。

指引以公共知識問答與醫學文獻摘要說明：需要背景知識時，先找相關來源，能讓生成有更具體的依據。

## 直覺

想像讀者問退票規則：系統先翻到適用條文，把條文和問題放在一起，再組成回答。檢索負責「找哪份資料」，生成負責「怎麼整理成答案」。

![沿問題、檢索、證據到答案閱讀；版本、權限與引用核對是補充的控制點。](figure:l21101-rag-controls)

:::supplement[來源：LangChain Retrieval；OWASP LLM Prompt Injection Prevention]
企業內規也可能不在訓練資料中，可在查詢時檢索適用文件，交給模型作為回答依據。

找到資料不代表已經答對。來源可能過期、超出權限，或混入要求模型改變行為的文字；取回後仍要核對。
:::

## 定義與公式

RAG 把外部知識檢索與語言生成接在同一個流程。生成模型接收問題及相關資料，產出以資料為依據的回答；本頁不需要額外公式。

### 更新的是可用證據（補充）

更新文件與索引，可讓模型在回答時讀到新規範，通常不需要為每次文件更新重訓模型。這不等於把文件永久寫進模型權重。

檢索可以用關鍵詞、向量或混合搜尋；向量資料庫不是定義上必需的元件。若相關條件沒有被找回，模型仍可能給出錯誤答案。

## 走一次流程

使用 `L21101-D-policies.json` 的交通第一查詢。所有比例與時間都是合成規則，並非真實營運規定。

| 階段 | 固定輸入或輸出 | 要核對什麼 |
|---|---|---|
| 問題 | 發車前45分鐘一般退票多少？停駛又退多少？ | 其實有兩個條件 |
| 找到文件 | T01：至少30分鐘退90%；T02：停駛退100% | 兩份依據都需要 |
| 組成上下文 | 問題＋兩段內容＋來源與版本 | 沒有漏掉適用條件 |
| 回答與引用 | 一般退票退90%［T01］；停駛退100%［T02］ | 每個主張各有依據 |

### 分段控制與反例（補充）

固定快照是 2026-10-01，索引版本是 policy-v1。每條規則切成一塊，讓「至少30分鐘」和「90%」留在同一段；切開可能讓生成漏掉條件。

| 環節 | 本例做什麼 | 失敗線索 |
|---|---|---|
| 切塊 | 保留規則、條件及來源 | 比例與時間被拆散 |
| 嵌入 | 文字轉向量供語意比較 | 新文件漏建向量或版本不合 |
| 檢索 | 按相關性取候選 | T01、T02 沒進候選 |
| 重排 | 再比較問題與候選內容 | 必要條件被排出上下文 |
| 生成 | 整理條件並附引用 | 有正確證據卻答錯比例 |

T05 是70%舊版，不能因詞面相近就採用。T06 是內部文件，須在交給模型前做權限檢查；T07 是隔離測例，要求公開內部碼的句子不能取得指令權限。

本例預先用信任標記隔離 T07，並不代表已能偵測未知注入。實務仍需來源審核、權限限制、內容與指令分隔，以及輸出檢查等多層控制。

## 程式（補充）

以下只示範本機字詞重疊檢索。它沒有呼叫嵌入模型或生成服務，也不是 BM25；目的是看清輸入、過濾、排序與引用的接點。

```python
import json, os
from pathlib import Path
root = Path(os.environ.get("IPAS_REPO_ROOT", "."))
d = json.loads((root / "content/examples/L21101-D-policies.json").read_text(encoding="utf-8"))
domain = d["domains"]["transport"]
q = domain["queries"][0]
safe = [x for x in domain["documents"] if x["current"] and x["trusted"] and x["access"] == domain["role"]]
hits = [(sum(t in x["terms"] for t in q["terms"]), x) for x in safe]
ranked = sorted(hits, key=lambda z: (-z[0], z[1]["doc_id"]))
retrieved = [x for score, x in ranked if score > 0][:2]
print("查詢:", q["query_id"])
print("可用:", ",".join(x["doc_id"] for x in safe))
print("取回:", ",".join(x["doc_id"] for x in retrieved))
```
```text
查詢: TQ1
可用: T01,T02,T03,T04,T08
取回: T02,T01
```

第二段接著核對人工相關標註，並用固定模板展示引用。模板直接整理已取回的兩段規範，沒有驗證語言模型的生成能力。

```python
ids = {x["doc_id"] for x in retrieved}
gold = set(q["relevant_docs"])
print("相關命中:", len(ids & gold), "/", len(gold))
print("檢索召回率:", f"{len(ids & gold) / len(gold):.2f}")
evidence = {x["doc_id"]: x["text"] for x in retrieved}
if {"T01", "T02"} <= ids:
    print("一般規則:", evidence["T01"], "[T01]")
    print("停駛規則:", evidence["T02"], "[T02]")
else:
    print("證據不足，轉人工確認。")
```
```text
相關命中: 2 / 2
檢索召回率: 1.00
一般規則: 發車前至少30分鐘辦理一般退票，退還票價90%。 [T01]
停駛規則: 班次停駛時退還票價100%，不受一般退票時間限制。 [T02]
```

:::tip[讀碼重點]
先依版本、信任與角色篩選，再排序；不能先把超權內容送給模型，最後才遮住答案。空相關集的拒答查詢另看拒答品質，不代入召回率分母。
:::

## 怎麼用、怎麼判讀

先確認任務是否需要外部背景資料，再問資料能否被找回、回答能否忠實使用。公共知識與症狀問答可查知識庫；文獻摘要可先取相關研究，仍需核對來源。

### 分開看檢索與回答（補充）

本例需要兩份文件，取回兩份都相關時，相關命中為2/2。若只查到 T03、T04，應先修檢索；若取回 T01、T02 卻把兩種情況都答成100%，應查生成及條件核對。

評估回答時，把比例、時間和例外逐項對照引用。另測試資料更新、空證據拒答與權限邊界；單一查詢成功，不代表整套系統可靠。

### 換個場景

| 場景 | 資料條件 | 使用重點 |
|---|---|---|
| 公共知識與症狀問答 | 問題需要領域背景 | 先取相關知識再回答 |
| 醫學文獻摘要 | 需要近期研究依據 | 比對來源、日期與適用範圍 |
| 交通退票（補充） | 規則有版本與例外 | 同時取回一般及停駛條件 |
| 公司請假（補充） | 員工與人資權限不同 | 依角色過濾可取回的文件 |
| 製造維修（補充） | 手冊隨機型更新 | 先核對設備型號再引用 |

## 常見誤解

- 「有引用就是真話。」引用只提供查證入口，仍要看內容是否支持該主張。（補充）
- 「更新資料庫就一定回答新版。」還要確認索引更新、生效版本與取回內容。（補充）
- 「多取文件一定更好。」無關或矛盾片段可能干擾回答，應以固定查詢驗證。（補充）

## 進階

### 本例的驗證邊界（補充）

本機程式測的是過濾、字詞匹配和模板引用。混合搜尋頁沿用同文件、切塊及查詢，但以兩份手設名次測 RRF；兩者不能當成真實模型的效能比較。

## 小結

- RAG 先檢索資料，再依資料生成答案。
- 問題、文件、回答與引用應能一路對照。
- 先診斷證據是否找齊，再核對回答是否忠實。（補充）
- 新版、權限與注入要各自設控制點。（補充）

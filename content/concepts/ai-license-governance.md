## 為什麼需要

AI 系統可能同時使用外部照片、預訓練權重、演算法及開源軟體。每項來源的權利範圍不同，取得其中一項授權，不代表整個系統都能按相同條件交付。

AI 資料與模型授權查核（AI License Governance）先建立來源清冊，再把實際行為與條款比對。

指引提醒，未經授權或超出範圍使用，可能涉及智慧財產權或商業秘密侵害，並帶來訴訟及聲譽風險。

## 直覺

「能下載」只說明取得方式。能不能訓練、修改、商用或把檔案交給別人，要再看權利方授與什麼。

:::supplement[來源：Creative Commons FAQ；Apache License 2.0]
同一個模型庫可能把程式、權重及範例資料分別授權。查核時分開列資產、版本及文件，避免把專案首頁的單一標章套到所有附件。
:::

## 走一次流程

### 步驟 1：寫出將做的事

承接本組製造與零售影像系統。專案擬用影像訓練、修改模型並向客戶提供推論服務；若另要交付權重或資料副本，也必須寫進預定行為。

:::supplement[來源：本組共用合成例子；Apache License 2.0；Creative Commons CC BY 4.0]
共用 `L23401-G-vision-review.json` 的來源台帳有五項資產。第三方條款均為教學假設；格網是本組自製，並未真的下載第三方照片或權重。

| 資產 | 來源及版本 | 授權或目前狀態 |
|---|---|---|
| 自製格網 | 本組生成規則 v1 | 保留合成說明 |
| 第三方照片 | 虛構供應商附件 A v1 | 僅內部評估 |
| 模型權重 | 虛構模型庫 v2 | 缺授權文件 |
| 推論程式 | 虛構程式庫 v1 | Apache-2.0 |
| 教學插圖 | 虛構作者頁 v1 | CC BY 4.0 |
:::

### 步驟 2：分開查使用、修改與散布

| 檢查 | 要問什麼 | 本例的處置 |
|---|---|---|
| 使用（補充） | 預定訓練及商用是否在許可範圍 | 照片僅准評估，商用訓練先停 |
| 修改（補充） | 能否改圖、微調或修改程式 | 依資產文件核對，不以署名替代 |
| 散布（補充） | 能否交付副本、權重及衍生材料 | 區分服務提供與檔案交付 |
| 缺授權 | 找不到文件或權利方不明 | 隔離待查，補許可或替換來源 |

:::supplement[來源：Apache License 2.0 第 2～4、6 節；Creative Commons CC BY 4.0 與 FAQ]
Apache-2.0 程式可依條件使用、修改及散布；交付時須逐項查 LICENSE、修改標記與適用 NOTICE。其專利授權有範圍，不等於可使用所有第三方專利，商標也須另查。

CC BY 4.0 插圖可依條件分享與改作；查核適當署名、授權連結及變更說明。該授權不代表肖像、隱私、商標等其他權利都已處理，也不能證明提供者擁有所有上游權利。
:::

### 步驟 3：把三類智慧財產權分開查

指引提到著作、專利及商標。三者保護的標的不同，不能用「已付錢」或「有註明出處」概括所有許可。

:::supplement[來源：WIPO What is Intellectual Property；全國法規資料庫《著作權法》；TIPO 各主題網]
| 權利 | 查核標的 | 影像系統的問題 |
|---|---|---|
| 著作權（Copyright） | 影像、文件或程式等具體表達 | 是否可複製、改作、散布 |
| 專利權（Patent） | 受保護的技術方案 | 實施壓縮或推論方法是否需許可 |
| 商標權（Trademark） | 識別商品或服務來源的標識 | 能否在介面或廣告用供應商 Logo |

具體表達、技術方案及來源標識的區分，用來分派查核工作，不直接判定個案侵權。專利還須查地域、有效狀態及實際落入的權利範圍；授權條款若已有特定專利許可，依其範圍核對。
:::

### 步驟 4：留下法名、機關及未結案事項

:::caution[注意]
指引 4-36 以「台灣智慧財產權法」統稱，並描述為 TIPO 制定，不能照搬成單一法律。應分別核對《著作權法》《專利法》《商標法》，並區分立法與主管機關職責。
:::

:::supplement[來源：全國法規資料庫《著作權法》第 2 條、《專利法》第 3 條、《商標法》第 3 條；《經濟部智慧財產局組織法》第 1～2 條]
三部法律由立法院通過。《著作權法》第 2 條、《專利法》第 3 條及《商標法》第 3 條均以經濟部為主管機關；相關業務交由其指定的專責機關智慧財產局辦理。

適用法域、條文版本、生效狀態及個案權利範圍交由法務確認，不把主管業務寫成「智慧財產局自行制定法律」。

結案待辦是：採購補照片商用範圍、供應商補權重文件、工程保存程式授權及修改紀錄、行銷確認 Logo 用途。每項留負責人與期限，未結項目維持待查。
:::

## 怎麼用、怎麼判讀

把「檔案能否取得」「個資能否處理」「智慧財產權能否使用」分成不同問題。對照片有著作授權，仍可能需要核對畫面人物的隱私；影像遮臉，也不表示第三方著作授權問題已消失。

:::supplement[來源：Creative Commons FAQ；Apache License 2.0]
換版本、換用途或由內部服務改成對外交付時，重新比對清冊。不要把一次核准視為未來所有用途的通行證。
:::

### 換個場景

| 場景 | 先查什麼 | 決策重點 |
|---|---|---|
| 第三方訓練資料、演算法與模型 | 來源與授權範圍 | 不超出許可，履行條件 |
| 開源工具 | 工具的授權條款 | 開放取得仍須依條件使用 |
| 製造檢測（補充） | 照片契約與模型權重 | 內部試用不直接等於商用 |
| 零售應用（補充） | 圖庫、推論程式及 Logo | 不把程式授權套到圖庫或標識 |
| 教育插圖（補充） | 作者、版本、署名與修改條件 | 開放授權仍有條件 |

## 常見誤解

- **有引用來源就有使用許可**：引用不會自動補足超出範圍的行為。
- **演算法可直接抄用而不標來源**：指引也提醒演算法抄襲與引用不足的風險；須核對來源及使用條件。
- **開源代表沒有義務**：仍要看相應授權文件及條件。
- **智慧財產權只有著作權**：專利與商標也可能影響實際用途。
- **權重和程式一定同授權**：應按各資產文件核對。（補充）

## 小結

- 分列資料、權重、程式與其他素材，不以單一標章代替整份清冊。
- 逐項比對使用、修改與散布條件，缺授權就補查或替換。
- 著作、專利、商標及個資議題各有範圍，要分別處理。
- 查核記錄須含版本、預定行為、負責人與未解事項。

## 為什麼需要

三家醫院想共同訓練疾病模型，卻不宜把病人紀錄集中到同一處。聯邦學習（Federated Learning）讓各院在本地訓練，再交換模型參數的更新，減少原始資料傳輸。

## 直覺

中央先發出共同模型，各方用自己的資料修正，再把更新送回。中央聚合更新，形成下一輪的共同模型；原始列仍在各院或使用者裝置。

![沿箭頭分辨下發模型、回傳更新與本地原始列，更新跨網路仍須保護。](figure:l23401-federated-learning-flow)

:::supplement[來源：McMahan 等（2017）第 1–2 節]
本頁介紹中央聚合式流程。聯邦學習也有其他協作架構，不能把「一定有單一中央」當成整個家族的必要條件。
:::

## 定義與公式

本地訓練與中央聚合各負責不同工作。要分清三種資料：原始訓練列、本地算出的更新，以及供下一輪使用的共同模型。

| 資料 | 主要位置／流向 | 用途 |
|---|---|---|
| 原始列 | 各院或手機內部 | 本地訓練 |
| 本地更新 | 各方傳到聚合端 | 改善共同模型 |
| 共同模型（補充） | 聚合端發給各方 | 下一輪訓練起點 |

### 按樣本數聚合（補充）

本例示範 FedAvg 式的本地更新與聚合，約定只對本輪實際參與且回傳有效更新的各方，按訓練筆數正規化。以下三方全部參與，使用相同模型結構與參數對應，都從同版共同模型出發、完成同一輪本地更新：

$$
w^{\mathrm{new}}=\sum_{k=1}^{3}\frac{n_k}{N}w_k,\qquad N=\sum_{k=1}^{3}n_k
$$

$w_k$ 是第 $k$ 方更新後的模型權重，$n_k$ 是該方本輪訓練筆數，$N$ 只加總本輪納入聚合各方的訓練筆數，不含驗證列。條件為 $n_k\ge 0$、$N>0$；若沒有有效訓練列，就不執行本輪聚合。一般模型有多個權重，須逐項用相同規則聚合。

一般加權平均的直接來源是 [NumPy `average` 官方文件](https://numpy.org/doc/2.5/reference/generated/numpy.average.html)的 `weights` 說明，完整列出 `avg = sum(a * weights) / sum(weights)`。逐一對應本式：`a` 的各元素是 $w_k$、`weights` 的各元素是 $n_k$、`sum(weights)` 是 $N$、`avg` 是 $w^{\mathrm{new}}$；求和涵蓋輸入的所有元素。本例把本輪納入聚合的各方放入輸入，因此得到上式。NumPy 支持一般加權平均的數學與程式語義，參與者如何選取則是本站示範約定。

本例各方 $n_k=6$、$N=18$。代入 $w_A=1/30$、$w_B=1/10$、$w_C=7/30$，得新權重 $11/90$，約 0.122222。

## 走一次流程

### 留存與交換的安排

跨院流程先在各院保留原始資料、進行本地訓練，僅回傳更新。中央處理收到的更新，再把共同模型送回各院。

### 固定資料走一輪（補充）

使用 `L23401-D-distributed.json`。跨院與跨銀行各有 24 筆，三方各 8 筆；各方前 6 筆訓練、後 2 筆驗證，兩領域切分相同。

1. 中央下發版本 v0、初始權重 0，各方確認輪次為 1。
2. 各方只讀自己的 6 筆訓練列，更新同一個單特徵邏輯斯迴歸模型。
3. 甲乙丙更新後權重為 0.033333、0.100000、0.233333，送出權重及訓練筆數。
4. 中央按 6、6、6 筆加權，產生版本 v1，權重為 0.122222，再送回各方。

FedAvg 回傳更新後的權重。本例起始權重是 0，數值才恰好等於更新量；一般情況不能把兩者混用。

跨院的標記是疾病，銀行的標記是風險事件；特徵是無單位的合成風險值。每輪驗證留在各方，這一輪不計算泛化成績，也沒有用驗證列訓練。

### 手機鍵盤怎麼換成同一流程

各手機保留輸入紀錄，先下載共同鍵盤模型，在裝置內學習，再傳回更新。中央整合多支手機的更新，送出新版模型；通訊量與參數逆推風險仍需評估。

## 程式

### 一步本地更新與平均（補充）

程式摘出共用 JSON 每方前 6 筆的特徵與標記。兩領域刻意共用相同訓練數字，迴圈只切換領域名稱，重用同一組陣列。

模型沒有截距，起始預測全為 0.5；使用二元交叉熵的一步梯度更新，學習率固定為 0.4。

```python
import numpy as np
x = np.array([1, 2, 1, 2, 1, 2])
labels = [[0, 0, 0, 1, 1, 1], [0, 0, 1, 1, 1, 1], [0, 1, 1, 1, 1, 1]]
for domain in ["hospital", "bank"]:
    updates, sizes = [], []
    for y in labels:
        gradient = np.mean(x * (0.5 - np.array(y)))
        updates.append(-0.4 * gradient)
        sizes.append(len(y))
    print(domain, "local", " ".join(f"{w:.6f}" for w in updates))
    print("global", f"{np.average(updates, weights=sizes):.6f}")
```
```text
hospital local 0.033333 0.100000 0.233333
global 0.122222
bank local 0.033333 0.100000 0.233333
global 0.122222
```

:::tip[讀碼重點]
`labels` 只摘訓練列，未包含最後兩筆驗證標記。這是集中核算的片段；實際部署應把各方資料讀取留在各自環境，本段沒有實作網路或隱私協議。

`domain` 只改輸出標籤，沒有另讀兩份資料；兩輪相同輸出是共用數字的結果。`updates` 在本例存更新後權重，起點為 0 時才等於更新量。
:::

## 怎麼用、怎麼判讀

適合資料分散、需要合作建模而不宜集中原始紀錄的情境。要同時問「資料留在哪裡」與「聚合端能看見什麼」，不能只問有沒有上雲。

通訊成本隨模型大小、參與方及輪次變動。更新仍可能被逆推，聯邦學習本身沒有承諾更新不帶個人資訊。

:::supplement[來源：Google Research 聯邦學習介紹；TensorFlow Federated 影像分類教學]
可另評估安全聚合，限制中央看到單一更新；差分隱私則處理輸出對個人的影響。各方資料分布不同也會影響訓練，保護機制與模型品質要分別檢查。
:::

## 常見誤解

- **資料不上傳就沒有外洩風險**：更新仍可能透露訓練資訊。
- **減少原始資料傳輸就一定省通訊**：多輪更新仍可能造成很大傳輸量。
- **傳加密原始列給雲端解密就是聯邦學習**：要看訓練是否在本地、交換是否為更新。（補充）

## 進階

### 聚合的前提（補充）

權重需使用相同模型結構、參數對應與共同起始版本，不能把不同欄位的數值直接平均。依本站「只納入本輪有效更新」的示範約定，少一方或某方訓練筆數改變時，分子與分母都只計入本輪實際納入聚合的各方，重算分母並記錄參與情況；仍須滿足前述非零分母條件。

McMahan 等原論文 Algorithm 1 先抽出本輪參與集合 $S_t$，但印刷的聚合式仍對 $k=1,\ldots,K$ 求和，分母 $n$ 沿用全體訓練筆數。本頁三方全參與時沒有此範圍差異；部分參與時，不能把本站重新正規化的約定說成該原式直接列出的規則，也不能由該式自行補出缺席端如何處理。原論文在此支持下發共同模型、本地訓練及回傳模型後聚合的流程。

## 小結

- 原始列留本地，各方交換模型更新，再取得共同模型。
- 留存位置、更新內容與聚合責任要分開畫清楚。
- 更新仍有逆推風險，通訊成本也不能忽略。
- 本例按訓練筆數加權，沒有把驗證列加入更新。（補充）

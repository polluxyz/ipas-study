## 為什麼需要（補充）

查詢「退票」和文件「退款」可能用不同詞；相反地，產品代碼差一個字元就可能是另一台設備。混合搜尋（Hybrid Search）同時利用詞面與語意線索，降低只靠單一路線的盲點。

## 直覺（補充）

讓兩位檢索者各交一份名次表：一位重視字詞吻合，另一位重視表示空間中的相近程度。排序融合把兩份意見合成一份，再決定哪些文件送去回答。

兩路的原始分數尺度可能不同。倒數排名融合（Reciprocal Rank Fusion，RRF）改用名次計分，不需要直接比較字詞分數與向量相似度的大小。

## 定義與公式（補充）

| 角色 | 依據 | 本身不保證什麼 |
|---|---|---|
| BM25 詞面檢索 | 詞頻、詞的稀有程度與文件長度 | 不直接理解所有同義改寫 |
| 向量檢索 | 查詢與文件表示的相近程度 | 不保證精確辨識型號、數字或否定 |
| RRF 融合 | 各路候選的名次 | 不重新閱讀文件判斷事實 |
| 重排 | 再比較問題與候選內容 | 不必然找回候選外的文件 |

等權 RRF 對文件 $d$ 的分數為：

$$
\mathrm{RRF}(d)=\sum_{j\,:\ d\in L_j}\frac{1}{c+r_j(d)}
$$

$L_j$ 是第 $j$ 路回傳的候選清單，$r_j(d)$ 是文件在該路的名次，從1開始；$c$ 是正的平滑常數，本例固定60。沒出現在某一路，就沒有該路的貢獻。

$c$ 越大，前幾名之間的單路分數差越小。它不同於「取前幾份」的數量；本例每路只取前三份，不能把60誤當候選數。

## 算一次（補充）

沿用 RAG 頁的交通第一查詢、policy-v1 索引與一規則一塊的切法。只有現行、可信且符合權限的區塊可進候選。

兩份名次是手設測試輸入，並非實際 BM25 或嵌入模型跑出的結果。詞面前三名為 T03→T01→T04，向量前三名為 T02→T01→T08。

| 文件 | 詞面名次 | 向量名次 | RRF 分數 |
|---|---|---|---|
| T01 | 2 | 2 | 2/62 ≈ 0.032258 |
| T02 | 未入榜 | 1 | 1/61 ≈ 0.016393 |
| T03 | 1 | 未入榜 | 1/61 ≈ 0.016393 |
| T04 | 3 | 未入榜 | 1/63 ≈ 0.015873 |
| T08 | 未入榜 | 3 | 1/63 ≈ 0.015873 |

T01 的兩路貢獻是 $1/(60+2)+1/(60+2)=2/62$。T03 只有一路第1名，貢獻 $1/(60+1)=1/61$；因此融合後 T01 在前。

同分按文件 ID 升冪，得到 T01→T02→T03→T04→T08。這是本例的可重現約定，不是 RRF 對同分的唯一規定。

答案需要 T01、T02。只看詞面前二名只能命中一份；融合前二名命中兩份，相關命中從1/2變2/2。

這個2/2依賴同分按 ID 升冪：若同分改先取 T03，前二名只命中1/2。RRF 本身沒有保證本例改善，更不能由此推論所有問題都會改善。

## 程式（補充）

從共用 JSON 讀兩份清單，只計算融合與固定的同分排序。沒有讀模型權重、下載資料或使用亂數。

```python
import json, os
from pathlib import Path
root = Path(os.environ.get("IPAS_REPO_ROOT", "."))
d = json.loads((root / "content/examples/L21101-D-policies.json").read_text(encoding="utf-8"))
q = d["domains"]["transport"]["queries"][0]
scores = {}
for ranking in [q["lexical_rank"], q["vector_rank"]]:
    for rank, doc_id in enumerate(ranking, start=1):
        scores[doc_id] = scores.get(doc_id, 0) + 1 / (d["settings"]["rrf_constant"] + rank)
fused = sorted(scores, key=lambda doc_id: (-scores[doc_id], doc_id))
for doc_id in fused:
    print(doc_id, f"{scores[doc_id]:.6f}")
print("前二名相關命中:", len(set(fused[:2]) & set(q["relevant_docs"])))
```
```text
T01 0.032258
T02 0.016393
T03 0.016393
T04 0.015873
T08 0.015873
前二名相關命中: 2
```

:::tip[讀碼重點]
enumerate 從1開始；同文件的兩路分數相加，未入榜不補虛構名次。印出時才取六位小數，排序用完整精度。
:::

## 怎麼用、怎麼判讀（補充）

要公平比較，固定文件版本、權限、切塊、查詢及相關標註，再比較詞面、向量與融合。若也換了切塊方式，就不能把差異全歸給 RRF。

若必要文件兩路都漏掉，融合與一般重排都無從使用。應先看資料是否入索引，再檢查各路取回數量及表示方式；候選齊全後才評估重排。

### 換個場景（補充）

兩本指引未明確教授混合搜尋與 RRF，以下是延伸場景。

| 場景 | 詞面線索 | 語意線索 |
|---|---|---|
| 交通規範 | 退票、停駛 | 不搭車能拿回多少 |
| 公司請假 | 事假、病假證明 | 臨時身體不適如何補件 |
| 設備維修 | AX-17 型號與故障碼 | 機台反覆重新啟動 |

請假第一查詢沿用相同名次位置，將 T 換成 H。按同分 ID 升冪，融合先取回 H01、H02；若先取同分的 H03，也只命中1/2。

H01、H02 分別支持事假與病假條件；不能把3天申請與2天補件混成一條規則。

## 常見誤解（補充）

- 「BM25 就是混合搜尋。」BM25 是詞面檢索的一條路，混合搜尋還要結合其他檢索訊號。
- 「RRF 就是重排模型。」它融合名次；內容重排則再次比較查詢與候選文本。
- 「融合分數是答案正確率。」分數表示名次貢獻，不是經校準的機率。

## 進階

### 排名看不到的資訊（補充）

RRF 保留次序，卻不使用原始分數差距。一路第一名大幅領先或只領先一點，若名次相同，貢獻仍相同；需要用任務資料評估這種取捨。

## 小結（補充）

- 詞面與向量提供不同相關性線索。
- RRF 加總各路名次貢獻，不直接相加異尺度原始分數。
- 先找齊候選，再判斷是否需要內容重排。
- 用固定查詢及相關標註驗證改善，不能只看分數變大。

## 為什麼需要

同一份專案有資料整理程式、模型、介接程式及測試。選工具時若把用途混在一起，容易以為安裝某個框架，就已完成全部開發準備。

版本沒有約定，資料工程師、模型開發者與架構師也可能各用不同的檔案。工具鏈（Toolchain）要連起工作，版本管理則讓大家知道接到的是哪一份。

## 直覺

先寫工作，再找工具：寫程式用語言，模型訓練用框架，大量資料處理看平台需求，程式改了什麼則交給版本控制。不是每一個小型試辦都必須把所有工具裝齊。

## 定義與公式

### 指引列出的工具分工

| 類別 | 例子 | 主要用途 |
|---|---|---|
| 程式語言 | Python | 撰寫資料、模型與整合程式 |
| 深度學習框架 | TensorFlow、PyTorch | 建立、訓練與使用模型 |
| 大資料處理平台 | Spark、Hadoop | 支援大量資料處理與分析 |
| 程式版本管理 | Git | 管理原始碼與版本變更 |

科目 1 指引 5-19 另提資料及模型版本追蹤，科目 3 指引 5-20 要記錄模型結構、權重、超參數與訓練結果。版本管理不限於為程式檔換名字。

### 工具名稱不代表全部功能相同（補充）

Python 是語言；TensorFlow、PyTorch 提供模型運算與訓練工具。Spark 可處理分散式資料運算；Hadoop 生態系包含儲存與資源管理等元件，兩者不等同。

Git 版本控制（Version Control）記錄檔案隨時間的修改，供比較及回查。Git 可以追蹤多種檔案，但「程式有 commit」不表示資料、模型與環境都已被完整保存。

本頁只辨認用途，不要求把 Spark 或 Hadoop 加入小型範例。是否採用分散式平台，要由資料規模、既有環境及維護能力決定。

## 走一次流程

### 製造案版本交付（補充）

共用案的 M2、M3、M5 分別交付資料、模型及部署介面。把三項產物的版本連在一起，才能知道這次測試驗證的是什麼。

| 交付欄位 | 教學示例 | 誰確認 |
|---|---|---|
| 程式 | 示意 Git commit `c0de001`，無未提交修改 | 開發者 |
| 資料與切分 | manufacturing-v1；600／200／200，批次隔離 | 資料工程師 |
| 訓練設定 | 種子 42、模型結構、超參數及環境版本清單 | 模型開發者 |
| 模型及介面 | 模型 v1、前處理 v1、API v1 | 模型開發者及架構師 |
| 驗證產物 | 同版測試報告、限制與未結項 | 測試工程師 |

本例假設各批次已隔離；JSON 只存索引，未提供逐筆批次 ID。腳本可核對索引互斥與完整覆蓋，不能證明實際批次隔離。

這個 commit 是虛構標記，實際交付要填真實識別碼。環境清單需記錄實際 Python、框架與依賴版本；只寫「已安裝 PyTorch」仍無法辨認執行環境。

假設資料欄位改版，先由資料工程師更新映射及資料版，再讓模型開發者確認前處理和模型是否重做，最後讓架構師及測試者更新對應引用。

### 零售案用同一規則（補充）

R2 的 retail-v1 假設按時間分成 300／100／100 筆，與製造案的批次隔離不同。JSON 沒有逐筆事件時間，因此時間順序仍是教學假設；索引核對不能取代時間查驗。

同一零售案比較模型時沿用這組索引及種子 42，不能換掉測試資料還聲稱是同基準比較。

資料量很小時，Python 與合適的模型工具即可起步。大量事件已在 Spark 或 Hadoop 平台時，可將整理後的特徵版本交給訓練工作，Git 另外管理處理程式。

## 怎麼用、怎麼判讀

看工具清單時，要找出它服務哪項任務，以及誰維護。若只列熱門產品名稱，卻沒有對應資料、模型或程式工作，仍無法判斷配置是否適合。

### 換個場景

指引以 AI 開發及大資料處理為通用情境，沒有為本段工具另指定單一產業。需要資料分析或深度學習時，依工具用途分工。

| 場景 | 使用重點 |
|---|---|
| 深度學習與大量資料處理 | 分辨語言、訓練框架、資料平台及版本控制 |
| 製造檢測（補充） | 綁定相機資料、前處理及模型版本 |
| 零售推薦（補充） | 保留事件時間範圍、切分及特徵版 |
| 醫療研究（補充） | 保存授權範圍內的資料版本與執行設定 |

## 常見誤解

- 「Python、PyTorch、Git 是同一種工具」：分別是語言、框架與版本管理工具。
- 「有 Git 就能自動重現訓練」：還需對齊資料、環境及設定。（補充）
- 「所有資料都應直接放 Git」：先確認容量及治理要求，版本清單可指向受控儲存位置。（補充）
- 「檔名最終版就是版本控制」：名稱無法交代修改歷史與內容差異。（補充）

## 進階

### 版本不是效果保證（補充）

版本完整讓差異可查，不代表模型一定比較好。兩次結果不同時，先核對輸入及環境，再看模型設定；不能只因新版本較新就宣布改善。

## 小結

- Python、訓練框架、資料平台與 Git 各有工作用途。
- 程式、資料、模型及訓練紀錄要能辨認版本。
- 同一次交付保存版本對應，才能跨角色回查。（補充）
- 工具依需求配置，不以清單長度判斷準備完成。（補充）

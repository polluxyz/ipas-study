## 為什麼需要（補充）

若任務要抓住一個關鍵條件，注意力卻把無關位置也混入相近比重，線索可能被稀釋。本頁把這個題設現象稱為「注意力過度平均」，不把它當所有模型失效的共同定義。

Attention Collapse 的名稱在不同研究中可能指不同現象。這裡只處理指定權重太平均的受控案例，不涵蓋各種秩退化、注意力頭重複或訓練不穩定。

Zhai 等人的 attention entropy collapse 指熵過低、權重過度集中，與本頁的過度平均方向相反。讀到 collapse 時，須先確認作者定義及觀察對象。

## 直覺（補充）

每一列是一個查詢位置，每一欄是可讀取的鍵位置。列內權重接近時，查詢會把多個值混成相近的平均；若關鍵只在其中一格，該格未必占足夠比重。

![上圖每列接近平均；下圖只保留各列最大值，請比較同一列的非零位置，而非只看顏色。](figure:l21101-attention-collapse-heatmaps)

兩張4×4熱圖由同一份手設權重生成。下圖是明訂 top-1 規則的結果，不是訓練前後的測量，也不是某個稀疏注意力演算法的實驗成績。

## 定義與公式

固定一個查詢位置，注意力輸出是值的加權加總：

$$
o=\sum_{j=1}^{4}a_jv_j,
\qquad a_j\geq0,\quad\sum_{j=1}^{4}a_j=1
$$

$a_j$ 是該列對第 $j$ 個位置的權重，$v_j$ 是該位置的值，$o$ 是輸出。本例用純量值便於手算；真實模型可對整個值向量逐維加權。

:::supplement[來源：Dive into Deep Learning 11.2]
「過度」必須相對任務判斷。若任務本來需要整體平均，分散不一定是缺陷；若需要同時讀兩個條件，硬只留一格反而可能遺漏資訊。
:::

## 算一次（補充）

共用例子固定四個值為0、0、0、8，並指定第4個查詢需要最後一格的線索。這些數字只是特徵示意，8不是退票金額或請假天數。

原第4列是0.25、0.24、0.25、0.26，因此：

$$
o=0.25\times0+0.24\times0+0.25\times0+0.26\times8=2.08
$$

這裡仍以 $o$ 表示輸出；四項乘法分別對應四個位置。只保留該列最大權重0.26，再除以保留權重總和0.26，得到0、0、0、1，輸出為8。

若誤把第1格設為唯一可讀位置，權重同樣只有一個非零值，輸出卻是0。由此可見，「更稀疏」和「讀對證據」是兩項不同條件。

![三列使用同一份值；稀疏但誤留第一格時輸出為0，不能由非零格較少推論品質較好。](figure:l21101-attention-collapse-weighted-counterexample)

## 程式（補充）

程式只重現題設的權重操作。top-1 留最大格，同分取最左，再正規化；沒有修改查詢或鍵的投影參數，也沒有做模型訓練。

```python
import json, os
from pathlib import Path
root = Path(os.environ.get("IPAS_REPO_ROOT", "."))
d = json.loads((root / "content/examples/L21101-D-policies.json").read_text(encoding="utf-8"))["attention"]
v, a = d["values"], d["before"]
focused = [[x if j == max(range(4), key=row.__getitem__) else 0 for j, x in enumerate(row)] for row in a]
focused = [[x / sum(row) for x in row] for row in focused]
weighted = lambda row: sum(x * y for x, y in zip(row, v))
print("原輸出:", [round(weighted(row), 2) for row in a])
print("聚焦輸出:", [round(weighted(row), 2) for row in focused])
print("錯誤聚焦:", weighted(d["wrong_focus"]))
print("原列權重和:", [round(sum(row), 2) for row in a])
```
```text
原輸出: [1.92, 2.0, 2.0, 2.08]
聚焦輸出: [0.0, 0.0, 0.0, 8.0]
錯誤聚焦: 0
原列權重和: [1.0, 1.0, 1.0, 1.0]
```

:::tip[讀碼重點]
聚焦後第4列取得8，但前面三列的任務正解並未給定，不能據此計算整體準確率。這個程式驗證加權行為，沒有證明下游任務改善。
:::

## 怎麼用、怎麼判讀（補充）

先問任務需要哪個位置，再看權重與輸出是否一致。比較時固定輸入、模型層及注意力頭，並確認沒有把填補位置、遮罩或平均多個頭造成的圖形差異誤認為現象。

稀疏約束旨在限制或鼓勵只讀取較少位置。Sparsemax 等方法能產生精確零值，但不等於本頁手動 top-1；採用哪種機制都需驗證是否保留必要資訊。

### 換個場景（補充）

指引介紹自注意力及其應用，沒有明確教授本頁限定的過度平均診斷。以下沿用題設解讀，不宣稱這些領域普遍發生同一種崩潰。

| 場景 | 應保留的線索 | 稀疏化的反例 |
|---|---|---|
| 交通退票 | 時間條件與比例 | 只留90%會漏掉適用時間 |
| 公司請假 | 返工後與2天期限 | 只留2天可能混淆時間起點 |
| 設備維修 | 型號與異常描述 | 只留型號可能排除故障線索 |

## 常見誤解（補充）

- 「平均分布一定錯。」要看任務是否需要整體彙整，不能只依熱圖下結論。
- 「權重集中就一定讀對。」錯誤位置也能得到權重1，反例輸出仍是0。
- 「注意力權重就是解釋。」它只描述內部加權，不能單憑圖形證明答案的因果來源。

## 進階

### 稀疏注意力與聚焦目的

科目3指引 4-84 介紹的稀疏注意力用於降低長序列的計算與記憶體負擔。它關心的是長序列能否更有效率地處理。

:::supplement[來源：Sparsemax 原始論文]
本頁的稀疏約束則著重權重是否聚焦於必要位置。減少可讀位置與讓權重出現零值是不同設計；不能由名稱相近，就推定能同時省計算並提升答案品質。
:::

### 直接加 L1 不一定產生稀疏（補充）

本頁權重非負且總和為1，所以絕對值總和也固定為1。原第4列是0.25＋0.24＋0.25＋0.26＝1，聚焦後是0＋0＋0＋1＝1。

若直接對這種歸一化權重加上 L1 懲罰，它是常數，不能靠這一項區分兩種分布。真正的稀疏機制須說清楚施加位置與方式，不能只寫「加稀疏正則化」就保證有效。

## 小結（補充）

- 本頁僅依題設辨認關鍵線索被近似平均混合的現象。
- 先算加權輸出，再評估保留的位置是否符合任務。
- 稀疏化可能聚焦，也可能刪掉必要條件。
- 熱圖與非零格數不能代替下游任務的驗證。

## 為什麼需要

影像模型不只要說「有瑕疵」，還可能要指出瑕疵在哪裡。預測框只碰到目標一角，與貼合整個目標，定位品質並不相同。

IoU（Intersection over Union；本站以「交集聯集比」說明）把這種重疊程度變成比例。它可比較物件偵測的框，也可比較影像分割的遮罩區域。

## 直覺

交集是兩個區域共同覆蓋的部分；聯集是至少被其中一個覆蓋的全部區域。交集越接近聯集，表示兩個區域越吻合。

:::supplement[來源：Dive into Deep Learning 14.4.2 Intersection over Union]
本頁用製造瑕疵定位的教學模擬資料。真實框 G 是人工標註的刮痕區域，預測框 B 寬高相同，卻向右偏移四像素。

![注意交集只有共同覆蓋的部分，聯集則把兩框覆蓋的區域合起來且不重複計數。](figure:l23303-intersection-over-union-box-overlap)
:::

## 定義與公式

$$
\mathrm{IoU}=\frac{|G\cap B|}{|G\cup B|}
=\frac{I}{A_G+A_B-I}
$$

$G$ 是真實區域，$B$ 是預測區域，$I$ 是交集面積；$A_G$、$A_B$ 是兩個區域各自的面積。$|\cdot|$ 表示面積，不是框的周長。

聯集只計一次交集，所以分母要減去 $I$。本例 $I=320$、$A_G=A_B=400$，得到 $320/(400+400-320)=2/3≈0.667$。

兩區域都有有效面積時，IoU 在 0 到 1 之間：沒有重疊是 0，完全重合是 1。影像分割的遮罩也採同一個交集除以聯集的想法。

### 從框座標求交集（補充）

本頁只處理與座標軸平行的矩形。每框寫成 $(x_1,y_1,x_2,y_2)$，前兩個是左上角，後兩個是右下角，單位為像素。

座標是連續邊界，寬高採差值，不加 1。有效框要求 $x_2>x_1$、$y_2>y_1$；旋轉框需另用對應的幾何算法。

$$
\begin{aligned}
w_I&=\max(0,\min(x_{2G},x_{2B})-\max(x_{1G},x_{1B}))\\
h_I&=\max(0,\min(y_{2G},y_{2B})-\max(y_{1G},y_{1B}))\\
I&=w_Ih_I,\qquad A_G=(x_{2G}-x_{1G})(y_{2G}-y_{1G})
\end{aligned}
$$

$w_I$、$h_I$ 是交集寬與高，下標 G、B 區分兩個框。預測框面積 $A_B$ 也用同樣的寬乘高；max 與 min 分別取較大、較小值。

代入 G=(10,10,30,30)、B=(14,10,34,30)：$w_I=30-14=16$、$h_I=30-10=20$，因此 $I=320$；$A_G=A_B=20×20=400$。

max(0, …) 避免不相交時出現負寬高。零面積框應先判為無效輸入；兩個空遮罩的聯集為 0 時，IoU 未定義，須依任務規約處理，不能默認為完美重合。

## 算一次（補充）

資料存於本組 JSON。G=(10,10,30,30)，主預測 B1=(14,10,34,30)；圖、手算與程式都使用這組座標。

1. 兩框面積都是 20×20=400 像素平方。
2. 交集為 x=14～30、y=10～30，面積 16×20=320。
3. 聯集為 400+400−320=480，IoU=320/480≈0.667。

把模型改成以下替代框，各自單獨與 G 比較：

| 預測方案 | 交集／聯集 | IoU | 代表什麼 |
|---|---|---|---|
| B1=(14,10,34,30) | 320/480 | 0.667 | 向右偏移 |
| B2=(0,0,40,40) | 400/1600 | 0.250 | 完整包住目標，卻框得過大 |
| B3=(40,10,60,30) | 0/800 | 0 | 完全不相交 |

這三列是替代方案，不是同一張圖同時輸出的三個框。B2 雖然包含整個真實框，仍因額外背景多而得低分。

### 指定面積與座標極端情形（補充）

`L21102-M4-E-iou-matching.json` 的面積例與匹配例各自獨立，均是合成座標。以下固定 G=(0,0,10,10)，面積 100 像素平方；邊界連續、寬高不加 1。

| 預測框 B | 交集 I／面積 B | 聯集／IoU |
|---|---|---|
| (6,0,14,10) | (10−6)×10=40／8×10=80 | 100+80−40=140；40/140=2/7≈0.286 |
| (0,0,10,10) | 10×10=100／100 | 100+100−100=100；100/100=1 |
| (20,0,28,10) | max(0,10−20)×10=0／80 | 100+80−0=180；0/180=0 |

第一列完整重算 100／80／40；第二列兩框座標完全相同，所以交集等於聯集；第三列不相交，交集為 0。

座標推算依 Torchvision 原始碼的矩形規則，屬補充深度，不倒算為指引已教座標算法。

先看圖上半部的面積與聯集；下半部是另一組固定框的匹配摘要，兩門檻均含等號。請搭配下方[固定框集的兩個匹配門檻](#固定框集的兩個匹配門檻補充)的完整座標及逐框表閱讀，不把兩組案例的框混用。

## 程式（補充）

以下不用額外套件，按已明示的座標約定計算。程式拒絕零寬或零高的框，避免把無效輸入混入評估。

```python
def iou(g, b):
    def area(box):
        x1, y1, x2, y2 = box
        if x2 <= x1 or y2 <= y1:
            raise ValueError("框必須有正寬高")
        return (x2 - x1) * (y2 - y1)
    ag, ab = area(g), area(b)
    w = max(0, min(g[2], b[2]) - max(g[0], b[0]))
    h = max(0, min(g[3], b[3]) - max(g[1], b[1]))
    inter = w * h
    return inter / (ag + ab - inter)
g = (10, 10, 30, 30)
for b in [(14, 10, 34, 30), (0, 0, 40, 40), (40, 10, 60, 30)]:
    print(f"{iou(g, b):.3f}")
```

```text
0.667
0.250
0.000
```

:::tip[讀碼重點]
先對交集寬高取 max(0, …)，再相乘。聯集不是兩個面積直接相加，也不是用包住兩框的外接矩形代替。
:::

## 怎麼用、怎麼判讀

IoU 適合比較分割區域或偵測框的幾何重疊。指引也在零售動線分析中列出這個指標；須先定義要比較的區域，再談重疊程度。

科目 1 指引 3-51 用 IoU「大於」0.5 或 0.7 描述常見的定位成功條件，未規定完整匹配演算法。

本頁下方的固定框集是補充匹配例，另採 COCOeval 等工具在這兩個門檻使用的「大於或等於」（≥）規約；兩者須分開閱讀。

:::supplement[來源：COCO 官方 COCOeval 的 evaluateImg 實作]
COCOeval 在本例 0.5、0.7 門檻下接受等號；原始碼還有門檻上限、crowd、ignore 等分支，不能概括所有工具與邊界。

本頁固定框 JSON 明訂採 ≥；主例子的 2/3 不等於 0.5 或 0.7，兩種判法結果一致。
:::

### 從重疊分數到偵測結果（補充）

IoU 只看幾何，正確偵測還需要類別吻合。一般一對一評估中，同一個真實物體不能讓兩個重複預測都算 TP；下表假設沒有忽略區域或特殊群聚標註。

| 狀況 | 評估結果 |
|---|---|
| 同類且達門檻，成功配對 | 預測算 TP |
| 類別錯、未達門檻，或目標已被別框配對 | 這個預測算 FP |
| 真實目標沒有配到任何合格預測 | 這個真實目標算 FN |

主例子只有一個真實物體與 B1，類別都是刮痕。門檻 0.5 時 2/3 達標，得到 TP=1；門檻 0.7 時不達標，得到 TP=0、FP=1、FN=1。

信心分數是模型對預測的評分，IoU 門檻則是評估定位的標準。B1 的信心為 0.9，不會讓 IoU 從 2/3 變大；改門檻也不會移動框。

### 換個場景

| 場景或資料條件 | 怎麼用 IoU |
|---|---|
| 影像分割，邊界模糊或物體重疊 | 比較預測區域與標註區域；依同一標註規則解讀邊界 |
| 零售動線分析 | 指引列有此指標，實際使用前要先明示區域的定義 |
| 製造瑕疵定位（補充） | 本頁主例子；比較刮痕框是否貼合目標 |
| 交通影像（補充） | 比較車輛預測框與真實框，另檢查類別與配對規則 |

:::supplement[來源：Torchvision box_iou API]
指引把邊界模糊或物體重疊列為適用情況，並給予較高的可靠性評價；這不表示標註歧義會自行消失。IoU 只計算給定區域的重疊，仍須先統一標註規則，再比較結果。
:::

### 固定框集的兩個匹配門檻（補充）

以下五個預測是同一張 I1 影像同時輸出，沒有先依信心刪框，也不是上方 B1–B3 的替代方案。

真值 G1=刮痕(0,0,10,10)、G2=刮痕(20,0,30,10)、G3=凹痕(40,0,50,10)。

依信心由高到低，找同類、未使用且 IoU 最大的真值；採 IoU **大於或等於**門檻，同一真值至多用一次。

本例無 crowd 或忽略區域。

| 預測／信心／框 | 幾何對象及 IoU | 門檻0.5 | 門檻0.7 |
|---|---|---|---|
| P1／0.99／(0,0,5,10) | G1：50/100=0.5 | TP→G1，恰等 | FP，未達 |
| P2／0.95／(20,0,27,10) | G2：70/100=0.7 | TP→G2 | TP→G2，恰等 |
| P3／0.90／(0,0,10,10) | G1：1 | FP，G1已使用 | TP→G1 |
| P4／0.85／(60,0,70,10) | 所有真值：0 | FP，無匹配 | FP，無匹配 |
| P5／0.80／(40,0,50,10) | G3：1，但預測刮痕 | FP，類別錯 | FP，類別錯 |

兩門檻均為 TP=2、FP=3、FN=1，未匹配的 G3 都是 FN。

P1 與 P3 卻互換成敗，說明提高門檻是定位要求更嚴，不保證總分必變或必升；也不能沿用舊配對，須從同一固定框集重新跑一次。

若規約改成嚴格大於，P1 的0.5及P2的0.7邊界都要重判，不能混用。

同類與一對一、等號規則依 COCOeval 的配對機制整理；這只是教學匹配，不宣稱重現完整 COCO AP。AP／mAP 的完整規則請讀 [[detection-map]]。

### 零售任務的指標導讀

沿用[多模態零售的同一案例](../multimodal-application-evaluation/#零售讓每個輸出有對應物件)：影像、銷售用來比較動線熱區與配置，先定義區域再用[IoU](../intersection-over-union/#從框座標求交集補充)。

交易、評論產生推薦清單，先定相關性與清單長度再看[Precision](../precision/#定義與公式)。

評論、社群做情感分類，固定類別與平均方式後看[F1](../f1-score/#多分類的平均方式補充)。

BI 整合影像、POS、評論，應分別驗收各項輸出。

顧客隱私、來源噪聲及處理時效也須另驗：遮蔽或噪聲可能影響區域及分類，離線分數高仍可能回應太慢。

IoU 不能評推薦命中，F1 不能取代幾何定位，Precision 也不能代表整個儀表板品質。

## 常見誤解

- **只要把真實框包住就得高分。** 過大的預測增加聯集，本例 B2 只有 0.25。
- **IoU 就是整個模型的準確率。** 它量兩個區域的重疊，不等於全部樣本判對比例。
- **IoU=1 一定算 TP。** 類別錯或重複配對仍可能算 FP。（補充）
- **提高 IoU 門檻代表模型改善。** 框與模型都沒改，只是定位要求更嚴；比較成績時須固定相同評測規則。（補充）

## 進階

### IoU 與 mAP 的關係（補充）

先固定 IoU 門檻與配對規則，按信心分數排序預測，再累計各類的精確率與召回率，可得到各類的 AP。mAP 是對類別做平均的摘要，不是把每個框的 IoU 直接取平均。

固定預測與其他規則時，提高 IoU 門檻會讓定位要求更嚴；部分原本命中的框可能變成 FP，目標也可能成為 FN。精確率、召回率與 AP 因而可能下降，跨類別平均的 mAP 通常也會較低。

COCO 標準評估還會對 0.50 到 0.95、每隔 0.05 的 IoU 門檻作彙整。AP 的插值、忽略區域與偵測數上限等依基準規約，不能直接套用任意 PR 曲線積分代替。

## 小結

- IoU 是交集除以聯集，聯集須扣掉重複計入的交集；本例為 320/480≈0.667。
- 從座標算面積前，先確認格式、單位與邊界約定；不相交的交集為 0。
- IoU 門檻判定定位是否達標，信心閾值決定保留哪些預測，兩者不同。
- 正確偵測還需要類別正確與配對成功；提高評估門檻不會讓模型的框自動改善。

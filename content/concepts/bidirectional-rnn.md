## 為什麼需要

有些詞語要讀到後文才容易判斷角色。只往前讀的 RNN，在某個位置的狀態還沒有看過後面的輸入。

雙向遞迴神經網路（Bi-RNN，英文為 Bidirectional RNN）在同一段輸入上設兩個方向的網路。它把正向與反向狀態結合，供每個位置利用前後文，常用於命名實體辨識。

## 直覺

正向從第 1 點讀到第 4 點；反向則從第 4 點讀回第 1 點。同一位置因此有兩份摘要，分別帶著前方與後方的脈絡。

![位置 2 的反向摘要會讀到位置 3、4；整段何時可取得決定能否使用。](figure:l23203-bidirectional-rnn-context)

:::supplement[來源：Dive into Deep Learning 10.4]
圖中的「未來」是相對於序列位置，未必晚於實際決策時間。歷史視窗裡較後面的點可能早已觀測完成；即時警報所需的後續量測則可能還沒發生。
:::

## 定義與公式

兩個方向各依自己的時間順序更新隱藏狀態，再把對應位置的結果合併。

:::supplement[來源：PyTorch RNN 文件；Dive into Deep Learning 10.4]
反向 RNN 的前向計算，與訓練時的 BPTT 是兩件不同的事。

常見合併方式是串接，兩個方向通常各有一套參數。若每方向寬度都是 2，同一位置串接後寬度為 4；不是把時間長度變成兩倍。

雙向描述資訊方向，單元仍可選基本 RNN、LSTM 或 GRU。BiLSTM 指兩個方向都使用 LSTM，並非另一種門控公式。
:::

## 走一次流程（補充）

共用能源與醫療各有 20 時點，首個視窗皆為第 1～4 點。先用同一視窗分辨三種任務：

1. 離線逐點標註：收完第 4 點後，再判斷第 2 點的狀態；第 3、4 點已存在，可供反向讀取。
2. 即時逐點警報：第 2 點就要決策；第 3、4 點尚未發生，不能用完整視窗產生這個警報。
3. 下一點預測：第 4 點收齊後預測第 5 點；可以雙向編碼已知的第 1～4 點，但不得加入第 5 點量測。

能源的前四天是 100、110、120、130 kWh；醫療的前四點是 60、62、64、66 次／分。兩者換算後都是 0、0.1、0.2、0.3，資訊可用性的判斷完全相同。

## 程式（補充）

用每方向寬度 2 的基本 RNN 示範，所有權重固定為 0.5、無偏差。先取得雙向輸出。

```python
import json, os
from pathlib import Path
import torch
root = Path(os.environ.get("IPAS_REPO_ROOT", "."))
d = json.loads((root / "content/examples/L23203-F-sequences.json").read_text(encoding="utf-8"))
torch.manual_seed(d["seed"])
x = torch.tensor(d["first_windows"])
m = torch.nn.RNN(1, 2, bias=False, batch_first=True, bidirectional=True)
with torch.no_grad():
    for p in m.parameters():
        p.fill_(0.5)
    a, h = m(x)
print("序列與末端:", tuple(a.shape), tuple(h.shape))
```
```text
序列與末端: (2, 4, 4) (2, 2, 2)
```

只改第 4 點，再比較第 2 點的兩個方向。陣列索引從零開始，所以第 2 點是索引 1。

```python
changed = x.clone()
changed[:, 3, 0] += 0.5
with torch.no_grad():
    b, _ = m(changed)
print("第2點正向相同:", torch.equal(a[:, 1, :2], b[:, 1, :2]))
print("第2點反向相同:", torch.equal(a[:, 1, 2:], b[:, 1, 2:]))
```
```text
第2點正向相同: True
第2點反向相同: False
```

:::tip[讀碼重點]
輸出的前兩個特徵是正向，後兩個是反向。第 4 點改變後，第 2 點反向表示也改變，證明它確實使用了後文；正向表示則不受影響。
:::

## 怎麼用、怎麼判讀

命名實體辨識等上下文敏感任務，可在完整句子已取得時使用雙向狀態。判斷模型是否可用，必須把輸入可取得的時間與輸出期限一起看。

:::supplement[來源：Dive into Deep Learning 10.4]
若系統容許延遲，可能等後續片段到齊再輸出；這會改變任務的時間條件，需要明確說出等待多久。模型不會預先知道尚未觀測的資料。
:::

### 換個場景

| 場景 | 上下文條件 | 判讀重點 |
|---|---|---|
| 命名實體辨識 | 完整句子已收到 | 前後詞語皆可利用 |
| ELMo 語境詞向量 | 雙向 LSTM 讀取前後文 | 相同詞彙可依語境得到不同表示 |
| 能源預測（補充） | 歷史視窗已收齊 | 不加入預測目標時點 |
| 醫療即時警報（補充） | 當下就需輸出 | 不偷用稍後量測 |
| 錄製影片標註（補充） | 完整影片已存在 | 與即時串流的條件不同 |

## 常見誤解

- 「雙向就是 BPTT。」雙向描述前向計算時讀取序列的方向，BPTT 是訓練時反傳。（補充）
- 「時間序列永遠不能用雙向。」決策時已知的歷史視窗可以雙向編碼。（補充）
- 「雙向模型能看到尚未發生的量測。」它只能使用實際提供的輸入。（補充）

## 小結

- 正向與反向網路提供同一位置的前後文資訊。
- 雙向處理與反向傳播是不同概念。（補充）
- 使用前先確認整段輸入是否已在決策時取得。
- 歷史視窗可雙向編碼；尚未取得的目標量測不可加入。（補充）

## 為什麼需要

能源需求、振動與語音都帶順序。把每週或每個聲音片段當成互不相關的樣本，可能失去趨勢、短期變化與前後相依。

序列模型的選擇（Sequence Model Selection）不只看模型能否讀序列。還要問可用歷史多長、預測多遠、資料是否支持統計假設，以及訓練與推論能花多少資源。

## 直覺

RNN 把歷史接進狀態；LSTM 與 GRU 用門控調整資訊保留。TCN 用沿時間的卷積讀歷史；ARIMA 則用過去值、差分與誤差結構描述序列。

:::supplement[來源：Forecasting: Principles and Practice 第 5 章；Bai 等人 2018 第 3 節]
用時間序列交叉驗證比較候選時，先把一條垂直線放在預測起點。線左側是當時已知資訊，線右側是未來目標；換模型時，這條線與預測期應保持一致。
:::

![三摺都向後續週驗證，增加視窗只向歷史延伸，不移動第一個預測目標。](figure:l23302-sequence-model-selection-window)

## 定義與公式

指引把 RNN、LSTM、GRU、TCN 與 ARIMA 列為序列任務的候選。以下比較的是選型條件，不是固定的優劣排名。

| 模型族 | 讀歷史方式 | 要先確認什麼 |
|---|---|---|
| RNN | 逐步更新共享狀態 | 長序列訓練可能有梯度問題 |
| LSTM、GRU | 門控狀態更新 | 資料與資源是否支持較多參數 |
| TCN | 時間方向卷積 | 指引強調長期相依的穩定性，仍須確認可見歷史 |
| ARIMA | 過去值與誤差的統計結構 | 差分、季節性及殘差是否合適 |

:::supplement[來源：Bai 等人 2018 第 3 節；statsmodels ARIMA 文件]
TCN 的可見歷史受感受野與視窗限制，穩定性不代表無限記憶或保證學會。它可在訓練時平行計算多個時間位置，但不表示任何硬體上都比 GRU 快。

ARIMA 的非季節部分不會自動處理固定季節週期，需另設季節項或比較其他季節基準。
:::

## 走一次流程

### 共用起點與三摺驗證（補充）

`L23302-A-weekly.json` 兩領域各 104 週，預測期固定為下一週。能源預測耗電，製造預測振動；兩者共用索引、種子 23302 與三摺時間序列交叉驗證的訓練截止點。

同一份製造資料也可轉成下週是否故障的分類視圖，見任務與模型配對；本頁固定比較振動量的迴歸視圖。

| 摺 | 訓練週 | 驗證目標週 | 第一個八週輸入 |
|---|---|---|---|
| 1 | 1–52 | 53–64 | 45–52 |
| 2 | 1–64 | 65–76 | 57–64 |
| 3 | 1–76 | 77–88 | 69–76 |

1. 先以最後值或簡單統計模型建立基準，再比較 GRU 與 TCN。
2. 每摺只以訓練週擬合縮放及模型，權重在該摺驗證期間固定。
3. 驗證逐週前進，下一週預測可讀剛公布的上一週實際值；不能事先讀完整驗證期。
4. 選定方案後用第 1–88 週重訓，最後第 89–104 週保留獨立測試。

第一個目標同是第 53 週，八週視窗讀 45–52，十六週視窗讀 37–52。比較視窗本身時，也可把訓練目標統一成第 17–52 週，共 36 筆，避免把樣本數差異誤認為視窗效果。

本組候選卡是固定模擬分數，用來練習讀表，沒有訓練出效能排名。資料取得規則與輸出目標一致，才有比較意義。

## 程式（補充）

這段只核對視窗與樣本數，沒有估計任何模型效果。

```python
import json, os
from pathlib import Path
root = Path(os.environ.get("IPAS_REPO_ROOT", "."))
d = json.loads((root / "content/examples/L23302-A-weekly.json").read_text(encoding="utf-8"))
for width in (8, 16):
    train_targets = list(range(width + 1, 53))
    first_input = list(range(53 - width, 53))
    print(f"視窗 {width}: 訓練 {len(train_targets)} 筆，輸入 {first_input[0]}–{first_input[-1]}，目標 53")
print("共同訓練目標:", len(range(17, 53)))
```
```text
視窗 8: 訓練 44 筆，輸入 45–52，目標 53
視窗 16: 訓練 36 筆，輸入 37–52，目標 53
共同訓練目標: 36
```

:::tip[讀碼重點]
`range` 不含右端點，因此輸入截止第 52 週。這裡先用原始週數字表示索引，讀 JSON 陣列時才減 1。
:::

## 怎麼用、怎麼判讀

若資料少、先看短期趨勢，可從統計基準起步；多變量且非線性相依強時，再比較門控 RNN 與 TCN。不要把「可處理長序列」解讀成無限記憶的保證。

### 換個場景

| 場景 | 候選與判讀 |
|---|---|
| 股價預測 | 保留時間順序，確認趨勢與不穩定性；不承諾可獲利 |
| 感測器監控 | 比較局部變化、長期相依及多通道訊號 |
| 語音辨識 | RNN 類或 TCN 可擷取相依，還要搭配辨識輸出設計 |
| 短期、資料少且週期明顯 | 統計模型可當起點，季節性需額外確認 |
| 零售補貨（補充） | 固定一步或多步預測，不能混用兩種分數 |
| 交通車流（補充） | 延遲與尖峰時段誤差也要納入比較 |

:::caution[注意]
指引 5-13 說 ARIMA 適合週期明顯的資料，應連同季節性處理理解。
:::

:::supplement[來源：Forecasting: Principles and Practice 第 9 章]
104 週只有兩個年度循環，仍不足以保證能可靠學出每種年度變化。
:::

## 常見誤解

- 「有時間欄就一定要用深度模型。」落後值配簡單模型也可以建立基準。（補充）
- 「驗證週的實際值永遠不能作為輸入。」逐週一步預測可使用當時已公布的歷史，需先講清取得時間。（補充）
- 「TCN 的視窗加長就一定讀得更遠。」還受感受野限制。（補充）
- 「門控模型一定勝過統計模型。」要以相同目標與資源條件驗證。

## 小結

- 先固定預測期、資訊取得時間與驗證目標。
- 統計假設、歷史相依與資源共同決定候選。
- 長視窗、門控與卷積都需要驗證，沒有固定勝出者。
- 使用時間序列交叉驗證，最後保留獨立測試。

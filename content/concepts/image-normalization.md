## 為什麼需要

同一張影像可以用0到255的整數，也可以用0到1的浮點數表示。模型必須知道自己收到哪一種尺度，否則相同景物也可能變成完全不同的數值輸入。

指引將像素轉為0到1，以及調整至均值0、標準差1，放在同一列介紹。本頁把正規化（Normalization）與標準化（Standardization）分開看。

## 直覺

正規化像換一把刻度不同的尺；標準化則進一步以某個平均位置為中心，以標準差當單位。兩者都改數值，不改像素所在的位置。

### 同一個2×2像素區

M01左上紅通道有0、85、170、255四格。每格仍在原位置，只是模型讀到的數字換了。

![四格像素逐步換成零到一尺度及標準化數值，負值不是處理失敗。](figure:l23301-image-normalization-pixels)

## 定義與公式

### 先辨認原始範圍

指引以0到255轉成0到1說明正規化：像素的位置不動，數字改用較小的尺度。

:::supplement[來源：TensorFlow資料增強教學]

對已知範圍0到255的8位元像素，固定縮放為：

$$
x_{01}=\frac{x}{255}
$$

$x$是原始像素，$x_{01}$是縮放後的浮點數。這不是除以每張圖的最大值；16位元影像、已縮放輸入或有特定物理單位的影像，不能直接套用255。
:::

### 再按通道標準化

指引也列出將數值調整至均值0、標準差1的標準化。它除了換尺度，還把數值的平均位置移到0附近。

:::supplement[來源：Torchvision Normalize；Stanford CS231n資料前處理]

$$
z_c=\frac{x_{01,c}-\mu_c}{\sigma_c}
$$

$c$是通道，$\mu_c$與$\sigma_c$是該通道的指定均值和標準差，$z_c$是輸出。均值與標準差必須跟輸入使用同一尺度，且標準差要大於0。

若使用訓練資料估計參數，訓練端的整體分布才會被調整至均值約0、標準差約1。個別影像、驗證集或新影像不保證有同樣的統計量；預訓練模型則應遵循它的既定輸入契約。
:::

## 算一次

### 兩步處理同一個像素區

先把像素換成0到1尺度，再按設定的均值與標準差轉換；這是兩個不同步驟。

:::supplement[來源：TensorFlow資料增強教學；Torchvision Normalize]

共用校準區為`[[0,85],[170,255]]`。先逐格除255，得到`[[0,1/3],[2/3,1]]`。

本例指定均值0.5、標準差0.25，僅為教學參數。不是拿這四格或全部32張影像估出來的結果。

| 原像素 | 除255 | 再標準化 |
|---|---|---|
| 0 | 0 | (0−0.5)÷0.25＝−2 |
| 85 | 1/3 | (1/3−0.5)÷0.25＝−2/3 |
| 170 | 2/3 | (2/3−0.5)÷0.25＝2/3 |
| 255 | 1 | (1−0.5)÷0.25＝2 |

這四格標準化後平均0，但標準差約1.491，不是1。原因是指定的0.25不是四格本身的標準差；這不表示公式算錯。

零售影像沿用同樣的型別與尺度規則。若改成另估零售領域的參數，必須視為新的訓練設定並記錄，不能只在推論端替換。
:::

## 程式

### 比對兩步轉換與重複縮放（補充）

```python
import numpy as np
x = np.array([[0, 85], [170, 255]], dtype=np.uint8)
scaled = x.astype(np.float32) / 255.0
z = (scaled - 0.5) / 0.25
print(np.round(scaled.astype(float), 3).tolist())
print(np.round(z.astype(float), 3).tolist())
print(f"mean={z.mean():.3f}, std={z.std(ddof=0):.3f}")
print(f"double-scale maximum={scaled.max() / 255:.6f}")
```
```text
[[0.0, 0.333], [0.667, 1.0]]
[[-2.0, -0.667], [0.667, 2.0]]
mean=0.000, std=1.491
double-scale maximum=0.003922
```

:::tip[讀碼重點]
先轉浮點再運算，避免把結果存回整數陣列。本例用float32計算，輸出前轉float64再四捨五入；不把float32表示造成的微小誤差當成算法不同。
:::

## 怎麼用、怎麼判讀

指引把像素數值統一用於影像分類前處理，目的包含提升訓練效率。使用前先確認模型需要的輸入範圍，不能見到影像就固定做兩次轉換。

### 訓練與推論核對清單（補充）

1. 原圖是8位元整數，還是已經轉為0到1？縮放只做一次。
2. 通道是RGB還是其他順序？均值與標準差須對到正確通道。
3. 使用哪版訓練參數或預訓練設定？驗證、測試與推論沿用同一版。
4. 遇到常數通道時，先訂出標準差為0的處理規則，不直接相除。

自己估參數時只用訓練資料，避免資料洩漏。不能用測試集重估均值，再聲稱測試是獨立評估。

### 換個場景

| 場景 | 數值處理重點 | 判讀界線 |
|---|---|---|
| 影像分類的固定輸入 | 指引的數值統一用途 | 依模型要求設定尺度 |
| 製造相機（補充） | 確認曝光與位元深度 | 除255不會修好過曝 |
| 零售OCR（補充） | 同相機同處理版本 | 不在服務端重複縮放 |
| 醫療影像（補充） | 保留量測與顯示契約 | 不能假定所有像素上限255 |

## 常見誤解

### 名稱與數值範圍要分開看（補充）

- **API叫Normalize就是除255。** Torchvision的`Normalize`按均值與標準差轉換；要先確認它收到的尺度。
- **標準化後一定介於0與1。** 輸出可為負，也可大於1，本例範圍為−2到2。
- **每張影像都要平均0、標準差1。** 沿用訓練端參數時，單張影像沒有這項保證。
- **正規化就是正則化。** 前者處理輸入數值，後者限制模型或訓練以減少過擬合。

## 進階

### 平均值到底跨哪些位置（補充）

逐通道估計時通常跨訓練影像及空間位置統計；逐張、逐像素位置、逐通道是不同的規則。只記錄「做過標準化」不足以重現流程，還要記錄統計軸、參數與前處理版本。

## 小結

- 正規化與標準化都改數值，沒有移動像素位置。
- 0到255轉0到1，與減均值再除標準差是不同步驟。
- 鎖定型別、尺度、通道順序與參數版本，才能讓推論沿用訓練設定。（補充）

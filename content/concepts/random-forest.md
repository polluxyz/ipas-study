## 為什麼需要

單棵決策樹容易因資料小幅改變而大幅改動。隨機森林（Random Forest）讓多棵樹從不同資料與特徵角度學習，再平均或整合類別，減少單樹的不穩定。

## 直覺

隨機性有兩個位置：每棵樹重抽訓練樣本，每次節點分裂又只看部分候選特徵。不是只在一開始替整座森林挑一組欄位。

![上半部是每樹重抽樣，下半部是每節點候選特徵；兩種隨機化發生在不同位置。](figure:l23202-random-forest-two-randomness)

多棵樹可分別訓練，最後才合併輸出。迴歸平均連續預測；指引以多數票解釋分類。

## 定義與公式

對同一房屋，三棵樹若給100、110、120，森林的迴歸預測為110。這個三樹示意沿用前置教材，平均公式詳見Bagging策略。

本頁不重列整合公式，重點是分清每樹重抽樣與每節點抽特徵，以及硬投票和機率平均的差異。

:::supplement[來源：scikit-learn Ensembles §Forests of randomized trees]
`RandomForestClassifier`先平均各樹的類別機率，再選最大機率類別。這與先將每棵樹變成硬類別再投票不一定相同，必須分清題目或API給哪種輸出。
:::

### 重要性與外推

森林可以列出特徵重要性，但整體有許多路徑，較難像單樹那樣逐條展示。樹數增加，也會增加模型體積與預測工作量。

:::supplement[來源：scikit-learn Ensembles §Feature importance evaluation]
常用的不純度重要性偏好較多候選切分的特徵；高度相關的特徵也會分攤重要性。重要性不能證明因果，可另用保留資料的置換重要性檢查。

一般平方誤差迴歸樹輸出訓練葉內平均，森林再平均這些值。因此遇到超過訓練面積範圍的豪宅，不會像線性模型那樣自然延伸價格趨勢。
:::

## 走一次流程

### 共用資料與三樹輸出（補充）

房價與授信各100筆，索引、60／20／20切分與種子23202和Bagging策略相同。房價三欄為面積、屋齡、區域；授信三欄為收入、負債比、年齡。

1. 房價每棵樹有放回抽60次；每節點從三個特徵抽兩個作候選。
2. 同一驗證房屋的三樹價格約102.929、100.250、56.296，平均86.492。
3. 授信第一筆驗證個案，各樹違約機率為0.266667、0、0，平均0.088889，閾值0.5下判正常。
4. 若另給示意硬票「違約、違約、正常」，則多數票選違約；不把它混稱為前一步的實測輸出。

這筆房屋的三樹輸出碰巧與Bagging相同。第三筆驗證房屋就不同：森林約170.410，Bagging約176.843；單筆相同不代表兩種建模流程相同。

### 單樹與森林的取捨

單樹可以展示一條從根走到葉的判斷路徑；森林要彙整許多路徑。指引強調森林可降低單樹過擬合風險，適合高維與複雜結構，但仍須驗證泛化效果。

![房價版示意：單樹沿條件走到葉；三樹硬類別為高價、高價、一般時，投票以二比一選高價。](figure:l23202-decision-tree-branch-vote)

## 程式（補充）

用共用授信資料檢查「機率平均」；違約標籤1是教學規則產生，並非真實授信評分。

```python
import numpy as np
from sklearn.ensemble import RandomForestClassifier
i = np.arange(100)
income, debt, age = 30+i*11 % 91, (i*7 % 61)/100, 22+i*3 % 40
X = np.column_stack([income, debt, age])
y = ((debt>.35) & (income<90) | (income<45)).astype(int)
tr, va = i[i % 5 < 3], i[i % 5 == 3]
m = RandomForestClassifier(n_estimators=3, max_depth=2,
    max_features=2, random_state=23202, n_jobs=1).fit(X[tr], y[tr])
p = [t.predict_proba(X[va[:1]])[0, 1] for t in m.estimators_]
print("三樹機率", np.round(p, 6).tolist())
print("森林前三筆", np.round(m.predict_proba(X[va[:3]])[:, 1], 6).tolist())
```
```text
三樹機率 [0.266667, 0.0, 0.0]
森林前三筆 [0.088889, 0.666667, 0.0]
```

:::tip[讀碼重點]
`max_features=2`明訂節點候選數，避免依賴不同任務的預設值。`bootstrap=True`才採本頁的有放回重抽樣。
:::

若抽到的候選特徵無法形成合法分裂，實作可能繼續檢查更多特徵；`max_features=2`不保證任何節點都只檢查兩欄。

## 怎麼用、怎麼判讀

森林適合非線性、特徵交互作用，以及數值和類別資訊混合的任務。類別欄如何編碼仍依實作而定，不能把指引的混合特徵能力理解為任何文字都能直接餵進API。

不平衡程度很高時，森林仍可能偏向多數類。醫療診斷若需要精確機率，也要檢查機率品質，不能只看類別判對多少。

### 換個場景

| 場景／資料條件 | 使用方式 | 判讀重點 |
|---|---|---|
| 房價、銷售量 | 森林迴歸 | 多樹平均與泛化 |
| 中大型、非線性混合特徵 | 比較多樹模型 | 解釋性、記憶體與延遲 |
| 高維複雜分類 | 整合分類樹 | 仍可能偏向多數類 |
| 醫療診斷機率 | 機率預測 | 類別正確不代表機率準確 |
| 授信（補充） | 預測違約機率 | 重要性不能當拒貸因果理由 |
| 設備維護（補充） | 故障分類 | 相同設備資料須避免跨組洩漏 |

## 常見誤解

- 樹更多不保證重要少數類別的召回率更高。
- 森林能給重要性，不等於整體模型與單樹一樣容易解釋。
- 節點候選特徵是每次重新抽，不是全森林永遠同一組。
- 不純度重要性與因果影響不同；迴歸森林也不擅長延伸訓練範圍外的趨勢。（補充）

## 小結

- 每樹重抽樣、每節點抽候選特徵，兩個層次要分開。
- 迴歸平均；分類整合方式要依題目與實作確認。
- 森林通常較穩定，代價是整體解釋與資源成本。
- 重要性不代表因果，模型也不能保證可靠外推。（補充）

## 為什麼需要

框能定位整個人，卻無法告訴我們手腕或膝蓋在哪裡。要估計姿態，必須先定義可重複標記的身體節點，才能取得各點的座標。

關鍵點標註（Keypoint Annotation）用點位座標表達這些目標。先確定「這是哪一個點」，再處理「它在什麼位置」。

## 直覺

每個物件都像有一張固定的點位清單。要比較姿態或位置，就先讓每一筆座標都對應明確的點名。

下面的人體面板使用 T01 的三個教學點；製造面板用 M01 的孔位與缺口。積木只供格式練習，不描述真實人體解剖或工業尺寸。

![先對照下方點序，再看實心或空心的狀態；未標點的佔位座標不應被畫成真的原點。](figure:l21102-keypoint-annotation-visibility)

## 定義與公式

### 點位名稱與座標

關鍵點可以是人體節點，也可以是任務定義的特定點位。姿態估計常用身體各點的位置表達動作，與整圖類別、物件框的資訊不同。

### 本例的可見性約定（補充）

每個點存成 `(x,y,v)`。原點、方向與單位沿用〈影像標註與品質規範〉頁的約定；x 向右、y 向下，可用小數表示點位，v 是可見性（Visibility）狀態。

本例借用 COCO 標準答案的三種狀態，但只選三個教學點，不是 COCO 完整人體點集。

| v | 意義 | 座標怎麼存 |
|---|---|---|
| 0 | 未標記，沒有可靠位置 | 用 (0,0) 佔位，讀取時忽略 |
| 1 | 已標記，但影像中不可見 | 依規範記可靠推定的位置 |
| 2 | 已標記，影像中可見 | 記實際觀察到的位置 |

被遮擋不必然能推定位置。只有規範允許且能可靠定位時才用 v=1；無法定位時用 v=0，不能為填滿表格亂猜。

點位清單採固定順序。即使某點沒有可靠位置，也保留欄位並記未標狀態，避免後續座標對錯點名。

## 走一次流程

### 人體：T01 的第一名行人

本例行人背對鏡頭，固定順序是頭、左腕、右腕；左右依被標註者本人，所以左腕也在畫面左側。這只是縮小版的教學規格，不要求把每種姿態都壓成三個點。

| 點序與名稱 | x | y | v |
|---|---|---|---|
| 1 頭 | 1.5 | 1.5 | 2 |
| 2 左腕 | 1.2 | 2.5 | 2 |
| 3 右腕 | 2.8 | 2.5 | 1 |

先找到人，再依固定點名標記。右腕位置可依本例規則推定，但不能把 v 改成 2；遮擋資訊仍須保留。

### 工業：M01 的第一個零件（補充）

換成工業定位，清單改為左孔、右孔、缺口。M01 的缺口沒有可靠點位，因此保留未標記欄位，不把後面的點往前挪。

| 點序與名稱 | x | y | v |
|---|---|---|---|
| 1 左孔 | 1.5 | 1.5 | 2 |
| 2 右孔 | 2.5 | 1.5 | 2 |
| 3 缺口 | 0 | 0 | 0 |

點表與物件 ID 綁在一起，才知道這是哪個人的右腕、哪個零件的孔。兩個物件若共用一份沒有 ID 的點清單，就會失去對應關係。

## 程式（補充）

這段依固定順序列出 T01、M01 的點表，再核對點數、範圍與可見性。三元組沒有點名，因此程式無法自動抓出對調點位；v=0 的座標也不能當定位結果。

```python
people = [(1.5, 1.5, 2), (1.2, 2.5, 2), (2.8, 2.5, 1)]
parts = [(1.5, 1.5, 2), (2.5, 1.5, 2), (0, 0, 0)]
for name, points in [("人體", people), ("零件", parts)]:
    assert len(points) == 3
    for x, y, v in points:
        assert v in (0, 1, 2)
        assert (x == y == 0) if v == 0 else (0 <= x < 8 and 0 <= y < 6)
    counts = [sum(v == state for _, _, v in points) for state in (0, 1, 2)]
    print(name, "未標/遮擋/可見:", counts)
```
```text
人體 未標/遮擋/可見: [0, 1, 2]
零件 未標/遮擋/可見: [1, 0, 2]
```

:::tip[讀碼重點]
先依 v 分流，再檢查座標。不能把 v=0 的 (0,0) 當成有效點；v=1 有座標，但仍不可視為影像中可見。
:::

## 怎麼用、怎麼判讀

人體姿態需要事先定義哪些身體點位要標，而非任意挑幾個容易看到的點。工業定位也先指定可重複辨認的位置，再決定數量、順序與精度要求。

:::supplement[來源：CVAT Annotation with skeletons；TorchVision Keypoint R-CNN 輸入契約；核心延伸：標註格式與模型讀取的界線]
三狀態表達的是資料語意，不保證模型把 v=1、v=2 分開處理。轉入框架前要查輸入契約；若讀取端只分「有標／未標」，就明確記錄轉換規則。

人體的左右以被標註者為準；工業零件可改以產品基準方向定義。翻轉影像時，座標與左右點名都要同步轉換。
:::

### 換個場景

指引明列人體姿態估計與「身體節點或特定點位座標」，未規定完整點集或可見性編碼。點名、狀態與下列工業情境是把資料規格補完整的教學例。

| 場景 | 點位定義 | 容易混淆之處 |
|---|---|---|
| 人體姿態估計 | 肩、肘、腕等身體節點 | 不能只標整個人的框 |
| 製造定位（補充） | 左孔、右孔、缺口 | 以產品基準方向定義左右 |
| 動物動作分析（補充） | 鼻端、四肢關節 | 需要適合物種的點集 |
| 農業採摘（補充） | 果梗連接點 | 遮擋時無法可靠定位就留未標狀態 |

## 常見誤解

- **框中心就是所有關鍵點。** 點位有自己的語意定義，不等於物件中心。
- **有座標就是可見。** 本例的 v=1 仍代表不可見。（補充）
- **點缺了就刪掉欄位。** 固定順序的資料要保留佔位，否則名稱會錯配。（補充）

## 進階

### 點位與特徵點的差別（補充）

人工視覺特徵中的 SIFT、ORB 尋找適合外觀比對的位置；這裡的點則事先指定語意，例如左腕。兩者都能有座標，但解決的是不同問題。

## 小結

- 先定義點名、點序與物件對應，再記座標。
- 可見、遮擋但已標、沒有標記，是不同狀態。
- 人體與工業都可用點位標記，但點集與基準方向要各自定義。
- 轉進模型前查輸入契約，不假設所有工具都使用同樣的狀態編碼。

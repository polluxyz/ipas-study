## 為什麼需要

同一個需求可以寫成「查配送」或「查運送」。訓練文字太少時，模型可能只記住常見寫法，遇到另一種表達就判錯。

文字增強（Text Augmentation）用替換、插入、刪除或交換詞語增加變化。指引列出的用途包括情感分析、主題分類與對話模型訓練。

## 直覺

把一句話換個說法，讓模型看到更多表達方式。

![四種局部變換都從原句出發；產生候選後，再依任務檢查語意與標籤。](figure:l23301-text-augmentation-transforms)

:::supplement[來源：Wei 與 Zou（2019）EDA 第 2 節]
「字不同」與「意思相同」是兩件事。主題可能仍是退款，情感卻由滿意變成不滿；同一種增強，對不同任務未必都能沿用標籤。
:::

## 定義與公式

指引介紹四種局部變換：同義替換、隨機插入、隨機刪除、隨機交換字詞位置。它們都改動現有文字。

:::supplement[來源：nlpaug BackTranslationAug；Sennrich 等人（2016）第 3.2 節]
反向翻譯（Back-Translation，下文簡稱回譯）有兩種常見教學情境，須看清任務方向。

| 情境 | 生成方向 | 得到什麼 |
|---|---|---|
| 中文分類的回譯增強 | 中文 → 英文 → 中文 | 同語言改寫候選，仍須檢查標籤 |
| 英翻中模型的語料擴充 | 原中文 → 合成英文 | 合成英文與原中文的配對 |

後者稱為偽平行語料：兩端語意相對應，但英文端是機器生成，不是人工翻譯。不是把兩種語言隨便並排，也不必再翻回中文才能建立配對。
:::

## 走一次流程

### 先比較局部變換

同義替換改詞語，隨機插入、刪除與交換則改動原句的組成或詞序。

:::supplement[來源：Wei 與 Zou（2019）EDA 第 2 節；本組教學例句]
共用客服資料有 24 句，C01–C16 為訓練，C17–C20 為驗證，C21–C24 為測試。先取訓練句 C03：「我不想退款，只想查 Q7 的配送。」

下表固定展示一次操作結果，方便比較；實際隨機增強會產生不同候選。

| 方法 | 候選句 | 判斷 |
|---|---|---|
| 同義替換 | 我不想退款，只想查 Q7 的運送。 | 配送需求未變 |
| 隨機插入 | 我不想退款，只想查 Q7 的配送，謝謝。 | 多了禮貌語 |
| 隨機刪除 | 我想退款，只想查 Q7 的配送。 | 否定遺失，需求衝突 |
| 隨機交換 | 我只想退款，不想查 Q7 的配送。 | 意圖反轉 |

再看一個情感換景：「這次配送我不滿意」刪除「不」後，變成「這次配送我滿意」。主題仍是配送，情感卻由負面變成正面，不能沿用負面標籤。

情感任務還要檢查褒貶與強度；主題任務要檢查真正談論的對象。不能以「仍出現配送」就判定每種標籤都沒變。
:::

### 再走一次回譯（補充）

1. 以 C03 為輸入，固定中介譯文為 `I do not want a refund; I only want to check delivery for Q7.`。
2. 回到中文：「我不需要退款，只想查詢 Q7 的配送進度。」
3. 核對否定、Q7 型號、配送意圖，再確認分類標籤仍適用。
4. 保留來源索引 C03，合格候選只加入訓練集。

共用資料另放兩個拒收例：C01 回譯漏了「不」，C02 把 Q7 變成 Q1。即使安全升級標籤仍為 1，也不能把語意錯誤的候選當成合格資料。

若要訓練英翻中，就把步驟 1 的合成英文與原始 C03 中文配對；原中文是目標端。這和把步驟 2 的回譯中文拿去做分類，是兩種用途。

驗證與測試的工作是檢查未見資料表現。C03 的原句、譯文與回譯句同源，不能分散到訓練與驗證兩邊。

## 程式（補充）

以下摘出共用 JSON 的三筆固定回譯與人工複核結果，不呼叫翻譯服務。`keep` 是人工決定，不是程式自動證明語意一致。

```python
train = set(range(1, 17))
validation, test = range(17, 21), range(21, 25)
candidates = [
    (3, "我不需要退款，只想查詢 Q7 的配送進度。", True),
    (1, "Q7 已冒煙，我想退款，請立即停用檢查。", False),
    (2, "Q1 漏電，請立即安排安全檢測。", False),
]
for index, back, keep in candidates:
    assert index in train
    print(f"C{index:02}", "保留" if keep else "退回", back)
print("驗證、測試原句數", len(validation), len(test))
```
```text
C03 保留 我不需要退款，只想查詢 Q7 的配送進度。
C01 退回 Q7 已冒煙，我想退款，請立即停用檢查。
C02 退回 Q1 漏電，請立即安排安全檢測。
驗證、測試原句數 4 4
```

:::tip[讀碼重點]
索引指向原始訓練句，候選保留人工複核結果。程式只展示資料流；單靠字串相似度不能替代語意與標籤判定。
:::

## 怎麼用、怎麼判讀

先從指引列出的四種局部變換開始，依情感、主題或對話任務選擇。

:::supplement[來源：Wei 與 Zou（2019）EDA 第 2 節；nlpaug BackTranslationAug]
同義替換要注意領域詞；插入不應新增事實；刪除要保留否定與關鍵實體；交換要避免改變修飾關係。回譯也只是候選產生器，不是自動保證正確的標註器。

比較增強前後模型，固定原始驗證集與指標。資料量增加卻讓語意或類別混亂，可能反而降低泛化能力。
:::

### 換個場景

| 場景／資料條件 | 可比較的方法 | 判讀重點 |
|---|---|---|
| 情感分析 | 同義替換、插刪 | 留意情緒詞與否定 |
| 主題分類 | 替換、交換詞語 | 留意主題實體與關係 |
| 對話模型訓練 | 多種表達變體 | 留意需求與回覆是否對應 |
| 客服查詢（補充） | 固定回譯候選 | 型號、退款否定是否保留 |
| 醫療紀錄（補充） | 小幅同義改寫 | 不得把未發燒改成發燒 |
| 法律條款（補充） | 人工複核的改寫 | 不得改變禁止、許可與例外 |

## 常見誤解

- **插刪字詞只是改長度。** 刪除否定、交換修飾位置，都可能改變標籤。（補充）
- **回譯後標籤相同就能全收。** 還要確認專有名詞與完整意思。（補充）
- **合成英文就是人工平行語料。** 它來自模型，須留下來源與複核紀錄。（補充）

## 小結

- 文字增強讓訓練資料包含更多表達方式。
- 替換、插刪、交換要依任務檢查語意與標籤。（補充）
- 回譯改寫與翻譯訓練的偽平行語料，要分清生成方向。（補充）
- 同源變體留在同一訓練集合，驗證與測試保持獨立。（補充）

## 為什麼需要（補充）

多模態模型若只見過完整輸入，部署時少一張影像就可能失效。模態缺失（Missing Modality）指某整路輸入不可用；品質低到不宜採信，也可依規則視為不可用。

指引 3-80～3-81 介紹對齊與資料品質，但未展開缺失模態的訓練及回退。本頁依 HeMIS 的缺失模態方法與多模態綜述，補足可靠性設計所需的深度。

## 直覺（補充）

把每種來源都帶上一個「是否可用」標記。缺文字不等於文字內容為零，缺感測值也不等於設備停止運轉。

![訓練時遮掉來源並保留可用標記；推論依核可組合走融合或人工路徑。](figure:l21104-missing-modality-routes)

圖中右側的「人工」是本例回退規則，不是所有缺失都一定要人工。能否改用單模態模型，要先有該路徑的訓練與驗收證據。

## 定義與公式（補充）

本組固定遮罩順序為影像、文字、感測；1 表示可用，0 表示不可用。101 代表有影像和感測、沒有文字，000 代表三路都不可用。

模態遮罩訓練（Modality Dropout）在訓練時刻意移除某些來源，讓模型學習較少輸入的情境。它遮掉的是整路模態，不等於一般 Dropout 只關閉部分神經元。

| 策略 | 如何處理缺失 | 代價或限制 |
|---|---|---|
| 零填補＋遮罩 | 保持輸入形狀，另告知缺失 | 零不能被誤認成有效量測 |
| 模態補全 | 用已有來源估計缺的資料 | 可能產生虛假細節，須保留估計標記 |
| 捨棄樣本 | 只處理完整輸入 | 減少服務覆蓋，也可能造成選擇偏差 |
| 可用分支／回退 | 僅組合可用來源或切換模型 | 每條路徑需獨立驗證 |

HeMIS 示範各模態先獨立編碼，再彙整可用分支的特徵，訓練時也移除部分模態。這提供可用來源集合的設計思路，不代表其醫學影像結果能直接套到工廠。

### 缺失不一定隨機（補充）

雨天可能同時讓影像模糊並增加交通風險。只隨機刪來源的訓練，可能沒有涵蓋這種「越重要時越容易缺」的組合。

因此要查缺失原因、持續時間、裝置與環境。訓練若使用補全模型或縮放參數，也只能由訓練集估計，不能偷看測試集真值。

## 走一次流程（補充）

共用例子 `L21104-B-events.json` 自訂四種核可組合：111、110、101、011。假設它們已完成驗證，其他組合轉人工；這是示範政策，沒有宣稱實務已通過驗收。

1. F19 影像可用、文字缺失、振動可用，遮罩為 101；先查時間及品質，才接受這兩路。
2. 模型訓練時應涵蓋 101，或準備另行驗證的雙分支模型。只在推論時突然改輸入，不算處理完成。
3. 本例對可用分支分數等權平均：F19 的 0.8 與 0.8 得 0.8，達到自訂 0.5 閾值，輸出需複核。
4. F24 遮罩為 000，沒有可平均的分數，轉人工；不填成 0 後宣告正常。
5. T19 與 T24 換成路口事件，仍沿用相同遮罩規則；是否可採用同一政策，實務須在交通資料重驗。

### 驗證全部組合（補充）

三路輸入有八種組合。先用完整來源的保留樣本依序遮出 111、110、101、011、100、010、001、000，確認路由正確，再量各路徑的錯誤與覆蓋。

本例另外保留原有缺失的測試事件：每領域 8 筆中，111、101、110 各 2 筆、011 有 1 筆、000 有 1 筆。自動處理 7/8=87.5%，另外一筆的人工結果不能算成自動正確。

隨機遮罩測試與自然缺失分組各有用途。前者控制同樣本比較，後者看部署時真正容易缺的條件；還要加入錯時、過期與品質下降的壓力案例。

## 程式（補充）

這段只核對合成事件的路由與筆數，不訓練模型，也不把路由通過解讀成準確率達標。

執行前將環境變數 `IPAS_REPO_ROOT` 設為教材專案的絕對路徑，讓程式能找到共用資料。

```python
import json, os
from pathlib import Path
from collections import Counter
root = Path(os.environ["IPAS_REPO_ROOT"])
d = json.loads((root / "content/examples/L21104-B-events.json").read_text(encoding="utf-8"))
approved = set(d["approved_auto_masks"])
for domain in d["domains"]:
    rows = [r for r in domain["events"] if r["split"] == "test"]
    counts = Counter(r["present_mask"] for r in rows)
    n = sum(r["present_mask"] in approved for r in rows)
    print(domain["id"], dict(sorted(counts.items())), f"自動={n}/{len(rows)}")
print("八組路由:", ["自動" if m in approved else "人工" for m in d["stress_masks"]])
```
```text
factory {'000': 1, '011': 1, '101': 2, '110': 2, '111': 2} 自動=7/8
traffic {'000': 1, '011': 1, '101': 2, '110': 2, '111': 2} 自動=7/8
八組路由: ['自動', '自動', '自動', '自動', '人工', '人工', '人工', '人工']
```

:::tip[讀碼重點]
000 不進入平均；100、010、001 雖有一個來源，本例也未核可自動處理。規則保存在 JSON，兩個領域共用，不能在評分後偷偷更動。
:::

## 怎麼用、怎麼判讀（補充）

同時報告「可自動處理多少」與「自動處理時錯多少」。捨棄困難樣本可能讓正確率上升，服務覆蓋卻下降；兩個數字應並列。

資料恢復後，也要檢查時鐘、校正與版本，避免把舊輸入直接接回融合路徑。需要回退的事件應保留原因及最終處置，供後續查核。

### 換個場景（補充）

| 場景 | 缺失或失效 | 可驗證的回退 |
|---|---|---|
| 醫學影像 | 某種 MRI 序列未取得 | 驗證可用序列模型，證據不足交專家 |
| 工廠巡檢 | 相機故障、文字未上傳 | 核對感測時效，走核可分支或人工 |
| 城市交通 | 雨夜影像模糊、感測中斷 | 依環境分組驗證，保留無法自動處理率 |

前一列是 HeMIS 的研究情境；後兩列是本組換景。它們都不是指引已展開的缺失模態應用。

## 常見誤解（補充）

- 填零就是補全：它最多維持形狀，沒有補回現場證據。
- 生成得像真的就能當真值：生成錯誤也可能看起來合理。
- 隨機遮罩訓練保證任何缺失都可用：仍需依實際缺失與品質分組驗證。
- 自動處理率就是準確率：前者計服務覆蓋，後者計預測對錯。

## 小結（補充）

- 把缺失標記與資料值分開，讓模型知道少了哪些來源。
- 零填補、補全、捨棄與回退各有代價。
- 遮罩訓練後仍要逐組驗證，未核可路徑明確交人工或拒答。
- 分開報自動覆蓋、各組錯誤與最終處置。

## 為什麼需要

one-hot 只把詞分到不同位置，詞袋也不直接表示近義關係。詞嵌入（Word Embedding）利用語料中的關係，把詞放進可比較的連續向量空間。

靜態詞嵌入在訓練後，讓每個詞保有固定向量。Word2Vec 與 GloVe 都屬這條路線，但學習方式不同。

## 直覺

經常出現在相似上下文的詞，可能具有相關用法。本組訂位句中，「訂」與「改」附近都出現「要、明天、的」，可提供學習關係的線索。

![圖只畫手設三維向量的前兩維；判斷三維相似度時，仍須把未畫出的第三維算進去。](figure:l21101-word-embedding-space)

這些座標是人工固定的教學示意，不是小語料訓練成果。真實模型還受語料量、領域與訓練目標影響，不能由「一起出現」直接保證向量距離。

## 定義與公式

分布式詞嵌入從語料學習詞間的語意關聯，讓語意相近的詞在向量空間中靠近。這類表示可捕捉語意與語法規律，供文本分類、情感分析或機器翻譯使用。

指引列出神經網路與矩陣分解兩種學習路線：Word2Vec 用神經網路做詞預測，GloVe 則從共現統計學習向量；其加權分解方式見 GloVe 頁。

:::supplement[來源：Jurafsky 與 Martin 第 5 章]
從編碼看，一個詞由多個共享維度共同表示；維度不各自綁定一個詞。是否學到有用的語意關係，仍須看語料與學習目標。
:::

### 用餘弦比較（補充）

兩個同維且非零的向量，可用餘弦相似度比較方向：

$$
\mathrm{cos}(u,v)=\frac{\sum_{j=1}^{q}u_jv_j}
{\sqrt{\sum_{j=1}^{q}u_j^2}\sqrt{\sum_{j=1}^{q}v_j^2}}
$$

$u,v$ 是待比較向量，$q$ 是維度，$u_j,v_j$ 是第 $j$ 維座標。值越接近 1，方向越接近；零向量無法代入這個分母。

同一向量乘正數，方向不變；餘弦仍相同。這能減少長度對比較的影響，但不會保證相似度等於同義程度。

## 算一次

先核對受控語料：T02 是「我／不／要／訂／明天／的／票」，T04 是「我／要／改／明天／的／票」。兩句附近的「要、明天、的」提供相似上下文。

### 三詞比較（補充）

共用例子的六個三維向量皆為手設。這裡取三詞，沿用同一順序比較，不從二維投影圖估讀數字。

| 詞 | 手設向量 | 與「訂」的餘弦 |
|---|---|---|
| 訂 | (1,0.2,0.1) | 1 |
| 改 | (0.9,0.3,0.1) | 約 0.992331 |
| 書 | (0.1,0.2,1) | 約 0.228571 |

「訂」與「改」的內積是 $0.9+0.06+0.01=0.97$，長度分別為 $\sqrt{1.05}$ 與 $\sqrt{0.91}$。

把內積除以兩個長度的乘積，得到 $0.97/\sqrt{1.05\times0.91}\approx0.992331$。這是公式分子、分母各自的計算結果。

「訂」與「書」內積為 $0.1+0.04+0.1=0.24$，兩者長度皆為 $\sqrt{1.05}$。因此餘弦約為 0.228571；此空間中「訂」較接近「改」。

## 程式（補充）

從 repo 根目錄讀取共用資料；實測器用 `IPAS_REPO_ROOT` 指向 repo。只計算向量相似度，沒有訓練或隨機步驟。

```python
import json, os
from pathlib import Path
import numpy as np
root = Path(os.environ.get("IPAS_REPO_ROOT", "."))
data = json.loads((root / "content/examples/L21101-B-vectors.json").read_text(encoding="utf-8"))
vectors = data["embedding"]["vectors"]
u = np.array(vectors["訂"])
for term in ["改", "書"]:
    v = np.array(vectors[term])
    score = u @ v / (np.linalg.norm(u) * np.linalg.norm(v))
    print(term, f"{score:.6f}")
```
```text
改 0.992331
書 0.228571
```

:::tip[讀碼重點]
@ 先算內積，norm 分別算兩向量長度，再相除得到餘弦。程式使用完整三維手設向量，不從二維投影圖估算，也沒有訓練模型。
:::

## 怎麼用、怎麼判讀

向量可以做類比：例如把「國王」扣掉「男人」再加上「女人」的向量，搜尋鄰近詞，可能找到「女王」。這反映語料裡的關係規律。

:::supplement[來源：Google Embedding space；Jurafsky 與 Martin 第 5 章]
類比不是邏輯證明。「訂」和「改」相近，不能推論訂票與改票可互換；類比結果接近某詞，也不保證該詞代表的事實為真。

例如「退款」與「付款」都可能靠近交易詞，卻不是相同的操作。實務要檢查任務錯誤，不能只看鄰近詞好不好看。
:::

### 換個場景

指引同時列出大規模語料學習與低頻詞限制。資料多能提供更多上下文，但領域、詞頻和多義性仍會影響表示。

| 場景 | 使用方式 | 判讀重點 |
|---|---|---|
| 文本分類、情感分析、翻譯 | 詞向量供下游模型使用 | 類似上下文可能提供語意關係 |
| 低頻詞或多義詞 | 檢查是否有足夠且一致的用法 | 少見詞不穩；固定向量混合詞義 |
| 製造零件搜尋（補充） | 找相關維修用詞 | 不同型號不可因接近就視為同件 |
| 圖書標籤推薦（補充） | 比對書籍介紹的相關詞 | 書名與罕見人名須另驗證 |

### 未登錄詞怎麼辦

| 情形 | 整詞靜態查表 | 判讀 |
|---|---|---|
| 已收錄但低頻 | 有專屬向量 | 學到的關係可能不穩 |
| 未登錄詞（OOV） | 沒有該詞的專屬列 | 需未知詞策略或換表示 |
| 子詞組合，如 FastText | 可利用已學片段 | 改善 OOV；不保證專名語意正確 |

## 常見誤解

- 「利用上下文訓練就是語境型」：靜態模型也用上下文學習；差別在使用時是否隨句子改變。
- 「語意近就能互換」：訂票與改票相關，仍是不同動作。（補充）
- 「GloVe 的輸出一定稀疏」：須區分輸入共現統計與輸出嵌入，見下方校正。

指引 3-20 把 GloVe 連到高維、稀疏風險。讀這段時應分清兩個物件：詞與詞的共現矩陣，和訓練後供查表使用的向量。

## 小結

- 相似上下文是學習關係的線索，靜態使用時每詞取同一向量。
- 餘弦可比較向量方向，零向量不適用。（補充）
- 低頻、未登錄與多義詞是不同問題。
- 向量類比與鄰近關係不能當成邏輯或事實保證。（補充）

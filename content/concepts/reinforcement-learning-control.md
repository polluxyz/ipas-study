## 為什麼需要

導航系統回答「往左或往右」，機械臂控制器回答「轉到多少度」。同樣叫控制，輸出的選擇集合不同，能用的演算法也不同。

:::supplement[來源：Stable Baselines3 RL Tips 的 Current Limitations]
強化學習需要與環境互動。遊戲可以大量重開，真實設備的試誤卻有耗材、時間與損壞成本；能否負擔訓練，要和控制需求一起評估。
:::

## 直覺

動作空間（Action Space）是代理人在一步決策中可輸出的動作集合。離散動作是選選項，連續動作是設定控制量。

![先看輸出是有限選項還是區間內的控制量，感測輸入的形式不決定動作分類。](figure:l23201-reinforcement-learning-control-actions)

| 對照 | 導航選方向 | 機械臂角度 |
|---|---|---|
| 輸出 | 左、右、前進 | 許可區間中的角度 |
| 動作空間 | 離散 | 連續 |
| 指引例子 | 遊戲動作、導航決策 | 機械臂、車輛轉向 |

:::supplement[來源：Gymnasium Spaces；Spinning Up Kinds of RL Algorithms]
觀測與動作分開判斷。攝影機可提供高維影像，但車輛若只選左、右兩個指令，動作仍是離散的；四種電量狀態也可以搭配連續充電功率。
:::

## 定義與公式

指引以選導航方向代表離散選項，以調整機械臂角度代表連續控制。

指引提醒樣本效率低、訓練不穩定與部署門檻，都是實務限制。

:::supplement[來源：Spinning Up Key Concepts 的 Action Spaces；Stable Baselines3 RL Tips；Spinning Up Kinds of RL Algorithms]
離散動作空間由可區分的選項構成；連續動作空間通常由一個或多個實數控制量構成。

樣本效率（Sample Efficiency）看取得一定決策表現需要多少互動經驗。

樣本效率與運算速度不同：同樣互動次數，換GPU可能只改變耗時。標準DQN通常輸出每個離散動作的Q值；PPO可依策略輸出設計處理離散或連續動作。
:::

## 走一次流程

### 用四格倉儲盤點

1. **確定任務**：從A出發，把貨送到D；移動與抓取會影響之後能否交付。（補充）
2. **列出輸出**：沿用前置組的作業前進、抓取或放回，這是兩個離散動作。（補充）
3. **匹配方法**：小狀態表可先試表格式Q-learning；高維影像觀測可考慮DQN（指引 `guide-1:5-11`）。
4. **檢查成本**：記錄每次移動、失敗與重開需要的時間，不能只數訓練輪數。（補充）
5. **限制操作**：先在模擬環境測試，定義碰撞停止與合法動作，再驗證真實設備差異。（補充）

:::supplement[來源：本組教學合成資料；Gymnasium Spaces]
此處採用 `L23201-C-warehouse.json` 的轉移與 `L23201-D-warehouse.json` 的擴充資料。新增Q值不會改變原本的動作集合。
:::

### 再換成四種電量（補充）

能源例目前只有充一格、放一格兩選項，所以動作離散。若改成輸出連續充放電功率，就改變了控制介面，不能只把Q表多加一個欄位便算完成。

把連續量切成固定檔位，可以轉成離散選項，但會犧牲控制精度。檔位與控制量變多時，組合也可能快速膨脹，必須重新評估。

## 怎麼用、怎麼判讀

先問是否需要一連串會改變後續情況的動作，再問動作形式。最後才比較方法，並評估是否能負擔互動與錯誤的成本。

### 換個場景

| 指引場景 | 長期決策焦點 |
|---|---|
| 遊戲與對弈 | 多步策略與最終勝負 |
| 自駕車與機器人 | 導航、動作序列與連續控制 |
| 推薦與廣告 | 即時回饋與長期使用者價值 |
| 金融與資源配置 | 持續配置與風險控制 |
| 運輸與物流排程 | 分階段安排與路徑規劃 |

:::supplement[來源：Stable Baselines3 RL Tips 的 Current Limitations；Spinning Up Kinds of RL Algorithms]
五類場景都要盤點互動成本與界線：

- 遊戲：可重開模擬，但訓練仍耗費計算與時間。
- 自駕車與機器人：先限制碰撞與危險動作，不能在真實道路任意試誤。
- 推薦與廣告：試誤會影響使用體驗，且回饋可能要等待。
- 金融與資源配置：測試情境與風險界線須明確，不能只看模擬收益。
- 物流：納入延誤、耗能與操作限制。

其他領域包括儲能的電量下限，以及灌溉的可用水量。即使回報較高，也不能據此忽略操作界線。

反例是固定照片的瑕疵分類：照片輸入後只預測標籤，沒有控制行為改變後續狀態。先做監督式學習通常較直接，不必為了有一個分數就改成強化學習。
:::

## 常見誤解

- 控制類任務常有連續動作，但也可以設計成有限指令；要看實際輸出。（補充）
- 高維影像是輸入特性，不能據此把動作判為連續。（補充）
- 能模擬不代表可直接部署，模擬器可能漏掉真實條件。（補充）
- 樣本效率高不代表每次更新快，互動次數與計算耗時要分開報告。（補充）

## 小結

- 離散是選動作項目，連續是輸出區間中的控制量。
- 長期決策、互動成本與樣本效率，決定強化學習是否值得採用。
- 演算法要匹配控制介面；標準DQN的輸出不是任意連續動作。（補充）

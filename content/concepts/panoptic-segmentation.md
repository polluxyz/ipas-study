## 為什麼需要

自駕不只要知道行人在哪裡，也要知道道路在哪裡。醫學影像也可能同時需要組織類別與各個病灶的區域。

指引提出結合語意與實例資訊的需求：既理解場景類別，也分開不同物件。單獨交語意圖或個體遮罩，可能各缺一部分。

## 直覺

同底圖先看每像素的類別，再看兩個行人各自的範圍。整合後，背景仍有意義，同類行人也能分開。

![上圖只判類別，中圖只保留行人個體，最下圖把背景類別與行人 ID 放入同一場景輸出。](figure:l21102-image-segmentation-three-outputs)

:::supplement[來源：Panoptic Segmentation 原始論文第 1、3 節；核心延伸：明確定義整合任務]
全景分割（Panoptic Segmentation）把這兩種需求整理成一致的任務：每個有效像素都有類別，可數物件另外有個體身分。它的「全景」不表示相機一定拍攝 360 度。
:::

## 定義與公式

:::supplement[來源：Panoptic Segmentation 原始論文第 3 節]
| 類型 | 名稱 | 例子 | 輸出要求 |
|---|---|---|---|
| 可數物件 | things | 行人、車輛 | 類別與個體 ID |
| 背景類別 | stuff | 道路、天空 | 類別；不逐個計數 |

這種分工由任務標註規約決定。背景不是「不重要」，只是通常不以一個、兩個的個體單位計數。

可把一格的結果理解成「類別＋個體值」。本例以個體值 0 表示背景類別；道路的類別值也剛好為 0，但兩個零屬於不同欄位，均不代表忽略。

標準全景結果對每個有效像素給唯一歸屬，不讓兩個物件同時占用同一格。有些資料集會設忽略區域；那些像素要依規約處理，本例則沒有忽略區。
:::

## 走一次流程（補充）

從 `L21102-B-scenes.json` 取交通 T01，與語意、實例分割頁共用索引與底圖。

1. 語意圖給 30 格道路、25 格建築、9 格行人，合計 64 格。
2. 個體圖把 9 格行人分成 ID 1 的 5 格、ID 2 的 4 格。
3. 合併為全景記錄：道路是（0,0）、建築是（2,0），兩人分別是（1,1）、（1,2）。
4. 檢查全部 64 格均有唯一記錄，兩個人的範圍沒有互相重疊。

醫療 H01 同樣保留一般組織與器官區類別，再替兩處病灶保留不同個體值。此時 things/stuff 的角色由醫療標註規約指定，不照搬交通的類別名稱。

## 程式（補充）

先設定 `IPAS_REPO_ROOT`。本例由已互斥的真值圖組合輸出，核對格式；這不是從重疊的模型預測進行融合的演算法。

```python
import json, os
from pathlib import Path
from collections import Counter
d = json.loads((Path(os.environ['IPAS_REPO_ROOT']) / 'content/examples/L21102-B-scenes.json').read_text(encoding='utf-8'))
for name in ['traffic', 'medical']:
    r = d['domains'][name]['rows'][0]
    pairs = [(c, i) for sr, ir in zip(r['semantic_class_map'], r['instance_map']) for c, i in zip(sr, ir)]
    counts = sorted(Counter(pairs).items())
    print(r['image_id'], counts)
    print('有效像素:', sum(n for _, n in counts))
```
```text
T01 [((0, 0), 30), ((1, 1), 5), ((1, 2), 4), ((2, 0), 25)]
有效像素: 64
H01 [((0, 0), 31), ((1, 1), 2), ((1, 2), 3), ((2, 0), 28)]
有效像素: 64
```

:::tip[讀碼重點]
一格存一對值，而非把類別值與個體值混為一個編號。若真值尚未互斥，不能直接照這段配對就宣稱完成全景融合。
:::

## 怎麼用、怎麼判讀

自動駕駛與醫學影像是指引提到的整合場景。先問是否同時要場景類別與個體範圍，再決定交付哪些資訊。

### 三種輸出怎麼選（補充）

| 需求 | 選擇 | 原因 |
|---|---|---|
| 只需道路、建築、行人的像素類別 | 語意分割 | 不要求分開同類個體 |
| 只需每名行人的輪廓 | 實例分割 | 背景不需逐類分析 |
| 背景要判類，行人也要分個體 | 全景分割 | 統一場景類別與個體歸屬 |

### 換個場景

| 場景 | 整合需求 |
|---|---|
| 自動駕駛 | 場景類別與不同物件都要保留 |
| 醫學影像 | 組織區域與多個病灶的個體範圍 |
| 倉儲機器人（補充） | 地面區域與每件包裹需同時表達 |
| 生態調查（補充） | 背景棲地類別與各隻動物需同時表達 |

## 常見誤解

- **全景分割就是語意圖多幾種類別。** 關鍵還有可數物件的個體身分。（補充）
- **背景只要標成其他就夠了。** 是否夠用取決於任務；本例需要分開道路與建築。（補充）
- **實例遮罩直接疊起來就是全景。** 仍須處理重疊與未覆蓋區域，讓有效像素只有一個歸屬。（補充）

## 小結

- 語意分割回答類別，實例分割回答個體範圍。
- 全景分割同時保留背景類別與可數個體資訊。（補充）
- 每個有效像素只有一個歸屬，忽略區另依資料規約。（補充）
- things/stuff 是標註分工，不是重要與不重要的區別。（補充）

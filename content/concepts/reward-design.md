## 為什麼需要

指引說強化學習用報酬引導行為，目標是長期績效。若分數只量容易計數的動作，代理人可能把動作做很多次，任務卻沒有完成。

:::supplement[來源：Ng等〈Policy invariance under reward transformations〉第1節]
獎勵設計要先把「想達成什麼」轉成可驗證的回饋，再檢查是否能鑽漏洞。本頁用合成倉儲資料比較同一環境的兩種獎勵。
:::

## 直覺

獎勵用來引導學習方向，不是替每一步提供正確動作標籤。

:::supplement[來源：Ng等〈Policy invariance under reward transformations〉第1節]
如果只看抓取次數，拿起、放回、再拿起，可在每次成功抓取時加分，放回本身不加分。交貨目標應問「同一件貨物是否確實交付」，還要計入作業消耗。
:::

## 定義與公式

報酬（Reward，本組算例也稱單步獎勵）是環境對行為給的回饋，會影響學習方向。評估策略則要看長期累積表現與任務達成率，不能用一次得分代替。

### 獎勵錯配與塑形（補充）

獎勵投機（Reward Hacking）是行為提高了設計分數，卻沒有達成原本目的。獎勵塑形（Reward Shaping）則是在任務獎勵之外加入引導訊號，例如協助找到通往目標的方向。

塑形不一定錯，但任意加分可能改變最優策略。先區分「修正業務目標」與「在目標固定時加速學習」；兩者要驗證的事情不同。

廣義用法也會把「重設獎勵結構，使回饋對準完成任務」稱為獎勵塑形。判讀時仍要分清修正任務目標與加入中間引導訊號，不能只憑名稱推論策略不變。

### 用相同回報尺度比較（補充）

$$
G_0=\sum_{t=0}^{T-1}\gamma^t r_{t+1}
$$

$G_0$是軌跡回報，$T$是結束步數，$r_{t+1}$是本步動作後的獎勵，$\gamma$是折扣因子。本例固定$\gamma=0.9$、A起點及最多五步，進D完成即結束。

錯配版交付的獎勵為0、8、0，故$G_0=0+0.9\times8+0.9^2\times0=7.2$。這是在核算既有規則，不是在替抓取獎勵背書。

## 算一次（補充）

### 同環境，只換獎勵

使用 `L23201-C-warehouse.json`。兩條指定軌跡共用起點、步數上限與轉移；沒有換一個更容易的環境。

| 版本 | 原版：成功抓取給8 | 修正版：完成10、其餘作業-1 |
|---|---|---|
| 交付A→B→C→D | 獎勵0、8、0；回報7.2 | 獎勵-1、-1、10；回報6.2 |
| 反覆A→B→C→B→C→B | 獎勵0、8、0、8、0；回報13.032 | 五次-1；回報-4.0951 |

原版偏好未交付的重複抓取。修正版下，重複作業回報為$-1-0.9-0.81-0.729-0.6561=-4.0951$，交付較好。

不能拿原版13.032直接與修正版6.2比誰的策略好，因為分數定義已變。應在每個版本內比較行為，再用交付成功率與耗時這些固定業務指標驗證。

### 修正流程

1. 定義完成：貨物送達且確認交付，不是抓取事件。
2. 搜尋反例：重複抓取、停在高分狀態、刻意拖延結束。
3. 調整回饋：完成給分、無效作業計成本；完成後不重複發獎。
4. 在相同起點與上限重播，另看成功率；兩條軌跡通過不等於所有漏洞已排除。

### 塑形保留原目標的界線

勢能式塑形（Potential-based Shaping）用狀態的勢能差提供額外獎勵：

$$
F(s,a,s')=\gamma\Phi(s')-\Phi(s),\qquad r'=r+F(s,a,s')
$$

$s$與$s'$是前後狀態，$a$是動作；$F$是額外獎勵，$r$是原本的單步獎勵，$r'$是新獎勵，$\Phi$是有界勢能。折扣須與原目標一致。

本例折扣0.9，勢能設定如下；這是引導訊號，不是另一份業務完成分數。

| 狀態 | 勢能 |
|---|---:|
| A | -3 |
| B | -2 |
| C | -1 |
| D | 0 |

三步$F$為1.2、1.1、1，新獎勵為0.2、0.1、11。回報$0.2+0.9\times0.1+0.81\times11=9.2$，比原來多3。

完整終止且終點勢能為0時，同起點回報都平移$-\Phi(A)=3$，不改變策略排序。無限折扣期需有界勢能等條件，任意中間加分沒有此保證。

五步到期但未完成是截斷，末端勢能可能非0；丟掉剩餘價值，平移結論不直接成立。須處理末端項，本頁只對確實終止於D的例子展示保證。

## 程式（補充）

固定重播兩條軌跡的獎勵，核對表格與塑形數字。這段不訓練、不用亂數，也不建立任何檔案。

```python
def total(rewards):
    return sum(0.9 ** t * r for t, r in enumerate(rewards))
versions = {"原版": ([0, 8, 0], [0, 8, 0, 8, 0]),
            "修正版": ([-1, -1, 10], [-1] * 5)}
for name, (delivery, repeat) in versions.items():
    print(f"{name}: 交付={total(delivery):.4f}, 反覆={total(repeat):.4f}")
phi = [-3, -2, -1, 0]
extra = [0.9 * b - a for a, b in zip(phi, phi[1:])]
shaped = [r + f for r, f in zip([-1, -1, 10], extra)]
print(f"塑形: {total(shaped):.4f}, 平移={total(shaped) - 6.2:.4f}")
```
```text
原版: 交付=7.2000, 反覆=13.0320
修正版: 交付=6.2000, 反覆=-4.0951
塑形: 9.2000, 平移=3.0000
```

:::tip[讀碼重點]
`zip(phi, phi[1:])`配對前後狀態勢能。交付終點勢能為0，故`total(shaped) - 6.2`等於$-\Phi(A)=3$；未完成的截斷軌跡不能直接套用。
:::

## 怎麼用、怎麼判讀

指引以長期績效、成功率或任務達成率評估強化學習，不能只看單步回饋。

:::supplement[來源：Ng等〈Policy invariance under reward transformations〉第1、3節]
業務目標沒變時，調整獎勵後仍要用同一套完成標準驗收。若某種加分可被低成本反覆取得，先查循環，不要急著把分數上升當進步。
:::

### 換個場景

| 場景 | 要完成的事 | 回饋或判讀 |
|---|---|---|
| 倉儲物流 | 貨物搬運與交付 | 配合任務達成率判讀 |
| 推薦與廣告 | 長期使用者價值 | 不只看一次即時反饋 |
| 儲能調度（補充） | 持續供電 | 同表的4、4、-6提醒勿只獎勵當次放電 |
| 客服分流（補充） | 問題獲得解決 | 只獎勵結案數可能鼓勵過早結案 |

## 常見誤解

- 一次高分不代表任務已完成；長期累積回報與任務達成率要一起看。
- 提高抓取分數只是放大原漏洞，不能讓它自動變成完成獎勵。（補充）
- 獎勵塑形一般可能改變最優策略；保留排序的保證有明確條件。（補充）
- 修正版在兩條軌跡較合理，不代表已證明全環境沒有漏洞。（補充）

## 小結

- 獎勵要與任務完成一致，先找重複獲利卻不完成的反例。
- 換獎勵後，在各版本內比較回報，並用固定業務指標查核。
- 塑形是額外引導；一般加分沒有保留原本最優策略的保證。

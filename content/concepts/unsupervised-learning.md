## 為什麼需要

電商只有購買紀錄，還沒有客戶類型標籤；工廠有感測資料，卻沒有逐筆故障答案。這時仍可先問：哪些樣本相似？哪些行為特別不同？

這類方法稱為非監督式學習（英文：Unsupervised Learning）。擬合時不讀目標答案，而是探索樣本結構；用途包括分群、特徵壓縮、視覺化與異常發現。

## 直覺

給模型同一份無標籤資料，可以要求不同形式的輸出。分群把樣本分組，投影把資料放進較低維的座標，潛在表示則用一組學到的編碼描述資料。

![同一份無標籤輸入可產生群編號、低維座標或潛在編碼，三者都不是現成的業務答案。](figure:l23201-unsupervised-learning-outputs)

:::supplement[來源：Google Machine Learning「What is clustering?」]
群編號只是識別名稱。把群 0 與群 1 對調，不會改變誰與誰同群，也不會使客戶價值反轉。
:::

## 定義與公式

「沒有標籤」指擬合時沒有拿目標答案來監督，不是資料裡不能有任何文字或欄名。客戶 ID 只是索引，不能當成目標答案。

### 本組無標籤視圖（補充）

每個領域各有 24 筆，以下抽四筆電商資料。第一個特徵是 30 日訂單次數，第二個是 30 日金額除以 1,000 元。

| 索引 | 訂單次數 | 金額換算值 |
|---|---:|---:|
| E01 | 1 | 1 |
| E02 | 1 | 3 |
| E09 | 7 | 1 |
| E10 | 7 | 3 |

資料檔另外保存參考群與候選預測，供教學核對；真正的無標籤擬合只讀兩個特徵。參考群是人造分組，不是已證實的消費者心理類型。

### 按輸出選任務

| 想知道什麼 | 任務 | 輸出 |
|---|---|---|
| 哪些顧客行為相近 | 分群 | 每筆的群編號 |
| 能否用較少座標保留結構 | 降維 | 每筆的低維座標 |
| 能否抽出有用的內部特徵 | 潛在表示學習 | 每筆的編碼向量 |
| 哪些觀測偏離多數模式 | 異常偵測 | 異常候選或分數 |
| 哪些商品常一起被買 | 關聯規則學習 | 規則與支持度、信賴度 |

異常偵測與分群的問題不同。少數樣本形成的小群，不一定是需要攔截的異常；它也可能代表合法但少見的設備模式。

### 常見方法先看什麼

科目 1 指引列出以下方法。先看要分組還是壓縮，再看資料形狀與輸出需求；不要只因都不需要標籤，就把它們互相替換。

| 方法 | 適合先考慮的需求 | 選型注意 |
|---|---|---|
| K-means 分群 | 群組較緊密、可先指定群數 | 要設定群數，初始中心與離群值會影響結果 |
| DBSCAN 密度分群 | 含雜訊或非球狀群的探索 | 以密度連結成群，不必先指定群數 |
| 階層式分群 | 想看樣本逐層合併或拆分的關係 | 產生樹狀結構，不只看一組群編號 |
| 主成分分析（PCA） | 用較少座標保留主要變異 | 用於壓縮或視覺化，輸出不是類別答案 |

## 走一次流程

1. 把需求寫成可觀察的輸出：顧客群、設備異常候選、壓縮結果或語意表示。
2. 確認是否有可用的答案；有可靠的故障／詐欺標籤時，也可直接考慮監督式分類。
3. 準備特徵並檢查尺度，再選方法：分組可考慮 K-means 分群、DBSCAN 密度分群或階層式分群；壓縮可考慮主成分分析。
4. 先看資料結構，再拿業務紀錄查核群組與候選異常。（補充）

### 電商與製造各走一次（補充）

電商 E01 與 E02 訂單次數相同、金額不同；E09 與 E10 則有較高訂單次數。可先比較兩維結構，不能只因它們落在群 0，就命名成「即將流失」。

製造 M01 的原始觀測為 55°C、0.6 mm/s，M02 為 55°C、0.8 mm/s。兩筆的固定工程換算座標也是 (1,1)、(1,3)，但座標相同不表示業務語意與顧客相同。

若任務改成找偏離正常運轉的設備，應先界定正常資料的來源。只有觀測差異，還不能確認是故障、負載變動或感測器失準。

## 怎麼用、怎麼判讀

### 離群與新穎性偵測（補充）

| 資料條件 | 任務方向 | 判讀 |
|---|---|---|
| 沒有答案，資料可能混入異常 | 離群偵測 | 從混合資料找偏離多數的點 |
| 已確認是一批正常資料 | 新穎性偵測 | 對後來的新樣本判斷是否偏離 |
| 正常與故障都有可靠標籤 | 監督式分類 | 學已定義的類別，另測未知異常 |

Isolation Forest 可作離群候選篩選；One-Class SVM 常用來學正常區域。這是選型起點，不是對任何資料都成立的排名。

### 換個場景

以下先列指引的領域用途。表中的「查核」是把無標籤結果接回業務時要補上的工作。

| 場景 | 無標籤任務 | 輸出如何使用 |
|---|---|---|
| 電商行銷 | 顧客分群 | 看購買行為差異，再查活動效果 |
| 工業、金融與資安 | 異常偵測 | 找候選偏離點，再查故障、詐欺或入侵 |
| 社群網路 | 社群偵測 | 看連線結構，不直接判定人員意圖 |
| 影像壓縮與文件語意 | 壓縮重建、主題或潛在表示 | 影像查還原品質；文件以主題、向量支援搜尋 |
| 交通（補充） | 路段流量模式分群 | 少見尖峰可能是活動，不能一律刪除 |
| 能源（補充） | 用電曲線壓縮 | 壓縮後是否仍保留尖峰資訊 |

:::supplement[來源：scikit-learn Novelty and Outlier Detection；Google Machine Learning「What is clustering?」]
異常候選不是惡意或故障的同義詞。群組與投影也只是依所選特徵、距離與模型得到的結構；語意、風險與效果都需要另外的證據。
:::

### 支援標註與半監督學習

科目 3 指引把非監督學習用於前處理、特徵抽取、模型初始化與標註支援。科目 1 指引 3-46 也說明半監督學習會合用少量已標註與大量未標註資料。

:::supplement[來源：Google Machine Learning「What is clustering?」；scikit-learn Clustering]
例如先讓人檢查不同群的代表樣本，再建立標籤準則。不能直接把全部群編號當成真實類別；這樣可能把分群錯誤傳進後續模型。
:::

## 常見誤解

- 無標籤就無法評估：仍可用非監督學習的評估方法檢查結構與重建。
- 所有異常偵測都不使用標籤：有可靠答案時也能做監督式分類。（補充）
- 群編號就是已確認的客戶類型：群的業務名稱需要查核。（補充）

## 小結

- 擬合不讀目標標籤，仍可探索群組、投影與潛在表示。
- 先看想取得的輸出，再決定分群、壓縮、表示或異常偵測。
- 無標籤結果適合支援查核與標註，不能直接保證業務意義。（補充）

## 為什麼需要

行程安排需要理解日期、查班表，再依條件整理建議。只會生成文字的系統，可能把查不到的班次也寫得像真的。

AI 代理（AI Agent）把語言模型和外部能力接在一起，讓系統從內容生成進一步處理任務。指引列出工具調用、檢索增強生成及記憶，也以行程安排、程式碼與圖文協作為例。

## 直覺

:::supplement[來源：Anthropic Building effective agents，Building block 與 Agents]
可把代理想成持有工作清單的助理：知道目標、選擇可用工具、查看回傳，再決定下一步。它是否完成工作，要看可查證的結果。
:::

多模態感知讓代理能接收文字以外的線索，例如圖片與語音。指引指出，這類能力可與決策系統整合，用在機器人、智慧助理、教育與客服。

![感知先形成可用輸入；工具回傳再成為觀察，記憶不會直接證明操作成功。](figure:l21103-ai-agent-components)

圖中感知與工具整合是指引內容；任務狀態、日期查核及權限閘門是為落實流程加入的補充。

## 定義與公式

指引將代理式發展描述為指令理解、多回合互動與外部工具整合。本頁重點是各元件如何合作，不需計算公式。

:::supplement[來源：Anthropic Building effective agents；LangChain Memory overview]
| 元件 | 負責什麼 | 不可混淆之處 |
|---|---|---|
| 指令與模型 | 理解目標、決定下一步 | 指令理解不等於已獲操作權限 |
| 工具 | 執行查詢或被允許的操作 | 模型提出呼叫後，程式才實際執行 |
| 檢索 | 找出任務所需的文件或紀錄 | 找到資料仍要確認日期與適用對象 |
| 記憶 | 保留當次條件或跨次偏好 | 舊紀錄不保證仍符合今天的事實 |

短期記憶保留本次任務狀態，例如日期、已查來源及未解問題；長期記憶可保存跨次使用的偏好。是否保存、讀取及更新，由應用設計決定，不是模型必然自帶。
:::

:::caution[注意]
「我已訂票」是文字回覆；訂票工具執行並取得成功憑證，才是外部操作完成。工具權限與成功結果要各自核對。（補充）
:::

## 走一次流程

### 從指令到回傳（補充）

共用資料 `L21103-E-agent-tasks.json` 的 TR01 是旅運查詢。查核日固定為2026-11-02，使用者要查明日；本例全為教學合成資料。

1. 感知：讀取 `route-1` 告示圖片與「請查明日資料」的語音，將明日轉成2026-11-03。
2. 決策：確認目標是查班表，只能使用只讀工具，不能訂票。
3. 檢索與工具：以 `route-1`、2026-11-03 呼叫班表查詢，取得08:30。
4. 觀察：核對來源識別碼、更新日2026-11-02、適用日2026-11-03及路線是否相符。
5. 記憶與回覆：保存本次來源及日期，再回覆查詢結果；偏好上午出發只協助篩選，不改寫班表。

SP01 用同一個流程整理 `supplier-1`，查得交期11日。來源更新日、適用日與供應商編號都要一致，偏好短交期不能讓11日變成更短。

### 多模態決策如何落地

指引列出機器人、客服與教育等整合用途。

:::supplement[來源：Anthropic Building effective agents，Agents；本組教學情境]
| 場景 | 感知與決策 | 工具與觀察 |
|---|---|---|
| 機器人 | 影像見通道障礙，決定改路 | 查地圖或下達允許的移動，讀回位置與障礙狀態 |
| 客服 | 看告示、聽詢問，辨別日期與路線 | 查班表，核對回傳的路線、日期與時間 |
| 教育 | 看圖表、聽提問，定位不懂之處 | 查課程資料，核對章節與圖表版本再解說 |

感知可能辨錯字或聽錯日期。工具回傳與使用者條件不一致時，先澄清或停止；不得把辨識結果當成已驗證的事實。
:::

## 怎麼用、怎麼判讀

行程規劃、程式碼生成與圖文編輯，都可能需要模型與外部能力合作。多模態代理再加入對圖像、語音等輸入的理解。

:::supplement[來源：Anthropic Building effective agents，When to use agents；LangChain Memory overview]
任務需依新觀察改變步驟時，代理有價值；步驟固定、輸入清楚時，可先用固定流程。增加記憶或工具不保證品質提升，仍應核對證據、成本與完成條件。
:::

### 換個場景

| 場景 | 資料條件 | 判讀重點 |
|---|---|---|
| 行程規劃、程式碼、圖文編輯 | 需結合指令與外部工具 | 分清生成內容與實際任務結果 |
| 機器人、智慧助理、教育、客服 | 多模態感知需接上決策 | 不能只辨識輸入就宣告完成 |
| 製造供應商整理（補充） | 規格表與交期會更新 | 按供應商、日期與單位核對 |
| 農業巡檢（補充） | 影像與感測器資料可能缺漏 | 記下缺漏，查不到時交人工確認 |

## 常見誤解

- 「有語言模型就是自主代理。」還要看系統是否使用觀察推進任務，名稱不能代替架構說明。（補充）
- 「記得越多越可靠。」過時記憶可能誤導本次查詢，應保留來源與時間。（補充）
- 「看懂圖就會操作。」感知、決策與工具執行各有責任，不能互相代替。（補充）

## 進階

### 記憶更新的界線（補充）

跨次保留偏好時，應記錄適用使用者及更新時點。單次工具錯誤或未核實的推測，不宜直接當成長期事實；不再需要的資訊也應能更正或移除。

## 小結

- 指令說明目標，工具取得外部結果，檢索提供資料，記憶保存可再用的資訊。
- 感知、決策、工具與觀察要接起來，才有可追蹤的任務過程。（補充）
- 文字宣告、操作授權與操作成功是三件不同的事。（補充）

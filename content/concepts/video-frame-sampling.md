## 為什麼需要

影片不是一張較大的照片，而是一連串有先後順序的影格。指引把影格取樣放在序列統一，應用於動作辨識與影像序列建模。

:::supplement[來源：PyTorchVideo UniformTemporalSubsample；Keras影片分類教學]
全部影格都送入模型，可能造成輸入過長與重複計算。影片影格取樣（Frame Sampling）選出有限影格，但不能因此丟掉任務真正需要的短動作。
:::

## 直覺

動作辨識需要時間上的變化，不能只確認每張影格都能正常解碼。取樣後仍要保留能說明動作的先後關係。

### 看時間軸上的空隙（補充）

共用例子有零售封口與製造表面異常兩段示意影片，各12格。兩者都從0到1100毫秒，每100毫秒一格；事件區間設定為450到650毫秒，所以500、600兩格有事件。

![每400毫秒選出的方框避開事件區間；每200毫秒會保留600毫秒，但仍只看到一個事件影格。](figure:l21102-video-frame-sampling-timeline)

兩段影片共用時間戳與索引，分開解讀領域標籤。圖的淡色帶是事件真值，用來檢查取樣結果，並非讓部署取樣器預先知道事件在哪裡。

## 定義與公式

影格取樣從影片或序列中選出影格，使後續模型取得所需的序列表示。指引沒有規定所有任務都採同一個取樣間隔。

### 三種規則要分清（補充）

| 取樣方式 | 規則 | 代價或風險 |
|---|---|---|
| 固定時間間隔 | 每隔固定毫秒取格 | 短事件可能落在空隙 |
| 固定格數、均勻索引 | 在片段索引範圍選K格 | 不等幀率時未必等時間 |
| 事件附近較密取樣 | 先以觸發規則找候選時段 | 觸發器也可能漏掉事件 |

均勻索引的實作必須寫明端點與取整。本頁程式採首末都含、等距索引向下取整，與PyTorchVideo的`linspace(...).long()`對齊。

原片不足K格時，某些工具會重複選格；補到指定長度不等於取得新資訊。可依模型契約使用遮罩或明確記錄補格，不能把複本當新觀測。

## 走一次流程

### 對兩段影片使用同一套規則（補充）

1. **讀時間戳：** 確認12格各自的毫秒位置，先檢查是否等幀率。
2. **設定成本上限：** 本例最多保留6格；先比較固定時間間隔，再比較固定格數。
3. **試400毫秒：** 保留0、400、800，共3格，事件命中0格。
4. **試200毫秒：** 保留0、200、400、600、800、1000，共6格，事件命中1格。
5. **檢查冗餘與順序：** 本例前五個原影格相同；200毫秒取樣的6格仍只有2種像素畫面，不能當成6次獨立事件。

若改成含首末的均勻索引取4格，得到索引0、3、7、11，也漏掉事件。取6格得到0、2、4、6、8、11，才包含事件索引6；它的最後時間點與200毫秒規則不同。

捕到一格只證明「曾看到」，未必足以辨認動作方向或持續時間。需要連續變化時，應取局部連續片段或提高時間解析度，再檢查計算預算。

## 程式

### 固定時間與均勻索引（補充）

時間戳及事件標籤均取自`L21102-D-vision.json`。以下只比較規則，不讀影片檔，也不使用事件標籤協助取樣。

```python
import numpy as np
np.random.seed(21102)
times = np.arange(12) * 100
event = (times >= 450) & (times < 650)
for step in (400, 200):
    ids = np.flatnonzero(times % step == 0)
    print(step, "ms:", times[ids].tolist(), "事件格:", int(event[ids].sum()))
for k in (4, 6):
    ids = np.linspace(0, len(times) - 1, k).astype(int)
    print(k, "格索引:", ids.tolist(), "事件格:", int(event[ids].sum()))
```
```text
400 ms: [0, 400, 800] 事件格: 0
200 ms: [0, 200, 400, 600, 800, 1000] 事件格: 1
4 格索引: [0, 3, 7, 11] 事件格: 0
6 格索引: [0, 2, 4, 6, 8, 11] 事件格: 1
```

:::tip[讀碼重點]
`times % step`依時間選格；`linspace`依索引範圍選格。事件命中數是在選完後才計算；不能先用答案定位，再宣稱部署時也能以相同成本找出事件。
:::

## 怎麼用、怎麼判讀

指引將動作辨識與序列建模列為適用場景。關鍵是模型需要哪段時間的資訊，不是單看壓縮後還剩幾張。

### 時間、洩漏與部署限制（補充）

短事件需要較密取樣；長時間狀態可用較疏取樣減少冗餘。固定間隔即使不大於事件時長，也要考慮原始幀率、事件對齊與需要幾個連續證據，不能承諾必定辨識成功。

同一影片、同一個體或同一段連拍的近鄰影格，應依評估目標整組分配。不要先抽成大量圖片再隨機打散，讓相似畫面同時出現在訓練與評估。

部署時只能使用當下已取得的影格。離線看完整段後選的代表格，不能直接當作即時系統在事件發生前已可取得的輸入。

### 換個場景

| 場景 | 資料條件 | 取樣判讀 |
|---|---|---|
| 動作辨識、影像序列建模 | 多影格、有時間順序 | 保留動作所需的變化 |
| 零售封口（補充） | 異常只出現約200毫秒 | 比較密取樣與事件漏失 |
| 製造表面異常（補充） | 背景長時間相同、瑕疵短暫入鏡 | 去冗餘仍須保住異常片段 |
| 交通轉向（補充） | 方向由多個時刻決定 | 單張命中不等於動作完整 |

## 常見誤解

- **統一格數就統一了時間解析度。** 長短影片各取6格，實際時間間距可能不同。（補充）
- **每格都標不同檔名就互相獨立。** 同源重複與時間相依不會因此消失。（補充）
- **取樣只能每隔幾格選一次。** 也能依時間戳、片段或候選事件規則選取。（補充）
- **一格有事件就足以分類所有動作。** 方向與順序可能需要多個連續影格。（補充）

## 進階

### 不等幀率與補格（補充）

若影格時間戳為0、100、1000毫秒，等索引步距不代表等時間步距。先確認解碼器提供的時間資訊，再定義時間格點如何對應最近影格，以及缺格或重複選格如何記錄。

## 小結

- 影格取樣用於動作與影像序列的輸入整理。
- 取樣間隔要配合事件時長，也要檢查所需的連續證據。（補充）
- 重複格可補長度，不能補出新的時間資訊。（補充）
- 來源隔離、順序與部署可取得時間要一起檢查。（補充）

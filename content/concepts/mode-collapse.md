## 為什麼需要

生成對抗網路可能找到幾種很能騙過判別器的樣本，便反覆產生它們。單張看來很逼真，整批卻沒有涵蓋真實資料中的不同型態。

這種多樣性不足稱為模式崩潰（Mode Collapse）。用生成資料擴充訓練集時，若重要型態沒有出現，增加張數也補不了缺口。

## 直覺

把正常商品分成橫紋、直紋、十字三種模式。生成器若只給出前兩種，就算每張都清楚，十字仍沒有被學到。

![注意漏模式組的十字為零；每類一原型組雖然三類都有，整批仍只有三張不同圖。](figure:l23203-mode-collapse-coverage)

:::supplement[來源：Google GAN 課程 Common Problems；Bau 等 Seeing What a GAN Cannot Generate]
模式不必等於人工類別，也可能是同一類裡的姿勢、角度或外觀變化。圖中的三類只是方便計數的教學切法，不能把全類別覆蓋當成完整多樣性。
:::

## 定義與公式

模式崩潰指不同噪聲輸入被映到少數幾種輸出，造成分布覆蓋不足。辨識重點是「整批產出了哪些變化」，不能只挑最好看的幾張。

| 觀察 | 說明什麼 | 能否直接判定模式崩潰 |
|---|---|---|
| 大量樣本只有少數類型 | 多樣性不足 | 是重要警訊 |
| 損失上下震盪 | 訓練可能不穩定 | 仍要檢查樣本分布 |
| 個別圖像模糊 | 樣本品質有限 | 不等於模式缺漏 |
| 類別都有但近乎同圖（補充） | 同類內變化不足 | 需查重複與近似 |

不穩定是訓練行為，模式缺漏是生成結果的分布問題；兩者可能一起發生，也可能只觀察到其中一種。不能只靠損失曲線分辨所有情況。

## 走一次流程（補充）

共用檔為 `L23203-I-reconstruction-generation.json`。兩領域各有 24 筆正常資料；候選依相同規則抽取，用於診斷對照，並非訓練成果。

1. 固定參考：設備三種負載各 8 筆；商品三種形狀各 8 張。
2. 固定抽樣量：每組取 24 筆，避免把張數改變誤當多樣性改善。
3. 回查正常模板辨認模式：平衡組為 8、8、8；漏模式組為 12、12、0，覆蓋從三種降成兩種。
4. 再查同類內變化：每類一原型組仍為 8、8、8，卻只有 3 個不同輸出。

模式標記由固定模板比對得到，不能直接相信生成器自己聲稱的類別。真實影像要用人工抽查或經驗證的辨識方法，並檢查同類內的變化。

## 程式（補充）

先在 PowerShell 設 `$env:IPAS_REPO_ROOT=(Get-Location).Path`。完全一致的模板比對適合本例；這不是可泛用到自然影像的模式辨識器。

```python
import json, os
from pathlib import Path
from collections import Counter
d = json.loads((Path(os.environ['IPAS_REPO_ROOT']) / 'content/examples/L23203-I-reconstruction-generation.json').read_text(encoding='utf-8'))
for domain, field in [('devices', 'mode'), ('images', 'shape_class')]:
    rows = {r['id']: r for r in d[domain]}
    payload = 'sensors' if domain == 'devices' else 'pixels'
    for name, indices in d['candidates'][domain].items():
        samples = [rows[i] for i in indices]
        counts = Counter(r[field] for r in samples)
        unique = len({json.dumps(r[payload]) for r in samples})
        print(domain, name, '模式數=', len(counts), '不同輸出=', unique)
```
```text
devices balanced 模式數= 3 不同輸出= 24
devices missing_mode 模式數= 2 不同輸出= 12
devices prototypes 模式數= 3 不同輸出= 3
images balanced 模式數= 3 不同輸出= 24
images missing_mode 模式數= 2 不同輸出= 12
images prototypes 模式數= 3 不同輸出= 3
```

:::tip[讀碼重點]
候選用已知模板的索引取樣，所以能回查模式。`len(counts)` 看出現幾種模式，`unique` 看實際不同陣列；兩個計數不能互相取代。
:::

## 怎麼用、怎麼判讀

GAN 訓練對學習率與架構敏感，可能出現梯度問題或模式崩潰。用生成圖做資料增強時，要檢查它是否只增加原本已有的少數樣式。

### 發現缺漏後（補充）

先查資料本來是否缺少某模式，再查多次抽樣是否持續缺漏，接著檢查生成器與判別器的能力和更新是否失衡。若只抽幾筆沒有見到某模式，尚不足以斷定整個分布都缺少它。

可嘗試調整更新比例、學習率或架構，或用 WGAN 改善分布差異的學習訊號。展開式 GAN（unrolled GAN）則讓生成器更新時預看判別器後續幾步的反應，減少只迎合當前判別器。

每次修改後重新看覆蓋、重複與品質，沒有任何單一設定能保證排除崩潰。

### 換個場景

| 場景或條件 | 缺漏會造成什麼問題 | 查核方向 |
|---|---|---|
| 人臉、動物、風景、藝術與動畫 | 只剩少數外觀 | 整批類型是否足夠多 |
| 資料增強 | 訓練資料仍缺重要型態 | 新增資料是否補到缺口 |
| 修復、上色、超解析度 | 多樣化輸入被推向少數樣式 | 內容有無被不當同質化 |
| 設備負載（補充） | 合成測試漏掉高負載 | 按負載回查生成覆蓋 |
| 服飾展示（補充） | 每類只剩同一角度 | 查類內角度與款式變化 |

## 常見誤解

- 「換了很多噪聲，就一定生成很多樣式。」生成器可能把不同噪聲映成近似輸出。
- 「損失穩定，就一定沒有模式缺漏。」還是要直接檢查生成分布。（補充）
- 「多產一千張就能補回消失的模式。」若生成器仍只輸出舊型態，重複張數再多也無法補足。
- 「涵蓋所有類別，就沒有模式崩潰。」每類內也可能只剩同一原型。（補充）

## 小結

- 模式崩潰是整批多樣性不足，個別樣本仍可非常逼真。
- 損失震盪、模糊與模式缺漏要分開觀察。
- 查類別覆蓋後，仍要查每類內的重複。（補充）
- 固定參考、抽樣量與判讀方式，再比較修改前後。（補充）

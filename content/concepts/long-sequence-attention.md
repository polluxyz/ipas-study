## 為什麼需要

長契約的定義可能在開頭，例外卻在結尾。直接截斷會漏資料；保留全部詞元，又會增加標準密集自注意力的計算與記憶體負擔。

長序列策略保留較長輸入，同時調整位置間的連結或注意力算法。但省下成本時，也要確認任務需要的遠距資訊仍能傳遞。

## 直覺

指引舉 Longformer、Reformer、Performer 為長序列 Transformer 的代表，並把局部注意力、稀疏注意力及近似計算列為壓低平方級成本的策略。

:::supplement[來源：Longformer 3.1；Performer 2]
局部注意力只看鄰近位置；稀疏注意力只保留選定連結，局部視窗就是其中一種模式。近似注意力則換一種計算表示，未必把遠處詞元排除。
:::

![分清三條路：局部只接鄰居、稀疏保留全域位置、近似以特徵彙整替代完整配對。](figure:l23203-long-sequence-attention-strategies)

### 代表模型的分工（補充）

| 模型 | 核心做法 | 主要取捨 |
|---|---|---|
| Longformer | 局部視窗＋任務指定全域位置 | 全域點要選得合適 |
| Reformer | 以局部敏感雜湊尋找相似鍵 | 分桶可能漏掉重要配對 |
| Performer | 用隨機特徵近似注意力核 | 特徵數與近似誤差要平衡 |

Reformer 也採可逆殘差層減少儲存激活；不是每個長序列模型都只是固定滑窗。Performer 可近似全域作用，不能畫成「把所有遠距連結刪掉」。

## 定義與公式

指引指出標準注意力的主要配對成本隨長度平方成長，長序列模型則使用局部、稀疏或近似算法降低負擔。

### 固定規則下的配對計數（補充）

局部視窗依 Longformer 第 3.1 節；以下精確計數由本頁固定規則推導，不是論文直接列出的公式。

$$
N_{\mathrm{dense}}=L^2,\qquad
N_{\mathrm{local}}=2\times2+(L-2)\times3=3L-2.
$$

$L$ 是序列長度，$N$ 是每頭有向的查詢—鍵配對數。局部公式限定 $L\ge2$、半徑一、包含自身、兩端不環繞；首尾各二格，其餘每列三格。

固定視窗寬度及少量全域點時，局部與全域連結數可隨長度線性增長。若把全域點數也擴到與長度相當，就不能仍宣稱相同的線性優勢。

配對數不是完整模型 FLOPs 或實際延遲。若用普通密集矩陣先算完再遮掉，並不會自動取得稀疏實作的記憶體與速度收益。

## 算一次

以共用 L01 的八詞元為例，密集每頭有 $8^2=64$ 格。固定半徑一的局部模式有 $3\times8-2=22$ 格；長度改成 16 時，兩者為 256 與 46 格。

:::supplement[來源：Longformer 3.1；本頁固定連結規則]
把第一詞元指定為全域點，讓它讀全部位置，也讓每個位置讀它。八詞元局部原有 22 格，加上第一列缺的六格及第一欄缺的六格，合計 34 格；十六詞元同理為 74 格。

這是示範連結數，不是 Longformer 實測速度。關鍵線索若不在同一視窗，可經全域點或多層傳遞，但效果仍須由任務驗證。
:::

## 程式（補充）

程式只計有向連結，不實作三種模型。近似方法沒有對應的二元刪邊遮罩，因此不把它硬換算成局部配對數。

```python
for length in (8, 16):
    pairs = [(i, j) for i in range(length) for j in range(length)]
    local = {(i, j) for i, j in pairs if abs(i - j) <= 1}
    global_pairs = {(i, j) for i, j in pairs if i == 0 or j == 0}
    print(f"長度 {length}: 密集 {len(pairs)}, 局部 {len(local)}, "
          f"局部加全域 {len(local | global_pairs)}")
```
```text
長度 8: 密集 64, 局部 22, 局部加全域 34
長度 16: 密集 256, 局部 46, 局部加全域 74
```

:::tip[讀碼重點]
`local | global_pairs` 取集合聯集，局部與全域都包含的連結只算一次。這段只列舉連結，沒有實作稀疏加速。
:::

## 怎麼用、怎麼判讀

指引的資料條件是數千到數萬詞元的長序列。先確認重要資訊的距離，再比較成本；相鄰資訊足夠的任務可先考慮局部模式。

:::supplement[來源：Longformer 3.1、6；Reformer；Performer 2、4]
需要遠距關聯時，可保留全域位置、用內容分桶，或採近似的全域注意力。分別檢查跨段問答表現、分桶遺漏與近似誤差，同時量測實際峰值記憶體和延遲。
:::

### 換個場景

| 場景 | 資料條件 | 判讀重點 |
|---|---|---|
| 長序列處理 | 數千至數萬詞元 | 平方成本是否超出預算 |
| 法律長契約（補充） | 定義和例外跨段 | 不能只保留局部線索 |
| 農業高解析影像（補充） | 區塊數很多 | 局部病斑與跨區域關係兼顧 |
| 語音逐字稿（補充） | 跨段指代 | 驗證遠距證據是否保留 |

## 常見誤解

- 「局部和稀疏一定是互斥的類別。」局部視窗可視為稀疏模式的一種。
- 「遮掉大部分分數就會省下密集運算。」需要對應的稀疏實作。（補充）
- 「Performer 只能看鄰居。」它是近似注意力核，不是固定局部遮罩。（補充）
- 「更長輸入一定更準。」成本下降不保證關鍵資訊學得更好。（補充）

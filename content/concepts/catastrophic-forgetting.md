## 為什麼需要（補充）

客服模型學會新產品，卻開始答錯原有服務；能源模型適應新季節，卻失去仍需處理的舊設備模式。接續更新時，新任務進步不代表整體服務能力都進步。

災難性遺忘（Catastrophic Forgetting）指順序學習後舊能力顯著退化。本頁把新能力與舊能力分開驗證，避免單一平均分數蓋住損失。

## 直覺（補充）

共享參數同時支撐許多能力。只拿新任務更新時，梯度會偏向當前資料；改動可能破壞原先對舊任務有用的表示或決策。

![新任務虛線上升時，舊任務實線下降；兩條線都用各自固定16筆留樣，觀察保留與適應的拉扯。](figure:l23304-catastrophic-forgetting-retention)

## 定義與公式（補充）

診斷需比較同一舊任務、同一評分規則在更新前後的結果。新任務也另外留樣；留樣不參與微調或重播，才能看見能力轉移的代價。

| 方法 | 改變什麼 | 可能的代價 |
|---|---|---|
| 全量微調 | 所有可訓練權重 | 適應自由度大，也可能改壞舊能力 |
| 凍結部分層 | 限制可改動的權重 | 新任務需要的表示可能學不到 |
| 低秩更新 | 限制新增更新的子空間 | 帶適配器的函數仍可能忘記 |
| 混合舊資料 | 新批次加入舊訓練樣本 | 儲存、授權與新任務曝光量成本 |

凍結主幹但更新共用輸出層，舊預測仍可能改變。若另保留完整舊路徑、舊輸出頭及推論狀態，舊路徑可重用，但需另外管理任務路由與版本。

LoRA保存原權重並加入低秩更新，帶著更新運作的模型仍是改變後的函數。切回原模型或停用適配器，可恢復該基底路徑，不等於新舊能力已在同一模型內相容。

## 走一次流程（補充）

共用資料的能源與客服各128筆，沿用訓練96、驗證16、測試16的固定索引。這裡另設舊、新任務的16筆驗證正誤遮罩，為教學設計，不是從原模型實測得出。

1. 更新前，舊任務對15筆，正確比例93.75%；新任務對8筆，為50%。先存下基準模型與兩份結果。
2. 只用新任務訓練資料更新12輪。舊任務變10筆、62.5%；新任務變15筆、93.75%。
3. 舊能力下降31.25個百分點，新能力上升43.75個百分點。固定的舊留樣退步，支持進一步檢查遺忘。
4. 排除輸入格式、標註、評分器或推論模式變更。若評估條件變了，不能直接把全部落差歸因於遺忘。
5. 回到同一更新前模型，各自只改一項策略，保留12輪與固定批次預算，比較下面兩項結果。

| 策略 | 舊正確／16 | 新正確／16 | 達成兩邊各14筆？ |
|---|---|---|---|
| 全量微調 | 10 | 15 | 否，舊能力不足 |
| 凍結主幹 | 14 | 12 | 否，新能力不足 |
| 低秩更新 | 13 | 14 | 否，舊能力不足 |
| 混合舊資料 | 14 | 14 | 本次達標 |

混合策略每批仍16筆，其中舊4筆、新12筆；其他策略每批新16筆。總處理筆數相同，但新任務曝光量減少，是重播策略的代價，不代表比較條件完全一樣。

保留的舊樣本來自訓練區段，不能把上述舊驗證留樣放回訓練。16筆太少，一筆便差6.25個百分點；需更多代表性留樣與重複實驗，不能宣布重播普遍最佳。

## 程式（補充）

本段只加總固定逐筆正誤，並不執行LoRA或大型模型微調。先將`IPAS_REPO_ROOT`設為repo絕對路徑。

```python
import json, os
from pathlib import Path
d = json.loads((Path(os.environ['IPAS_REPO_ROOT']) / 'content/examples/L23304-B-training.json').read_text(encoding='utf-8'))
for domain in ('energy', 'text'):
    scores = d['domains'][domain]['forgetting']['strategies']
    print(domain)
    for name, result in scores.items():
        old, new = sum(result['old']), sum(result['new'])
        print(name, f'{old}/16 {new}/16', '達標:', old >= 14 and new >= 14)
```

freeze 14/16 12/16 達標: False
lora 13/16 14/16 達標: False
replay 14/16 14/16 達標: True
text
before 15/16 8/16 達標: False
full 10/16 15/16 達標: False

:::tip[讀碼重點]
old與new分開計數，再檢查是否同時達標。兩領域數字刻意一致方便核對，不表示能源與客服真實退化幅度相同。
:::

## 怎麼用、怎麼判讀（補充）

先決定哪些舊能力仍屬服務承諾，再設定可接受退化與新任務目標。若舊概念已不再有效，可能應該適應新分布；保留所有歷史行為不一定正確。

資料漂移描述輸入分布改變，概念漂移描述輸入與目標的關係改變；遺忘關注模型更新後的舊能力損失。它們可能同時發生，但不是同義詞。

先比較凍結、限制更新或重播，再看雙任務驗證與成本。沒有一種方法保證消除遺忘；資料保存規範、任務衝突與代表性都會限制效果。

### 換個場景（補充）

| 場景 | 要保留什麼 | 判讀重點 |
|---|---|---|
| 能源季節更新 | 仍在役的舊設備模式 | 依設備及季節分開留樣 |
| 客服新品訓練 | 原產品與通用問答 | 新舊能力均需達服務門檻 |
| 醫療影像更新 | 舊院所及舊設備表現 | 重播受資料使用權限限制 |
| 多語文字模型 | 原語言理解能力 | 單語微調後逐語言測試 |

## 常見誤解（補充）

- **新任務上升就代表更新成功。** 還要看仍需支援的舊能力。
- **凍結或LoRA保證不忘。** 更新的頭、適配器及推論路徑仍可能改變結果。
- **重播要混入歷史驗證資料。** 重播用合法訓練資料，留樣保持獨立。
- **退步都叫遺忘。** 先排查評分、前處理、推論模式及任務定義是否改變。

## 進階

### 重要權重的保護（補充）

除了凍結、低秩與重播，也可用正則化減少對舊任務重要權重的改動。Kirkpatrick等人的研究提出這類方向；重要性估計及任務差異仍影響效果，不是無條件保證。

### 參考來源

- [Kirkpatrick等人：Overcoming catastrophic forgetting](https://arxiv.org/abs/1612.00796)：支持定義、共享權重改動與重要權重保護。
- [Rolnick等人：Experience Replay for Continual Learning](https://arxiv.org/abs/1811.11682)：支持混合歷史經驗的處理方向與保留／適應比較。
- [LoRA原論文](https://arxiv.org/abs/2106.09685)：支持凍結原權重並加入低秩更新；不作為不遺忘的保證。
- [PyTorch遷移學習教學](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial.html)：支持凍結特徵萃取器與重訓輸出層的區別。
- [Avalanche訓練教學](https://avalanche.continualai.org/from-zero-to-hero-tutorial/04_training)：支持順序經驗、基準策略與重播比較的教學流程。
- 科目1指引`guide-1:3-64`：已核對PDF，僅作指定來源落差說明，不當成本頁定義及策略的依據。

## 小結（補充）

- 固定新舊留樣，比較更新前後，才能看見能力取捨。
- 凍結、低秩與重播有不同成本，都沒有普遍保留保證。
- 舊任務退步先排查評估條件，再判斷遺忘。
- 以雙任務門檻及重複驗證決定是否接受更新。

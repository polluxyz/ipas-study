## 為什麼需要

序列的重要訊號可能相隔很遠。逐步更新狀態是一種方式，沿時間方向用卷積擷取歷史模式，則是另一種方式。（補充）

時序卷積網路簡稱 TCN（Temporal Convolutional Network）。指引強調它處理長期相依的穩定性；本頁補充如何追蹤它可讀取的歷史。

## 直覺

### 只往歷史找資料（補充）

因果卷積（Causal Convolution）只讀當下與過去。擴張卷積（Dilated Convolution）在取樣點之間留間隔，讓疊層後可看見更長的歷史。

![先沿第二層箭頭找中間位置，再往第一層展開，第八點可見第二至第八點。](figure:l23302-temporal-convolutional-network-field)

圖中每層只有一個卷積。第二層讀中間位置 4、6、8；第一層再把這三點展開，得到原始輸入 2–8，沒有第 9 點。

## 定義與公式

### 因果與感受野（補充）

對單通道、核寬 k、擴張率 d 的因果卷積，可寫成：

$$
u_t=b+\sum_{j=0}^{k-1}w_jx_{t-jd}
$$

$x_t$ 是第 t 點輸入，$u_t$ 是卷積輸出，$w_j$ 是第 j 個權重，$b$ 是偏差。索引只會小於或等於 t；最左側超出序列的部分，本例補零。

以下是本站自行推廣的逐層核寬感受野總式，原文只直接列出固定核寬的情況。堆疊 L 層、每層各一個卷積且步幅都是 1 時：

$$
R=1+\sum_{\ell=1}^{L}(k_\ell-1)d_\ell
$$

$R$ 是最遠到最近的感受野跨度，$k_\ell$ 與 $d_\ell$ 分別是第 l 層的核寬及擴張率。此式假設沒有改變時間尺度的池化或步幅；跨度也不保證任意擴張配置都填滿每個歷史位置。

本例核寬都是 3、擴張率為 1 與 2，因此 $R=1+2\times1+2\times2=7$，且這個配置確實覆蓋連續七點。

Bai 等人第 3.4 節的殘差區塊含兩個卷積。同一區塊若放兩次相同擴張率，計算時兩次都要加進去，不能把「區塊數」直接當成本頁的層數。

因果卷積的求和核心見 Bai 等人第 3.3 節式 (2)；偏差項及框架的卷積定義另見 PyTorch Conv1d 文件。

Shang 等人「Temporal convolution network」式 (2) 直接列出固定核寬 k 的跨層感受野總和，擴張率由各層陣列指定；原文未直接列出逐層不同核寬的完整總式。

本頁按層寫成 $k_\ell$ 是本站推廣：在上述步幅與時間尺度條件下，沿各層追蹤最遠歷史索引，將每層增加的延遲逐項相加，再計入當下點，得到跨度。

這段推導不等於原文直接列式，也不表示跨度內每點都可達。

## 算一次

:::supplement[來源：Bai 等人 2018 第 3 節；本站 L23302-A 教學合成資料]

共用資料的 `tcn.input` 是 1–8，用來代表已做尺度換算的八週輸入。這個小張量專供讀碼，不是耗電預測值，也沒有進行訓練。

兩層權重都設成 1、偏差為 0。第一層核寬 3、擴張率 1，第 4、6、8 點分別得到 2＋3＋4＝9、4＋5＋6＝15、6＋7＋8＝21。

第二層擴張率 2，第 8 點加總這三個中間值：9＋15＋21＝45。這是卷積特徵；若要預測第 9 週耗電，還要接輸出頭並用第 9 週標籤訓練。
:::

## 程式（補充）

以下只實作 TCN 的兩層因果卷積核心，沒有殘差、激活函數及預測頭。PyTorch 的 `Conv1d` 輸入順序是「批次、通道、時間」。

```python
import json, os, torch
import torch.nn.functional as F
from pathlib import Path
root = Path(os.environ.get("IPAS_REPO_ROOT", "."))
d = json.loads((root / "content/examples/L23302-A-weekly.json").read_text(encoding="utf-8"))
x = torch.tensor(d["tcn"]["input"], dtype=torch.float32).reshape(1, 1, -1)
w = torch.ones(1, 1, 3)
def core(z):
    h = F.conv1d(F.pad(z, (2, 0)), w, dilation=1)
    return F.conv1d(F.pad(h, (4, 0)), w, dilation=2)
y = core(x)
z = x.clone(); z[0, 0, -1] = 800
print("輸出:", y.flatten().tolist())
print("只改第 8 點，前 7 點不變:", torch.equal(y[..., :7], core(z)[..., :7]))
```
```text
輸出: [1.0, 3.0, 7.0, 12.0, 19.0, 27.0, 36.0, 45.0]
只改第 8 點，前 7 點不變: True
```

:::tip[讀碼重點]
`F.pad(z, (2, 0))` 只補左側，第二層因擴張率為 2 改補 4 點。核全為 1，因此不受框架權重排列方向影響；實際學習時仍須依 API 的交叉相關慣例讀權重。
:::

## 怎麼用、怎麼判讀

指引把 TCN 列為處理長期相依較穩定的候選。是否適合仍要與 RNN 類及統計模型，在相同預測期與資料條件下比較。

:::supplement[來源：Bai 等人 2018 第 3 節；PyTorch Conv1d 文件]
先看感受野是否夠長，再看歷史視窗是否真的提供那些資料。本例雖輸入八點，第八點輸出只讀到七點；增加輸入長度卻不改架構，不能讓它自動讀到更早歷史。

因果卷積也不能修復特徵工程的資料洩漏。若縮放用完整序列估計，或輸入含未來才有的統計量，仍不符合預測當時的資訊條件。
:::

## 常見誤解

- 「擴張率 2 就只保留一半資料。」它改變取樣間隔，堆疊後仍可能覆蓋完整區段。（補充）
- 「因果卷積可以看當下，所以能直接預測當下。」預測未來仍須移動目標，不能讓輸入含目標值。（補充）
- 「左側補零就是新增真實歷史。」序列起點看到的是人工補值。（補充）
- 「感受野夠長就保證學到長期相依。」它只描述資訊可達範圍。（補充）

## 小結

- 因果限制讀取方向，擴張率改變歷史取樣間隔。（補充）
- 感受野要按實際卷積數、核寬、擴張率與步幅核算。（補充）
- 可讀到某段歷史，不保證模型一定學到其中關係。（補充）
- 檢查單側補值、目標位移與特徵取得時間。（補充）

## 為什麼需要（補充）

推薦清單與搜尋結果有先後之分。同樣 5 部影片，最愛的排第 1 與排第 5，使用者的感受差很多。

[[accuracy]] 與 [[f1-score]] 只問判對沒有，不問順序。[[roc-auc]] 只分相關與不相關兩級，說不出「很相關」與「略相關」的差別。

NDCG（Normalized Discounted Cumulative Gain，正規化折損累計增益）是專門量排序品質的指標：相關度高的項目排得越前面，分數越高。

## 直覺（補充）

本頁用一個影片推薦的教學模擬情境。系統替一位使用者排出 5 部候選影片，使用者事後給每部相關度（Relevance，這部對使用者有多合用）：0 沒興趣、1 略有興趣、2 喜歡、3 非常喜歡。

依系統的名次，5 部影片的相關度依序是 1、3、0、2、3。最愛的兩部排在第 2 與第 5 名，沒興趣的卻排第 3 名，排得並不理想。

NDCG 把這個「不理想」變成一個 0 到 1 的數字，靠三個想法：

- 相關度越高，貢獻越大。這是增益（Gain）。
- 名次越後面，貢獻打越多折。使用者較少看到後面的項目，這是折扣（Discount）。本頁把每個名次的折扣寫成一個乘上去的折扣因子。
- 拿同一批項目的最佳排法當 1。這是理想排序（Ideal Ranking）。

:::tip[重點]
同一部影片放在第 1 名與第 5 名，貢獻不一樣。NDCG 衡量的是「該放前面的有沒有放前面」，不只是「有沒有挑到」。
:::

## 定義與公式（補充）

本頁的相關度都是非負數，並先假設 IDCG 大於 0（IDCG 為 0 的情況見下面的邊界情況）。

名次 $i$ 的項目相關度記為 $\mathrm{rel}_i$，只看前 $k$ 名時的 DCG（Discounted Cumulative Gain，折損累計增益）是：

$$
\mathrm{DCG}_k=\sum_{i=1}^{k}\frac{\mathrm{rel}_i}{\log_2(i+1)}
$$

每個名次的增益乘上折扣因子 $1/\log_2(i+1)$，再把各名次的貢獻加總。

名次 1 的因子是 1，不打折；名次 3 的因子是 0.5，打對折（$\log_2 4=2$）。本頁 $k=5$，看全部 5 名。

IDCG（Ideal DCG，理想 DCG）把同一批候選項目依相關度由大到小重排，再算一次 DCG。

重排的範圍是完整候選集，算 @$k$ 時才取理想順序的前 $k$ 名；不是先截實際的前 $k$ 項再只用這 $k$ 項重排。NDCG 是兩者的比值：

$$
\mathrm{IDCG}_k=\sum_{i=1}^{k}\frac{\mathrm{rel}^{*}_i}{\log_2(i+1)},\qquad
\mathrm{NDCG}_k=\frac{\mathrm{DCG}_k}{\mathrm{IDCG}_k}
$$

$\mathrm{rel}^{*}_i$ 是重排後名次 $i$ 的相關度。IDCG 大於 0 時，排得和理想一樣好則 NDCG 為 1，否則小於 1。

增益有兩種常見約定，要先確認用的是哪一種：

- 線性 gain：增益就是 $\mathrm{rel}_i$。scikit-learn 的 `dcg_score`、`ndcg_score` 用這一種。
- 指數 gain：增益是 $2^{\mathrm{rel}_i}-1$（Burges 2010 §3 式 (5) 採用這種寫法）。相關度 3 對 1 的權重比從 3 倍拉大到 7 倍。

三個邊界情況要先講好：

- IDCG 為 0（所有項目相關度都是 0）：NDCG 是 0 除以 0，沒有定義。做法要事先約定，記 0 或排除，scikit-learn 回傳 0。
- 分數同分：同分項目的先後不確定，DCG 會因排法而變。scikit-learn 預設（`ignore_ties=False`）把同分項目的增益取平均。
- 項目數不足：只有 1 個項目且相關度大於 0 時，公式值恆為 1，但沒有排序可比。scikit-learn 要求至少 2 個項目，否則直接報錯。

:::caution[注意]
不同約定的 NDCG 數字不能互相比較。報告時寫明 gain 的約定、折扣的形式與 $k$。
:::

## 算一次（補充）

把名次、折扣因子與貢獻列成表。「實際」欄用系統的名次與相關度 1、3、0、2、3；「理想」欄用重排後的相關度 3、3、2、1、0。

| 名次 $i$ | 折扣因子 $1/\log_2(i+1)$ | 實際：相關度 × 因子 | 理想：相關度 × 因子 |
|---|---|---|---|
| 1 | 1.000 | 1 × 1.000 = 1.000 | 3 × 1.000 = 3.000 |
| 2 | 0.631 | 3 × 0.631 = 1.893 | 3 × 0.631 = 1.893 |
| 3 | 0.500 | 0 × 0.500 = 0 | 2 × 0.500 = 1.000 |
| 4 | 0.431 | 2 × 0.431 = 0.861 | 1 × 0.431 = 0.431 |
| 5 | 0.387 | 3 × 0.387 = 1.161 | 0 × 0.387 = 0 |
| 合計 | | DCG ≈ 4.9147 | IDCG ≈ 6.3235 |

格內數字取 3 位小數，合計用未四捨五入的值相加。於是：

$$
\mathrm{NDCG}_5=\frac{4.9147}{6.3235}\approx 0.7772
$$

驗算改用逐名次比較：理想貢獻減實際貢獻。名次 1 差 $2.000$，名次 3 差 $1.000$，名次 4 差 $-0.431$，名次 5 差 $-1.161$。

四項相加約 1.409，等於 IDCG 減 DCG。1.409 ÷ 6.3235 ≈ 0.223，所以 NDCG = 1 − 0.223 = 0.777，與上面吻合。

只看前 3 名時，實際前三項的相關度是 1、3、0，DCG 是 2.893。

理想前三項從全部 5 項取最大的 3 個，相關度是 3、3、2，IDCG 是 5.893。NDCG 約 0.4909。前 3 名放得差，分數比 0.7772 低很多。

本例只比較固定候選集內的排序。若要連漏找的相關項目一起評估，評估用的相關項全集與理想基準必須先統一，不能各模型自行縮小候選集。

改用指數 gain，增益變成 1、7、0、3、7，理想排序的增益是 7、7、3、1、0：

$$
\mathrm{NDCG}_5=\frac{1+7(0.631)+0+3(0.431)+7(0.387)}{7+7(0.631)+3(0.5)+1(0.431)+0}\approx\frac{9.4165}{13.3472}\approx 0.7055
$$

同一份排序，兩種約定得到 0.7772 與 0.7055。排序沒變，是 gain 的算法讓高相關度占的比重不同。

## 程式（補充）

用 scikit-learn 算同一份資料。`y_true` 放相關度，`y_score` 放系統的分數，函式依分數由大到小決定名次。兩個參數的形狀都是（使用者數, 項目數）。

```python
import numpy as np
from sklearn.metrics import dcg_score, ndcg_score

rel = np.array([[1, 3, 0, 2, 3]])    # 名次 1 到 5 的實際相關度
score = np.array([[5, 4, 3, 2, 1]])  # 分數遞減：照這個順序排

print(round(dcg_score(rel, score), 4))
print(round(ndcg_score(rel, score), 4))
print(round(ndcg_score(rel, score, k=3), 4))
print(ndcg_score([[0, 0, 0]], [[3, 2, 1]]))  # 全不相關：IDCG = 0

# 手寫 2^rel − 1 的約定，結果和 sklearn 不同
factor = 1 / np.log2(np.arange(2, 7))  # 名次 1..5 的折扣因子
dcg = lambda r: ((2.0 ** np.array(r) - 1) * factor).sum()
print(round(dcg(rel[0]) / dcg(sorted(rel[0], reverse=True)), 4))
```

```text
4.9147
0.7772
0.4909
0.0
0.7055
```

:::tip[讀碼重點]
- 第 1、2 行輸出是 DCG 4.9147 與 NDCG 0.7772，和上一節手算一致；第 3 行 `k=3` 的 0.4909 也一致。
- 第 4 行：全不相關時 IDCG 為 0，scikit-learn 回傳 0.0，不是報錯。
- 第 5 行是手寫的 `2 ** rel - 1` 約定，得 0.7055，和手算一致，也證明 scikit-learn 用的是線性 gain。
- `np.arange(2, 7)` 是 2 到 6，對應名次 1 到 5 的 `i+1`，所以 `factor` 就是五個折扣因子。`(增益 * factor).sum()` 先把每名次的增益乘上因子，再用 `.sum()` 加成 DCG。
- `y_score` 是分數，不是名次：要排第 1 的項目要給最大的數。傳成名次（1 最前）會把順序整個反過來。
:::

## 怎麼用、怎麼判讀

NDCG 可用於推薦系統與行銷的排序任務。

:::supplement[來源：scikit-learn 官方文件 ndcg_score、dcg_score API 頁面]
它適合清單有先後、相關度有多個等級的任務，例如搜尋與廣告排序。

判讀時先看它的範圍與基準：

- 相關度不為負時，NDCG 在 0 到 1 之間；1 表示排序已等同理想排序。
- 要比較的是「同一批候選項」的不同排法，所以要用同一份 gain 與折扣約定。理想排序也取自這一批候選項。
- 使用者通常只看前幾筆時，改用 NDCG@$k$，並讓 $k$ 對應實際看的筆數。

多位使用者時，每人各算一個 NDCG 再平均。把多列資料傳給 `ndcg_score`，它回傳各列的平均。例如 0.7772 與 1.0 的平均是 0.8886。

選指標時，先問想回答什麼：

| 想回答的問題 | 優先看 |
|---|---|
| 清單前面有沒有放對，相關度有多級 | NDCG@$k$ |
| 項目只分相關／不相關，整體分得開嗎 | [[roc-auc]] |
| 固定閾值下，警報準不準、漏多少 | [[precision]]、[[recall]] |

NDCG 是離線指標，相關度來自人工標註或歷史點擊。它不能直接代表上線後的點擊率或營收，這些要靠線上實驗確認。

:::

### 換個場景

指引 5-25 把推薦系統與行銷列為商業應用，同段列出的指標名稱包括 NDCG 與 Profit Score。主例子的影片推薦屬於推薦系統。

:::supplement[來源：scikit-learn 官方文件 ndcg_score、dcg_score API 頁面]
主例子是影片推薦。換到其他領域，相關度怎麼定、$k$ 怎麼選、判讀時要小心什麼，都會不同。

| 場景 | 相關度怎麼來 | $k$ 怎麼選 | 判讀要小心 |
|---|---|---|---|
| 電商搜尋 | 依使用者行為分級，例如購買 3、加入購物車 2、點擊 1、無動作 0 | 對應首頁一次能看到的商品數 | 分級是設計出來的，換一套分級，NDCG 就不能和舊數字比 |
| 客服知識庫 | 人工標註「這篇能解決問題」記 1，否則記 0 | 客服人員多半只看前 3 篇，取 $k=3$ | 只有 0 與 1 兩級時，兩種 gain 約定的增益相同（$2^1-1=1$、$2^0-1=0$），NDCG 仍會因名次不同而變 |
| 廣告排序 | 歷史點擊 | 對應畫面上同時露出的廣告數 | 排在前面的廣告本來就容易被點，歷史點擊會偏袒原本排前面的項目。離線 NDCG 高，不保證線上營收高 |

三個場景的共同點：理想排序都取自同一批候選項，所以比較兩版排序時，候選集與 gain、折扣約定要一致。

:::

## 常見誤解（補充）

- **「NDCG 等於 1 代表每個項目都很相關。」** 不是。1 只表示排序等同理想排序。若 5 部影片的相關度都是 1，任何排法的 NDCG 都是 1。
- **「DCG 夠大就是好模型，可以跨使用者直接比。」** 不行。清單長度與相關度不同，DCG 的量級就不同。除以 IDCG 之後才能比較與平均。
- **「NDCG 高代表模型把相關項目都找出來了。」** 不一定。NDCG 只看給定候選集內的排序，理想排序也取自這個集合。沒進候選集的相關項目不在計算內，不會被扣分。要連漏找一起評估，得先統一相關項全集與理想基準，不能各模型自行縮小候選集。
- **「不同 gain 約定的 NDCG 可以直接比。」** 不行。上例同一份排序，線性 gain 得 0.7772，指數 gain 得 0.7055。
- **「換對數底數會改變 NDCG。」** 不會。底數只讓所有折扣因子乘上同一個常數，分子與分母同時消掉。

## 進階（補充）

### 對數底數與原論文的折扣起點（補充）

對數換底後，$\log_b x=\log_2 x/\log_2 b$。所有名次的折扣因子都乘上同一個常數，DCG 的大小會變，但 NDCG 的分子與分母同時縮放，比值不變。

原論文（Järvelin 與 Kekäläinen，2002）的寫法不同：名次小於底數 $b$ 的項目不打折，從名次 $b$ 起才除以 $\log_b$ 名次。$b=2$ 時，名次 1 與 2 都不打折。

scikit-learn 與多數實作改用 $1/\log_2(i+1)$，名次 2 就開始折扣。比較不同來源的 DCG 數字前，先確認折扣形式。

### 同分的實際效果（補充）

同一份相關度，若 5 個項目分數全相同，scikit-learn 預設把增益取平均 1.8。DCG ≈ 1.8 × 2.948 ≈ 5.307，NDCG ≈ 0.8393。

`ignore_ties=True` 的意思是「假設沒有同分」，只取其中一種次序，同一份資料得 0.9395，不是處理同分的方法。沒有同分時兩種設定的結果相同。

## 小結（補充）

- NDCG 以「相關度 × 折扣因子 1/log2(名次+1)」累加成 DCG，再除以同一批項目的理想排序 IDCG，得到 0 到 1 的分數。
- 本頁例子：相關度 1、3、0、2、3 的排序，DCG 4.9147、IDCG 6.3235、NDCG 0.7772。
- gain 有線性（scikit-learn）與 $2^{\mathrm{rel}}-1$ 兩種約定；同一份排序分別是 0.7772 與 0.7055，不可混著比。
- IDCG 為 0 時沒有定義，要事先約定；同分項目要有規則，scikit-learn 預設取平均。
- NDCG 只評估給定候選集內的排序，是離線指標，不等於上線成效。

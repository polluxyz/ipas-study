## 為什麼需要

模型訓練只是開發的一部分。資料定義、清理、驗證調整與最終測試若順序混亂，漂亮的成績可能來自看過答案。

完整流程讓每一步的輸入與用途清楚：哪份資料用來學參數，哪份用來選設定，哪份保留到最後。

## 直覺

訓練集用來學；驗證集用來決定下一次怎麼改；測試集在設定確定後做最終評估。調整可以反覆，測試資料不能跟著成為調參依據。

## 走一次流程

### 準備與學習

先明訂輸入、標籤與任務，蒐集資料並檢查品質；再訓練模型，使輸出與標籤的差距縮小。

### 驗證與調整

使用驗證資料比較模型結構與超參數。驗證表現不佳時，回頭檢查資料或設定，再用訓練資料學習。

### 測試與部署

設定確定後，在測試資料評估最終效能。通過需求門檻後，才將訓練完成的預測流程投入應用。

### 用固定索引走完（補充）

兩領域都用種子 42 排列 120 筆索引：前 72 筆訓練、接著 24 筆驗證、最後 24 筆測試。原始順序不帶時間或群組，這是可交換樣本的教學設定。

| 步驟 | 使用資料 | 本次動作 |
|---|---|---|
| 準備 | 欄位定義與訓練資料 | 檢查單位、類別與缺漏 |
| 學習 | 72 筆訓練 | 擬合深度 2 的樹 |
| 驗證回饋 | 24 筆驗證 | 答對 18 筆，嘗試深度 4 |
| 再學習與選型 | 同一訓練／驗證索引 | 深度 4 答對 19 筆，依事先規則選它 |
| 最終測試 | 24 筆測試 | 鎖定後答對 16 筆，記錄與驗證落差 |

驗證只差一筆，不足以宣稱深度 4 普遍較好。本例先以驗證答對數選型，同分時選深度較小的樹。

最終 16/24 也提醒我們，小資料的估計會波動。

## 程式（補充）

下列重建與 JSON 相同的資料。完整例子分成兩段，在同一個 Python 程序依序執行。

```python
import numpy as np
i = np.arange(120)
X = np.column_stack((i % 12, i // 12))
y = (X.sum(axis=1) >= 10).astype(int)
y[i % 19 == 0] = 1 - y[i % 19 == 0]
order = np.random.default_rng(42).permutation(120)
train, val, test = order[:72], order[72:96], order[96:]
print("資料形狀", X.shape, "切分", len(train), len(val), len(test))
```
```text
資料形狀 (120, 2) 切分 72 24 24
```

先印兩個設定的驗證結果，選定後才執行一次測試預測。

```python
from sklearn.tree import DecisionTreeClassifier
candidates = []
for depth in [2, 4]:
    model = DecisionTreeClassifier(max_depth=depth, random_state=42)
    model.fit(X[train], y[train])
    correct = int((model.predict(X[val]) == y[val]).sum())
    candidates.append((correct, depth, model))
    print("深度", depth, "驗證答對", correct)
best = max(candidates, key=lambda row: (row[0], -row[1]))
print("選定深度", best[1])
print("測試答對", int((best[2].predict(X[test]) == y[test]).sum()))
```
```text
深度 2 驗證答對 18
深度 4 驗證答對 19
選定深度 4
測試答對 16
```

:::tip[讀碼重點]
選型鍵先比答對數，再以負深度讓較淺的樹勝出同分。fit 沒有讀取測試資料；最後才使用 test，不能把測試移進候選比較迴圈。
:::

## 怎麼用、怎麼判讀

分類可看準確率、精確率與召回率等；迴歸可看均方誤差與平均絕對誤差。資料角色不因指標不同而改變。

:::supplement[來源：scikit-learn Common pitfalls 12.2]
由資料學得的補值、縮放及特徵選擇，也只能在訓練資料上擬合。新資料要套用相同轉換；部署的應是完整預測流程，而非只有模型權重。
:::

### 換個場景

| 場景 | 指引的任務或資料條件 | 判讀 |
|---|---|---|
| 郵件、流失、影像分類 | 有類別標籤 | 依驗證結果調整，再最終測試 |
| 房價與銷售量 | 有數值目標 | 更換指標，保留資料分工 |
| 醫療診斷（補充） | 同一病患有多筆 | 先依病患隔離資料 |
| 物流交期（補充） | 預測未來出貨 | 驗證與測試應晚於訓練 |

## 常見誤解

- 測試成績不佳就繼續拿同一測試集挑設定：這會使測試失去獨立性。（補充）
- 資料清理完才能切分：固定的格式檢查可以先做，但估計轉換參數須保留資料隔離。（補充）
- 只記分數不記切分，之後無法公平比較改動。（補充）

## 小結

- 先定義與準備資料，再訓練、驗證調整、測試部署。
- 驗證回饋可以改設定，測試不參與選型。
- 前處理也屬於要鎖定與部署的流程。（補充）

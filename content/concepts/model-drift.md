## 為什麼需要

「模型漂移（Model Drift）」在不同段落可能指不同現象。若只報這四個字，團隊無法知道要找真值算分，還是先查輸出及版本。

科目1指引4-30以預測準確度隨時間下降說明模型漂移；5-19則以模型預測分布不同描述它。閱讀時需要把觀察對象說清楚。

## 直覺

模型固定不代表成績固定。它仍使用舊規則，但新時期的個案或外部條件可能已經不同。

:::supplement[來源：CMU SEI〈Expecting the Unexpected〉How Can We Detect Drift?]
本組教學合成資料四期都用同一個v1模型、前處理與0.5閾值，完整回收真值後計分。折線只表示批次順序，不能把先後連線解讀成因果。
:::

![P0與P1準確率都是90%，P2與P3降為60%，四期模型及閾值都固定。](figure:l21203-model-drift-performance)

圖示範指引所說的效能隨時間衰退：先比較各期實測成績，再另外調查變差的原因。

## 定義與公式

效能衰退是以同一指標及一致評分規則，觀察模型在較晚資料上的成績變差。指引4-30將它放在模型穩定性風險下，4-42則建議追蹤資料或環境變化等可能原因。

| 觀察對象 | 要比較的東西 | 是否需要真值 |
|---|---|---|
| 效能衰退 | 準確率、錯誤率等成績 | 實測評分需要 |
| 預測分布變化 | 分數或預測類別的占比 | 不一定需要 |
| 參數更新（補充） | 權重、版本、部署紀錄 | 查版本即可 |

:::supplement[來源：Google Cloud Introduction to Model Monitoring]
本頁不用「模型漂移」推論權重自己改變。無真值時先記錄輸入及分數分布，待真值回收後再報實測準確率。
:::

## 走一次流程

指引要求監控效能並追蹤原因；把這兩件事分開記，才有可調查的回報。

### 用固定授信模型查核（補充）

沿用`L21203-C-drift.json`，閾值固定0.5。低組分數0.2判未違約，高組0.8判違約，真值1為違約；P0與P2兩組都各50人。

1. 固定版本：四期模型、切點與決策閾值不變。
2. P0組內違約率為10%／90%。低組未違約50−5＝45人、高組違約45人，正確90/100＝90%。
3. P2組內違約率為40%／60%。低組未違約50−20＝30人、高組違約30人，正確60/100＝60%。
4. 比較真值：兩組人數固定，違約率由10%／90%變40%／60%，是同條件關係改變的證據。

這是「固定模型仍衰退」的例子。關係改變的證據來自組內真值比較，不能只由準確率下降倒推。

預測陽性率是模型預測為正類的比例。P1由50%增為80%，準確率卻仍是90%，所以預測分布改變與效能下降也不能互換。

## 怎麼用、怎麼判讀

報告時寫成「哪個資料窗、哪個版本、哪個指標、從多少變多少」，並保留可能原因。輸入及條件關係的區分，見資料漂移與概念漂移。

:::supplement[來源：Google Cloud Introduction to Model Monitoring；CMU SEI 漂移教學]
真值必須與當時預測按個案及時間配對。授信只回收較早到期的案件時，不可把這個子集合當成整個當期的完整成績。

先查資料、標註、前處理及閾值，再評估是否重訓。版本改變是變更紀錄，不能單憑它宣稱效能改善。
:::

### 換個場景

| 場景 | 指引或案例的訊號 | 判讀重點 |
|---|---|---|
| 長期模型、環境變動 | 準確度隨時間下降 | 保留一致的比較基準 |
| 電商推薦 | 準確率下降後調整模型 | 不只觀察預測分布 |
| 授信（補充） | 到期違約真值延遲 | 先報可配對的回收範圍 |
| 視覺檢測（補充） | 人工複驗後漏檢增加 | 查相機、標註與關係 |
| 醫療分診（補充） | 診斷後回收結果 | 查病人組成及追蹤完整性 |

## 常見誤解

- 準確率下降是效能觀察，不是原因名稱。
- 預測陽性變多，不等於真陽性變多。（補充）
- 固定模型參數不保證固定效能；外部資料仍可能改變。
- 參數更新不等於效能衰退，也不等於改善。（補充）

## 進階

### 回報用語的範例（補充）

「P2完整回收100筆真值，v1在閾值0.5下準確率60%，參考P0為90%；模型與前處理未改。相同負債組內違約率已不同，待業務查明原因。」

這比「模型漂移了」多交代比較證據，也沒有把統計關係誤說成外部事件造成的因果。

## 小結

- 使用「模型漂移」時，說明指效能還是預測分布。
- 實測效能要有能與預測配對的真值。（補充）
- 固定模型也可能衰退；更新參數則是另一件事。

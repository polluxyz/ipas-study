# L21103-A 共用任務卡

本例是教學合成資料，沒有執行生成模型，也沒有真實影像、錄音或硬體結果。`L21103-A-task-cards.json` 含企業客服 C01–C12、製造設計 M01–M12；同索引對應相同任務角色。

## 欄位與固定規則

- `input`、`output`：輸入描述與預期交付，並非實測輸出。
- `input_modalities`、`output_modalities`：資料形式；標籤、索引、系統狀態、實體動作另列，不冒充新內容。
- `new_content`：是否合成新的內容表達；轉寫保留原話，所以記 false。它不決定模型的機率建模類別。
- `primary_capability`：本卡的主要驗收能力；`capabilities` 是可重疊的能力組合，並非互斥階段。
- C03、M03 檢索比對既有資料，沒有合成新內容，本組將其主要能力歸為感知；若加入規劃與行動回饋，須另判斷是否具備代理能力。
- `tools`：所需工具；固定檢索也是工具，但不因呼叫工具就自動成為代理。
- `label_requirement`：訓練、推論或驗收各需什麼證據；不是所有生成任務都無標籤。
- `acceptance`：查核交付的條件，不能當成已達成的測試成績。
- 每張卡的 `model_review`：版本、修訂編號、授權來源與日期為 null，狀態為「待查」；待選定模型後另做採用審查。
- `seed=42`：保留比較設定，本例沒有亂數抽樣；索引 1–8 為 walkthrough，9–10 為 practice，11–12 為 transfer。這是練習安排，不是訓練／驗證／測試切分。
- `model_review_template`：三家族的採用查核空白表。版本、revision、授權來源、核對日期仍是 null；頁面中的查閱快照不等於團隊已完成採用審查。

## 可核對的參考數值

每領域 12 卡：主要能力感知 3、生成 7、代理 1、物理 1；新內容 7、非新內容 5。全組 24 卡：感知 6、生成 14、代理 2、物理 2；新內容 14、非新內容 10。

每領域生成卡 04–10：純文字輸出 2、純圖像 1、純音訊 2、純影片 1、圖文混合 1。音訊包含語音及音樂；跨模態和上述類型可重疊，不能把它們相加當互斥分類。

## 使用頁面

- `ai-capability-types`：01、04、11、12 的能力差異與組合。
- `generative-discriminative-models`：01 的分類任務、04 的生成任務；同一輸入的不同學習目標。
- `generative-content-types`：04–10 的輸出模態；03 的檢索作為 CLIP 邊界案例。
- `open-weight-models`：04、05 的內部草稿需求與三家族採用查核表。

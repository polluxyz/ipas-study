# L21202-B 共用工作包

`L21202-B-work-packages.json` 為教學合成資料，客服問答與預測維護各六包。它們不是L21202-A的製造地端檢測或零售推薦案；沒有沿用、覆寫前置組的工時與預算。

## 欄位與固定規則

- `cases[].tasks`：`id`為案內固定工作包A至F，`name`為領域工作名稱，`predecessors`為完成到開始的直接前置，`duration_days`為持續工作日數。
- `owner`為主要負責人及角色；`hours`為包內總人時，已含檢查清單、子任務與驗收文件。兩案使用同樣的教學角色名稱，各案獨立計算，不假設兩案同時搶同一批真人資源。
- `resource`、`output`、`acceptance`分別為所需資源、交付版本與事先約定的通過條件。工時不能再按子任務重複加總。
- `group`為WBS成果群組；`sprint`是基準工作所屬輪次。`milestones`為零工期節點，分別在E與F之後，排程不把里程碑再算一天。
- 基準相依為A→B、A→C、B→D、C/D→E、E→F，工期2、3、4、2、3、1日。所有相依零間隔，無資源衝突，允許不同負責人並行，工期固定。
- 2026/11/02開始，週一至週五為工作日，不另扣假日；時間為從0開始的工作日邊界。ES=0表示11/02開始，EF=2表示11/03日終，不是11/04日終。
- 狀態快照為11/06日終、經過5個工作日：A/B完成、C進行中、D/E/F待辦。日期是計畫日期；快照不表示執行過真實專案。
- 每案資料索引0至99，訓練0至59、驗證60至79、測試80至99，種子42，版本各自固定；領域資料互不混用。沒有逐筆模型預測，16/20是教學驗收門檻，不宣稱已訓練或量測。
- 第一輪11/02–11/13，第二輪11/16–11/27，短衝是固定時間框。第一輪A至E形成可用原型，F在第二輪形成試用決議；回饋新增的原型更新須另估工時，不包含六包80人時。
- 四工具線框皆用客服案，保留同案ID、相依、狀態及期限；維護案在正文另作換景，不混入四工具比較。畫面不是產品截圖，也不宣稱全部方案均有示意功能。

## 核對數值

兩案各80人時、活動工期合計15日；並行基準工期11工作日。關鍵路徑A→B→D→E→F，總長11日；另一條A→C→E→F長10日。

順推ES/EF：A 0/2、B 2/5、C 2/6、D 5/7、E 7/10、F 10/11。逆推LS/LF：A 0/2、B 2/5、C 3/7、D 5/7、E 7/10、F 10/11。僅C總浮時1日，其餘為0。

計畫日期：A 11/02–03、B 11/04–06、C 11/04–09、D 11/09–10、E 11/11–13、F 11/16。M1為11/13日終，M2為11/16日終。D增加2日後，M1為11/17，M2為11/18。

資源衝突變體：B與C必須由同一人串行，先B再C，C 5/9、D 5/7、E 9/12、F 12/13，工期13日。額外完工緩衝2日為管理安排，與C的網路浮時不同；若承諾13日則對外日期11/18。

# L21202-C 選型、原型、成本與採用的共用例子

全部為教學合成資料，沒有實際訓練、部署、訪談、呼叫 API 或處理真實醫療紀錄。金額皆為新臺幣，單價不是任何產品的現行報價。

## 檔案與固定規則

- 新檔 `L21202-C-decision-inputs.json` 延伸 `L21201-C-poc-records.json`，用 `upstream.file` 與 SHA-256 確認來源。原檔的流程數字、問卷、12 則訪談與迭代紀錄不重編、不覆寫。
- 種子沿用 212013；每領域 100 個案件及相同索引。探索 80（一般 64、複雜 16）、確認 20（一般 16、複雜 4），跨領域使用相同位置、分開計算。
- 探索兩輪 r1/v1、r2/v2 可觀察；確認 r1 為 null，只在鎖定 v2 後評估一次。新版本若使用已揭露確認結果修改，須另收獨立確認資料。
- `domains[].requests` 是對原案件的 token 帳索引，不是再新增 100 筆測試。`flow_version` 指回原輪次，`token_profile=base` 是附加的合成規格，不表示原模型量過這些 token。

## 欄位與情境界線

- `requirements`：下一階段各六週、六個月支出上限 200,000 元。客服一名、醫療兩名工程師；醫療已預留算力且文件留院內。這是 POC 之後的方案比較，不改原 POC 的十萬元、六週上限。
- `sourcing_options`：三模式各兩領域的建置費、月費、估期、資源及限制。費用是簡化方案預估；未列項不代表真實專案沒有內部人力、移轉、測試等成本。
- `token_profile`：每次請求的靜態前綴、問題、歷史、檢索、預期輸出，以及壓縮後的歷史與檢索量。`daily_requests` 是新階段的每日假設流量，不是 100 筆試辦件數。
- `context_limit/output_reserve`：本例假設的上下文上限與輸出預留。實體長度由完整輸入加輸出預留核對，快取前綴仍占上下文。
- `pricing`：每 1,000 token 的普通輸入 0.02、輸出 0.04、快取讀取 0.002、快取寫入 0.025 元。假設服務無額外最低長度限制、每個未命中均建立快取，無儲存等其他費用；不是特定模型的費用預測。
- `cache_hit_fraction`：前綴完整命中的請求比例；客服 75%、醫療 50%，全數命中均覆蓋相同長度前綴，因此可直接加權。不是文字相似率，也不是任意 token 的命中率。
- `token_quality_scenarios`：v2 探索 80 筆的輸入策略反事實。基準、歷史摘要、檢索縮減及合併均設定 76 筆符合；過度摘要刪掉前四個符合案例，剩 72。這些是教學設定，不是執行模型量得的品質。
- `communication_actions`：連到既有訪談的溝通提案，狀態明列已做與待驗。`external_feedback_plan` 是兩則對外回饋演練提案，不是已收到或已修復的真實事件。
- `counterexamples`：自編的摘要遺失例，標明起算日、例外、欄位範圍、否定及人工確認等不能丟失的資訊。

原 POC 的每件執行費涵蓋範圍與這份 token 帳不同。不得用本檔估算替換原 `cost.runtime_twd_per_case`，也不得兩者相加後宣稱完整 ROI。

## 關鍵核對值

| 情境 | 普通輸入／次 | 輸出／次 | 每日生成費 |
|---|---|---|---|
| 客服基準 | 5,000 | 500 | 1,200 元 |
| 客服只做歷史摘要 | 3,800 | 500 | 960 元 |
| 客服只縮減檢索 | 4,200 | 500 | 1,040 元 |
| 客服合併兩項 | 3,000 | 500 | 800 元 |
| 醫療基準 | 6,000 | 600 | 288 元 |
| 醫療合併兩項 | 4,000 | 600 | 208 元 |

客服輸入量省 40%，總生成費省 400/1,200＝33.33%；客服只快取 800-token 前綴，h=0%、25%、75% 時每日 1,240、1,194、1,102 元，包含未命中的寫入費。合併摘要與檢索後再假設相同命中率，為 702 元，未宣稱實測可達。

六個月方案：客服商用 102,000、自研 156,000、委外 144,000 元；醫療商用 102,000、自研 192,000、委外 192,000 元。估期分別客服 2/6/4 週、醫療 2/6/8 週；金額達標不能抵銷資料或人員前提不符。

`ai-sourcing` 檢核 c3 沿用客服報價，另設必須改底層模型結構的需求。這是對照用的延伸情境，不改主例子「無須改模型結構」的條件；委外雖較貴，仍須優先檢查是否符合硬性需求。

原流程資料：客服探索採用 56/80→68/80、平均人工 6.5→5 分鐘、正確 74/80→76/80；醫療為 60/80→64/80、9→8 分鐘、74/80→76/80。v2 確認客服 19/20 正確、17/20 採用；醫療 19/20、16/20，醫療採用未達 85% 門檻。兩案第二輪問卷皆 5/6 願意繼續，分母與案件採用率不同。

## 使用與重建

- `ai-sourcing`：下一階段需求、六個月支出、供應選項。
- `rag-token-budget`：token 結構、流量、假設單價、摘要與檢索的品質反例。
- `rapid-prototyping`：沿用原檔的兩輪目標、回饋及技術／業務／使用者指標。
- `ai-change-management`：沿用原檔的訪談、問卷、採用；本檔提供待驗溝通行動及對外回饋演練。

重建：`node tmp/rollout/groups/W-L21202-C/generate-examples.mjs`。數值核算：同資料夾的 `examples-check.md`。輸入預算 SVG 由 `figure-scripts/token-budget.mjs` 讀本檔產生；流程 SVG 為作者自繪示意。

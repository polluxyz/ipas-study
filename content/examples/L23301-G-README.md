# L23301-G 共用例子

四頁共用零售點擊與能源資料，各40筆：20天×2個實體，每天18:00一列。資料為教學合成，固定規則生成，seed=42供後續比較記錄；本組沒有抽樣或模型訓練。

## 檔案與索引

- `L23301-G-retail.json`：顧客A/B的報價、每日點擊計數與未來24小時購買標籤。
- `L23301-G-energy.json`：電表A/B的運轉計畫、當日用電與未來24小時尖峰告警標籤。
- 兩檔同索引、同日期、同切分，索引0/1為10月5日A/B，2/3為10月6日A/B，以此類推。
- 訓練候選0–27；模型fit截止10月19日18:00。26/27的標籤於18:10才成熟，排除；實際訓練0–25，驗證28–33，測試34–39。

## 欄位與固定規則

| 欄位 | 意義 | 規則 |
|---|---|---|
| `event_time` | 當日18:00的預測截止點／觀察時點 | 含+08:00；同實體每日等距 |
| `available_time` | 當日clicks或usage可讀的時間 | 一般18:10；A的10月8日延至10月9日19:00 |
| `label_available_time` | 未來24小時目標可定案的時間 | 隔日18:10；不得提前把負例當已成熟 |
| `raw_text` | 截止點已有的短句原文 | 教學文字已用空白分詞，詞彙表固定4詞 |
| `target` | 未來24小時事件0/1 | 零售為購買，能源為尖峰告警 |

| 領域欄位 | 單位／意義 | 生成規則 |
|---|---|---|
| 零售price、quantity | 元／件、件；截止點報價與意向數量 | 以5天規則重複，乘積是報價總額，不是成交金額 |
| 零售clicks | 當日點擊次數 | A循環2、4、6、8、10；B每值加1 |
| 零售purchase_time | 未來購買時間 | 正例在當日20:00；負例為null，不作輸入 |
| 能源power_kw、planned_hours | kW、h；截止點已知計畫 | 乘積是計畫用電kWh，不是實測usage |
| 能源usage、temperature | kWh、°C | A用電循環10、20、30、40、50；B加5；氣溫已知 |

時間窗採`[cutoff−7天, cutoff)`，再檢查`available_time <= cutoff`。乘積只用當下已知欄位；歷史聚合按實體分組，不混合顧客或電表。`lag1`指前一日的原始格點；晚到資料保留缺值，不把更早一列冒充昨天。

文字表的欄順序由`vocabulary`決定。TF-IDF只在實際訓練26列fit；驗證與測試只能transform，未知詞不新增欄位。工作日教學定義為週一到週五，未套用國定假日與調班表。

## 關鍵參考數字與頁面

- `interaction-features`：R01報價30×2=60元；A在10月12日截止前7天點擊2+4+6+8+10+2+4=36。能源同窗用電180kWh；E01計畫2×3=6kWh。
- `temporal-features`：A在10月8日lag1=6、rolling3=4；10月9日lag1與完整rolling3皆缺值；10月10日lag1=10、rolling3=8。能源分別為30/20、缺值/缺值、50/40。
- `temporal-text-features`：零售訓練26篇的文件頻率為14、14、12、12，平滑IDF為1.5877866649、1.5877866649、1.7308875085、1.7308875085；程式關閉向量正規化以方便核對。
- `cyclic-time-features`：10月10日星期六=5；11日星期日=6；12日星期一=0。週日/週一圓周弦長約0.8677674782，整數差6；週一/週二弦長相同。

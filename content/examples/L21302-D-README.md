# L21302-D：版本、發布與擴量紀錄

`L21302-D-releases.json` 是零售推薦與製造檢驗共用的教學合成發布資料。沒有真實個資、訓練、負載測試或部署；觀測值是為練習門控而設計的固定紀錄。

## 與前置組的銜接

沿用 L21302-A 的產品命名：rec-v2、inspect-v3、retail-d1、manufacturing-d1、API v1、特徵規則 f1。前置組的 12 筆請求是介面回放，本組的 1,000 個索引是獨立的發布驗證描述；兩者不相加、不宣稱是相同切分或訓練資料。沒有修改前置例子。

## 固定規則

- 種子為 21302；所有值明列，沒有亂數抽樣。
- 同一領域三版共用資料描述、索引與切分：訓練 0～599、驗證 600～799、保留 800～999。保留集未用於候選挑選。
- `data_payload` 是資料描述替身，`code_payload` 是程式描述替身，`model_payload` 是權重描述替身。指紋核對的是這些實際 JSON 物件，不是外部 Git commit、影像或模型權重。
- SHA-256 的輸入使用遞迴鍵排序、緊湊 JSON；本組 payload 只含 ASCII。每版保存模型與程式指紋，資料指紋按領域保存。
- `environment=teaching-env-1` 為教學標記，不冒稱真實訓練環境。
- API v1、f1 在新舊版間相容；回復點包括舊版模型及這兩項規則。
- 教學發布清單為 retail-release-2、manufacturing-release-2；各指向該領域第二版及來源實驗。

## 欄位

| 欄位 | 意義 | 約束 |
|---|---|---|
| seed、split、split_sha256 | 固定種子與切分身分 | 兩領域共用索引規則 |
| domains.id、dataset、baseline | 領域、資料描述版及回復點 | 資料內容跨領域不同 |
| data_payload、data_sha256 | 資料描述與內容指紋 | 不是真實資料檔 |
| versions | 每領域三個固定候選 | 版號、run、程式與模型指紋 |
| gates | 發布與擴量標準 | 為教學假設，非產業標準 |

`offline_p95_ms` 是發布前效能上限；`online_p95_ms` 是線上暫停優化門檻；新增的 `rollback_p95_ms` 是線上延遲回復門檻。零售分別為 120／120／200 ms，製造為 80／80／100 ms；錯誤率 >1% 或品質低於門檻也會回復，並非只看延遲。

| 欄位 | 意義 | 單位或算法 |
|---|---|---|
| tests.passed／total | 單元測試結果 | 全部 20 項須通過 |
| validation.correct／count | 固定驗證集答對數 | 分母 200，門檻 93% |
| offline_p95_ms | 固定負載的教學紀錄 | 零售 ≤120 ms；製造 ≤80 ms |
| observations | 新版分階段觀測快照 | 各有版本、窗與發布清單 |
| traffic_pct、requests、minutes | 流量、新版請求與觀察長度 | 5%、30%、100%；分鐘 |

| 欄位 | 意義 | 單位或算法 |
|---|---|---|
| errors | 新版失敗請求數 | 除以同窗 requests |
| latency_histogram | 所有新版請求的延遲計數 | 最近秩 p95，計數和等於 requests |
| quality_good／quality_count | 零售點擊／曝光；製造 TP／真瑕疵 | 品質事件和請求是獨立計數 |
| labeled_samples、labels_mature | 已到齊品質樣本及回饋狀態 | 製造總工件 1,000，真瑕疵 100 |
| compatibility_ok、rollback_to | 相容檢查與固定回復點 | 失敗時不得繼續擴量 |

## 關鍵數值

| 零售版本 | 單元測試 | 驗證準確率 | 離線 p95 |
|---|---|---|---|
| rec-v2 | 20／20 | 186／200＝93% | 100 ms |
| rec-v3 | 20／20 | 190／200＝95% | 110 ms |
| rec-v4 | 19／20 | 192／200＝96% | 115 ms；因測試遭拒 |

| 製造版本 | 單元測試 | 驗證準確率 | 離線 p95 |
|---|---|---|---|
| inspect-v3 | 20／20 | 190／200＝95% | 60 ms |
| inspect-v4 | 20／20 | 194／200＝97% | 70 ms |
| inspect-v5 | 20／20 | 196／200＝98% | 95 ms；因延遲遭拒 |

每階段快照的總流量為 20,000 次，5%、30%、100% 對應新版請求 1,000、6,000、20,000。early 與 ready 是同一 30% 階段的快照，不相加。各快照保留 90% 低延遲、5% p95 檔、5% 高延遲；最近秩 p95 等於中間檔。

latency 是同一固定產物的另一個惡化情境窗，ready 不宣稱已修好 latency；修改模型或程式後必須另建候選並重新驗證，不沿用舊證據。

| 觀測 | p95 | 錯誤率／品質 | 決策 |
|---|---|---|---|
| r-5 | 110 ms | 5／1,000＝0.5%；CTR 12% | 擴量 |
| r-30-early | 115 ms | 30／6,000＝0.5%；CTR 12% | 只有 10 分鐘，暫停 |
| r-30-latency | 140 ms | 30／6,000＝0.5%；CTR 12% | 達暫停、未達回復門檻，優化 |
| r-30-ready | 115 ms | 30／6,000＝0.5%；CTR 12% | 30 分鐘，擴量 |
| r-100-breach | 160 ms | 400／20,000＝2%；CTR 12% | 錯誤率觸發回復 rec-v2 |

| 製造觀測 | p95 | 錯誤率／品質 | 決策 |
|---|---|---|---|
| m-5 | 70 ms | 5／1,000＝0.5%；Recall 95% | 擴量 |
| m-30-breach | 75 ms | 30／6,000＝0.5%；Recall 88% | 回復 inspect-v3 |

零售品質的 120／1,000 是另一個曝光事件流；不把 1,000 曝光當作 API 成功數。製造品質的分母是 100 真瑕疵，不是 1,000 總工件。製造 100% 僅為計畫，實際模擬在 30% 止損。

按單位擴張另示範 20 條產線的 1→6→20，比例為 5%→30%→100%；它和請求分流是兩種可選安排，不宣稱產線數等於流量百分比。

## 使用頁面

- continuous-integration：六版本的三類發布門檻。
- continuous-deployment：通過門控的固定產物交付。
- data-model-versioning：實驗、資料、程式、模型及切分指紋。
- model-registry：版本到來源實驗、驗證標籤與發布角色。
- release-strategies：同一新舊版的替代發布安排。
- phased-rollout：七個階段快照的指標核算與決策。

本組七張 SVG 是自繪流程示意，沒有數據曲線。指標的獨立核算與邊界紀錄另見工作報告 `tmp/rollout/groups/W-L21302-D/examples-check.md`。

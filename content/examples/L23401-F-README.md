# L23401-F 法規適用性共用例子

`L23401-F-applicability.json` 是教學合成情境，供本組六頁共同使用，不是核准清單。

## 承接與固定規則

- `predecessor` 指向前置組 `L23401-E-purpose.json`，保留健康 H01–H20、電商 E01–E20 的 ID 與索引。前置組原檔不變；地區不改成維吉尼亞州。
- 種子 42、訓練索引 0–11、驗證 12–15、測試 16–19，兩領域相同。本組沒有訓練或新切分。
- F1 原服務、F2 內部意圖分類、F3 擬議美國俄勒岡州委外，沿用前置組原值。每領域13筆候選、合計26筆，仍待法律、敏感資料及語料權利審查。
- F4 另設24筆美國醫院受託資料，F5 另設12筆支付事件，F6 另設8筆電信客服事件。這三項不是原40筆的子集，也不與它們加總成受規範人數。
- `virginia_case` 是另設的年度企業情境：面向維吉尼亞州成年居民，120,000名消費者，出售個資營收占比0%。不能由20筆樣本推估門檻，機構及資料例外仍要檢查。

## 欄位

- `flows`：來源、目的、接收者、地區、欄位及待核狀態；`records` 只描述新情境規模。
- `payments`：P01–P12、索引0–11、金額100至1,200元；沒有可付款卡號。`raw_pan_in_ai=false`、`cvv_stored_after_authorization=false` 是設計限制，非已通過稽核。
- `requests`：四種自編權利請求，保留前置組紀錄連結，不宣稱已完成法律處理。
- `legal_checks`：逐項記 `identity`（法律／標準身分）、`version`、`scope`、`right`、`basis`、`transfer`、`checked_at`、`source`、`state`。其中 `basis` 是該制度的查核欄，不能把所有制度套成GDPR六種依據。

## 核對數值與頁面

支付事件12筆、金額合計7,800元；原始卡號進AI筆數及授權後驗證碼保存筆數均為0。這些是教學設計值，不能推出合規結論。

`gdpr`、`taiwan-pdpa` 用F1–F3及R1–R4；`virginia-cdpa` 用獨立年度情境；`hipaa` 用F4並回看F1健康平台；`pci-dss` 用F5；`sector-compliance-screening` 比較全部六段資料流與五項查核。

PCI DSS頁另有支付邊界示意圖 `l23401-pci-dss-payment-boundary`。其餘頁以具體條件表呈現，沒有必需的空間或曲線推理，不強加插圖。
